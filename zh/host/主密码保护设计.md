## 0. 结论先说

- 主密码是**可选**的第二层，默认关。开了之后，系统密钥链（macOS 钥匙串 / Secret Service）或 Windows DPAPI 文件里存的不再是本机加密密钥本身，
  而是**用主密码派生的密钥包裹过的本机密钥**：密钥链条目和主密码两样都在才解得开。
- **已存的 `enc1:` 密文一字不改**。主密码包的是本机密钥（数据加密密钥，DEK），不是每条密文 —— 开启、关闭、修改主密码都只重写几十字节的包裹，
  秒级完成，不碰数据库。这也是 KeePass / Bitwarden / 1Password 的做法。
- 解锁：启动后弹一次解锁框（可取消）；取消或锁定期间应用照常可用，只是已存的密码读不出来。自动重连、隧道自动建立、自动同步、插件后台取机密都按「锁着」处理，**不弹框**。
- **忘记主密码 = 已存的机密作废，没有后门**。提供「重置」：另起新密钥、重新输入密码；旧的包裹与数据库里的旧密文都保留不删（想起来还能解）。

## 1. 第一步之后的现状

- `MasterKeyResolver` 解析出一个**密钥环**（一把或几把 32 字节 DEK，第一把用来加密，解密依次试）；macOS / Linux 上每把一条密钥链条目
  （编号 = 域分隔 SHA-256(DEK) 前 128 位），数据目录 `secret.key.ref` 只列编号；Windows 上是 DPAPI 包裹的 `secret.key`；密钥链用不了时回落到明文 `secret.key`。
- `ISecretProtector` 是同步的 `string → string`，调用方遍布会话仓储、共享凭据、Gist、插件机密、插件信任库；`TryUnprotect` 能如实说「解不开」。

## 2. 威胁模型：主密码多挡住什么

| 场景 | 第一步（密钥链） | 加主密码 |
| --- | --- | --- |
| 拷走 / 备份 / 网盘同步数据目录 | 挡住 | 挡住 |
| 同一用户下的其它程序读密钥链条目（macOS 条目对任何应用开放；Secret Service 解锁后对会话内进程开放；DPAPI 对本用户进程开放） | **挡不住**（与原来 0600 文件同级） | 挡住（还要主密码） |
| 钥匙串 / keyring 文件连同登录密码一起泄露、域管理员重置账户后的 DPAPI | 挡不住 | 挡住 |
| 别人坐到你已登录、没锁屏的电脑前打开 VelaShell | 挡不住 | 锁定期间挡住（§5 自动锁定） |
| 解锁之后读进程内存、键盘记录 | 挡不住 | **挡不住**（如实写，不承诺） |
| 进程内插件（与宿主同进程） | 挡不住 | 解锁后挡不住；隔离插件仍只经 `ISecretsApi` 拿到自己的机密 |

## 3. 密钥层次与存储格式

```
主密码 ──Argon2id(salt, m, t, p)──► KEK（32 字节，只活到包裹 / 解包完成就清零）
                                     │ AES-256-GCM（随机 12 字节 nonce）
DEK（第一步密钥环里的每一把） ────────►  wrapped = nonce ‖ tag ‖ GCM(KEK, DEK)
```

- **KDF 头**（盐与参数，不是机密）存在数据目录的 `secret.key.mp`：`version=1`、`kdf=argon2id`、`m`、`t`、`p`、`salt`（16 字节随机，base64）。
  整个密钥环共用一个 KEK（一次派生解开全部）。
- **每条密钥链条目**的值从「32 字节 DEK」换成 `VSMP1` 魔数 ‖ `wrapped`（60 字节）。条目编号仍按 DEK 派生，不变 ——
  所以第一步「条目内容对不上编号就不用也不动」的规则天然保护了包裹过的条目：不认 `VSMP1` 的旧版本读到它只会报「找不到」、另起新密钥，不会覆盖（降级不丢数据）。
- **Windows**：`secret.key` 的内容从 `DPAPI(DEK)` 换成 `DPAPI(VSMP1 ‖ wrapped)`；回落到明文文件的平台同理（`VSMP1 ‖ wrapped`，这时主密码是唯一屏障）。
- 校验：GCM 认证标签即主密码校验，不另存验证值（少一个可供离线比对的东西）。
- **事实来源是包裹格式本身**，不是 `AppSettings.MasterPasswordProtection`：设置导入、Gist 同步都可能改那个布尔值。
  字段只用于界面显示，并登记进 `SettingsCategories` 的「不导出、不同步」字段。
- 备选方案（不推荐）：开主密码后把密钥只存成数据目录里的包裹文件、删掉密钥链条目 —— 数据目录 + 主密码即可换机，
  但主密码弱时等于退回「拿到目录就能离线爆破」，与第一步的目的相反；换机已有连接导出与端到端同步。

## 4. KDF：Argon2id

- 参数：m = 64 MiB、t = 3、p = 1（RFC 9106 §4 的第二推荐是 m = 64 MiB、t = 3、p = 4；OWASP 的下限是 m = 19 MiB、t = 2、p = 1），主流笔记本上约 0.3–0.6 秒。
  参数随头存，以后调参只在下一次解锁成功时用新参数、新盐重新包裹（rehash），不需要一次性迁移。
- 实现：BCL 没有 Argon2。宿主经 `VelaShell.Ssh` 已带着 BouncyCastle.Cryptography（`.ppk` v3 的 Argon2id 用它），Infrastructure 显式引用同一个包即可，不新增依赖；
  `src/Directory.Packages.props` 的注释里登记这项新用途（`VelaShell.Ssh/README.md`「没有第二种用途」说的是 SSH 库内部）。
- 派生放后台线程（64 MiB 内存、几百毫秒 CPU），解锁框显示忙碌态。
- 在线防猜：解锁框连续输错后逐次加等待（1、2、4… 秒，上限 30 秒），不锁死、不删任何东西。离线防猜只靠参数与密码强度：开启时提示长度 ≥ 12 或用口令短语。

## 5. 解锁、锁定态与保存

- **何时解锁**（待定 §9-1）：建议主窗口出现后弹一次解锁框，可取消；取消后状态栏留一个锁形入口，点它再解锁。
  理由：启动阶段就挡住只想开本地终端的人不合适，而 `Unprotect` 是同步接口、调用点遍布全仓，不能在每个调用点就地弹框。
- **锁着时的语义**：`AesSecretProtector` 的密钥环为空 → `TryUnprotect` 返回 false、`Unprotect` 原样交回密文（与第一步「密钥没取到」完全同一条路，调用方已经会处理）；
  `Protect` 不得另起新密钥（那会生出一把主密码管不到的密钥），改为抛专门的 `SecretsLockedException`。
- **新增异步闸口** `IMasterPasswordGate { bool IsLocked; Task<bool> EnsureUnlockedAsync(bool interactive, CancellationToken); event Unlocked; }`。
  用到机密的入口（凭据管理器设计 §5.5 的五个构建点、Gist 同步、插件 `ISecretsApi`、插件信任库写入、编辑框保存）在解析 / 保存之前先 await 它。
  保存时被锁：交互式入口弹解锁框，取消则这一次不保存密码（连接照样用手输的那份），并明说「未解锁，这次的密码没有保存」。
- **自动锁定**（待定 §9-2）：可选「空闲 N 分钟后」「系统锁屏时」；锁定 = 清零内存里的 DEK（`CryptographicOperations.ZeroMemory`）回到锁着。默认建议不自动锁。
- **解锁框**：模态于主窗口，`SecurePasswordBox`，不进剪贴板、不进历史；串行化（同一时刻只有一个框，其余请求等它的结果）。

## 6. 自动重连与后台任务

与[凭据管理器集成设计](凭据管理器集成设计.md) §5.7 同一张表（那里的「保险库锁定」即这里的「主密码锁定」）：

| 触发 | 模式 | 锁着时 |
| --- | --- | --- |
| 用户主动连接、手动重连（Ctrl+R / 回车 / 「重连」）、连接诊断、插件 `Sessions.OpenAsync`、启动时恢复会话（用户意图，算一次交互） | 交互式 | 弹解锁框 |
| 自动重连定时器、睡眠唤醒后的 `ReconnectAllAfterResume`、隧道 `AutoReconnectAsync` | 非交互式 | 不弹框；标签失败覆盖层写「已锁定，解锁后按 Ctrl+R 重连」；解锁成功后对这些挂起的自动重连各重试一次 |
| Gist 自动同步 | 非交互式 | 跳过这一轮并记一行；手动「立即同步」走交互式 |
| 插件后台读机密（`ISecretsApi.GetAsync`） | 非交互式 | 需要 SDK 新契约「已锁定」异常（在 velashell-plugin-sdk 写好、不动版本号）；契约就绪前等待交互式解锁。**不能返回 null**：插件会以为机密不存在、让用户重填，覆盖旧值 |

理由同凭据管理器设计：网络恢复后 20 个标签同时自动重连，不能弹出一个用户不知由谁触发的解锁框（钓鱼疑虑）。

## 7. 开启 / 关闭 / 修改 / 忘记

- **开启**（设置 → 常规 → 隐私与安全，恢复 R-04 那一行并接线）：输入两次、强度提示、确认「忘了主密码，已保存的密码无法找回」→ 解析当前密钥环 → 派生 KEK →
  逐条「写新、读回核对」→ 写 `secret.key.mp`。任何一步失败整体回到未开启（条目只在核对通过后才替换；第一步的「不覆盖对不上的条目」与原子写法照用）。
- **关闭**：输入当前主密码 → 解包 → 逐条写回明文 DEK（第一步形态）→ 删 `secret.key.mp`。
- **修改**：旧 + 新 → 解包 → 新盐新 KEK 重新包裹 → 写新、核对、再换头。数据库不动。
- **忘记**：解锁框上「忘了主密码？」→ 说明后果 → 确认后：旧条目与头文件改名保留（`.forgotten-时间戳`，不删），生成新 DEK（可选立即设新主密码），
  之后与第一步「条目找不到」同一条提示路径：连接时重新输入。（待定 §9-3：开启时是否同时生成一份恢复码。）
- **审计**：开启 / 关闭 / 修改 / 重置各记一条 `settings` 类审计（只记动作，不记任何口令材料）。

## 8. 迁移与兼容

- 第一步 → 第二步：只在用户开启时一次性包裹；不开的人什么都不变。
- 降级到不认 `VSMP1` 的版本：包裹过的条目对不上编号 → 旧版本报「找不到」、另起新密钥、不覆盖；旧版本里已存密码解不开，
  升回来解锁后照常（旧版本另起的那把按第一步的规则并入）。
- 多设备：主密码只管本机；云同步的端到端口令是另一回事，不合并、不复用（避免一个口令泄露两处都失守）。

## 9. 待定决策

1. 解锁时机：启动后弹一次（可取消）vs 第一次用到机密时才弹。草稿倾向前者。
2. 自动锁定默认值：不自动锁 vs 空闲 15 分钟。
3. 恢复码：开启时生成一串 128 位随机码（用户自己抄下），它也能解包 DEK。成本低（多一份包裹），倾向提供、可跳过。
4. 插件 `ISecretsApi` 的「已锁定」语义要 SDK 新契约。
5. Windows Hello / Touch ID 作为解锁方式（[调研](系统密钥链与sudo凭据填充可行性调研.md) §8 第 2 条）：留到第三步。
6. Argon2id 参数在低端机器（树莓派上的 Linux 桌面）是否降到 m = 32 MiB。

## 10. 测试计划

- KDF 头与包裹格式的往返；错误主密码 → GCM 失败 → 解锁失败计数与退避。
- 开启 / 关闭 / 修改在每一步中断都不丢任何一把 DEK（沿用第一步的假密钥链用例形状）。
- 锁着时：`Protect` 不生新密钥、`TryUnprotect` 为 false、自动重连与自动同步不弹框、交互式入口只弹一个框。
- 降级：不认 `VSMP1` 的解析器读到包裹条目不覆盖。
- 设置导入 / Gist 同步改了 `MasterPasswordProtection` 不影响实际保护状态。
