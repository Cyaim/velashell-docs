## 一、结论先行

- **形态**:与 Docker 面板同一个路数 —— 清单只贡献一条命令(`contributes.commands` + `onCommand:velashell.mongo.open`),
  用户在命令面板(Ctrl+P)里点「MongoDB: 打开 MongoDB 工作台」才装载本程序集与驱动,开一个文档面板;进程内装载。
  **连接由插件自己管**:已保存的连接列在对象树的根上,新建 / 编辑是设计稿 10 的对话框,MongoDB 不出现在宿主的
  新建连接窗口与会话树里。只用 SDK 2.0.6 已有的能力面(`minSdkVersion: "2.0.4"`:`ISessionsApi` 要 2.0.2,工作台页签图标 `PanelOptions.Icon` / `PluginIcon` 要 2.0.4)。
- **引擎**:官方驱动 MongoDB.Driver 3.x(Apache-2.0),随插件目录分发;驱动异常在出口翻成一句人话并分好类
  (连不上 / 认证失败 / 证书不受信任 / 配置写错 / 跳板没建起来),失败卡片按类给按钮。
- **界面骨架**:Navicat 的对象树 + 大图标工具栏 + 对象标签页(对象 / 集合 / 查询 / 管道 / GridFS / 设计 / 监控 / 慢查询 / 用户),
  补齐 Compass 的聚合管道、Schema 分析、索引建议与 GridFS。
- **编辑模型**:网格 / 树 / JSON 三视图共用一份数据;所有编辑先进**暂存区**,提交前可预览将执行的命令,
  提交走一次 BulkWrite 并带**乐观并发**,提交后 10 秒内可撤销。
- **护栏**:环境标记(开发 / 测试 / 生产)派生出只读默认值与写前确认;只读是客户端护栏,权限置灰来自 `connectionStatus`。

## 二、连接:插件自己管

### 为什么不是宿主的连接类型

设计稿 10「新建连接 · MongoDB」是一整张对话框:分段的服务器形态、一行一台的成员、并排的认证、两张「安全通道」卡片,
右侧栏还有随输入更新的连接串、逐步的测试结果与发现的成员。宿主的新建连接窗口只认声明式字段
(本蓝图 [07](../plugins/07-capability-apis.md) "设置表单是声明式 schema,不是控件树"),把这张稿子画进去,
得给 SDK 加一套字段版式与"连接检查"契约、宿主跟着实现 —— 这条路试过(SDK 2.0.7),已整体撤回:
为一个插件的表单让宿主永远背着一份公开契约,不如让插件像 Docker 面板一样把整件事装在自己的面板里。
早先"注册成工作台连接类型、工作台里不放连接入口"的做法也随之作废。

### 落点

| 关切 | 做法 |
| --- | --- |
| 入口 | 命令面板里的「MongoDB: 打开 MongoDB 工作台」;面板已开着就把它带到眼前。工具栏最左「连接」与对象树表头「+」新建连接;对象树里双击连接行连上,右键里有连接 / 断开 / 编辑 / 复制 / 删除 |
| 已保存的连接 | 插件存储(`IPluginStorage`,键 `connections`);设置按 `MongoSettings` 的字符串键存,与解析是同一份。对象树根上列全部连接(灰点没连、绿点连着、红点没连上),分了组的挂在可收起的组名节下;常用的(最近连过的)在上面 |
| 口令 | 宿主的加密密钥库(`ISecretsApi`,按连接 id);不写进连接串、不写进插件存储。编辑时口令框留空表示不改;改成匿名就删掉存着的 |
| 几条连接同时开着 | 每条连着的连接一个会话对象,标签页拿到的就是它 —— 同名集合在两条连接里是两个标签;工具栏、只读开关、服务器徽章与状态条跟着活动标签所在的那条连接走 |
| SSH 跳板 | 选宿主里已保存的一条 SSH 连接(`ISessionsApi.ListSavedAsync`)。连的时候请宿主打开它(`OpenAsync`,理由原样给用户看),在本机回环上起一个转发端口,驱动每开一条连接就经 `IRemoteTunnelApi.OpenTcpAsync` 在跳板机上开一条流对接。几条连接走同一台跳板时共用一条会话,最后一个走了才关,而且只关本插件开的那条(用户自己开着的终端会话宿主不让关)。插件碰不到跳板机的凭据 |
| 证书信任 | 自签证书连不上时,失败卡片列出证书(主题、签发者、到期、SHA-1)并给「信任此证书并重连」,只记这一张的指纹 |

| 设计稿 10 | 落点 |
| --- | --- |
| 连接名 / 分组 / 环境标记 | 「基本」一行;分组可选已有的也可新写;环境标记是三颗带语气色圆点的小标签,选成生产时(安全策略没被手动改过)只读与写前确认随之打开 |
| 主机列表 / SRV 记录 / 连接字符串 URI | 分段按钮;主机列表一行一台(第一台就是连接的主机),「+ 添加主机」;SRV 一栏域名、默认开 TLS;连接字符串一栏整串 |
| 副本集名、默认库、readPreference | 三等分一行(连接字符串形态不显示,以串为准) |
| 认证机制 / authSource / 用户名 / 密码 | 机制默认协商 SCRAM-SHA-256,另有 SCRAM-SHA-1、X.509、PLAIN/LDAP;口令框旁「钥匙串」表示存在宿主密钥库 |
| 「安全通道」:SSH 跳板 / TLS 两张卡片 | 跳板卡片的开关在一条已保存的 SSH 连接都没有、或选了 SRV 时禁用并写明原因(已开着的仍能关);TLS 打开后给 CA 与客户端证书两栏 |
| 右栏:连接字符串 | 纯字符串拼出脱敏连接串(口令永远是 `****`),按片段角色着色,可复制;连接字符串形态填了一半时原样脱敏摆出来 |
| 右栏:测试结果 / 发现的成员 | 逐步测:SSH 隧道(开会话 + 起转发)/ TCP(走跳板时在跳板机上敲目标端口)/ 认证 / hello / 权限检查;只读账号是权限一步的**警告**;成员取 `replSetGetStatus`(没权限时退回 `hello`),带角色与复制延迟,并按地址把角色徽章标回主机列表那一行。参数一改,结果作废 |
| 右栏:安全策略三个勾 | 只读、写前确认、禁用 `dropDatabase`;前两个**不给默认值** —— 缺键即按环境定(生产开、其余关) |
| 页脚:测试连接 / 取消 / 仅保存 / 保存并连接 | 照稿;改的是连着的那条时「保存并连接」先断开再连 |
| (稿外)调优项 | 末尾一个默认收起的「高级」:appName、连接超时、默认 maxTimeMS、每页行数、Schema 抽样数、扩展 JSON 模式、直连、显示系统库 |

**连接中 / 连接失败**(设计稿 22「连接状态」)照宿主「先建标签、后连会话」的习惯:连的时候先开一个占位标签
(「正在连接 X」+ 经哪个跳板 + 取消),连上了换成默认库的对象列表;没连上就原地变成「无法连接 X」+ 连的哪儿 +
等宽字的原因 + 编辑连接 / 关闭标签页 / 重新连接,不弹模态框。面板没有宿主状态栏可用,于是自己画一条 24px 状态条:
当前连接 · 范围 · 当前标签的状态。

两个容易做错的点:

1. **经 SSH 跳板时必须直连。** 驱动连的是本地转发端口,但它会按副本集配置去连其余成员的**真实地址**,
   本机够不着,结果是选服超时。所以走跳板时强制 `directConnection`,也不再传副本集名。
2. **选服超时背后的真正原因在心跳里。** 首次连接失败时驱动只抛一句"选服超时",认证失败、TLS 被拒、端口不通
   都藏在各成员的心跳异常里。插件在释放连接前把它们捞出来再分类(认证失败 → 去改口令;TLS → 能信任就给信任按钮;
   其余 → 连不上),并剪掉驱动拼进消息里的整份集群描述。

设计稿没画、但用起来离不开的几条交互(照 Navicat 的习惯):

- **钻入对象 / 数组**:集合网格与查询结果网格里双击(或 Enter、右键「展开查看」)对象或数组单元格,网格换成那一层的子表 ——
  数组一个元素一行、行号是下标,元素是文档时列是字段并集,有标量元素时多一列「值」;对象就一行。上方一条面包屑
  (`文档 #3 › items › [2] › attrs`),点任一段跳回,Backspace / Alt+← 回上一层并落回刚才那一格。
  集合网格里子表照样可改:单元格路径从文档根算起(`items.2.qty`),暂存、提交、撤销、冲突处理与树视图里改嵌套字段是同一条路;
  底栏「+ / −」在子表里是加 / 删数组元素。按值筛选时去掉数组下标(`items.sku`),带下标的筛选几乎从来不是想要的。
- **列宽**:所有表格的列头分隔线都可拖,双击按内容自适应(量列头与已实现的行,虚拟化列表里看不见的行不量)。
- **服务器监控随窗口伸缩**:两行图表(操作 / 秒 + 副本集、连接数 + 存储 Top + 事件)按 1 : 1 分剩余高度,中间的分隔可拖 ——
  设计稿 900 高时正好是 282,窗口一高也不会上面定死、下面一行被拉成一面墙。刚开始采样、柱子还不满一窗时,柱子已是最终宽度、
  靠右排(最新的贴着「现在」),不再几根柱被拉得和整张图一样宽;横轴标签挨不下时跳过中间的。存储 Top 列前 10 个集合
  (面板矮时表内滚动),集合名一列默认按最长的名字自适应、列头分隔线可拖、双击重新自适应;跨库时库名淡色、集合名亮色,
  悬停看完整命名空间与数据 / 索引各占多少。
- **右侧面板收起**:集合网格的文档检查器与 JSON 视图的大纲可收起,底栏右下角一颗按钮切换,收起后数据区占满整宽;新开的集合标签记着上次的选择。
- **面板**:对象树、检查器、各详情侧栏、查询编辑器与结果、执行计划侧栏、管道阶段卡片的编辑 / 预览、文档编辑器的预览与命令,
  分隔处都可拖。拖条画成原来那条 1px 线,抓取区左右(上下)各探出 3px。查询编辑器与下方结果区的分界只听这条分隔条:
  切到「执行计划」页不再把编辑器收矮到设计稿 14 的 194px —— 结果页与执行计划页是同一块面板的两个页签,高度应当一致。
- **新建索引(设计稿 07b,Navicat 设计表的做法)**:原先挤在索引页右侧 340px 面板里,字段行一窄就容易点错。
  现在点「新建索引」(或建议卡片的「创建此索引」),索引页下半部分从建议卡片换成整宽的编辑器:索引表末尾钉一行「新建」草稿
  (强调色底 + 左侧色条,键、类型、属性、预估大小跟着表单实时变,索引多到要滚时它也一直看得见),编辑器分三栏 ——
  字段表(序号 / 字段 / 排序或类型 / ESR 角色 / 抽样类型 / 上移下移删除,也可按住序号列拖动;键序即索引前缀顺序)、
  类型与选项(每个选项右边一句它做什么)、命令预览与预估;名称在编辑器头上,底栏写明「将在 库.集合 上执行 createIndexes」。
  编辑器开着时索引表最多露 5 行,其余在表内滚动。
- **查询的执行目标(连接 ▾ 数据库 ▾)**:查询工具行分两行 —— 上行是编辑类(保存 / 格式化 / 历史 / 导出为代码),
  下行是「在哪跑」与「跑」:连接下拉、数据库下拉、运行 / 运行当前语句 / 停止 / 执行计划,右侧一句「在 连接 / 库 上执行」与 maxTimeMS。
  连接下拉列出插件里全部已保存的连接;选另一条时查询标签**原位换成**那条连接上的(标签的连接定死在构造里,随连接断开而关),
  文本、未保存状态、光标与 maxTimeMS 带过去,库名那边也有就沿用、没有就用那条连接的默认库(提示里写明换了库);
  没连着的先安静地连上 —— 不开「正在连接」占位标签、不动对象树、不开对象列表。
  数据库只决定库,不选集合:`db.集合` 永远在**生效的库**里解析(语句之前最后一条 `use`,没有就是下拉里的库)。
  那个库里没有这个集合时集合名下画橙色波浪线(插入类语句除外 —— 往不存在的集合里插就是新建它),
  右侧字段页标题写成「orders @shop」并给出同样的提示,免得在错的库上查了个空。
- **GridFS 拖放区可点**:拖放区整块可点,点空白处弹「选择要上传的文件」(与工具行的「上传文件」同一条路);
  框里还有「选择文件… · 选择文件夹…」两个链接。悬停时描边变亮、铺一层淡底,看得出它能点。
- **对象树里就地新建**:「集合 / 视图 / GridFS 存储桶」三个分组上右键各有「新建集合… / 新建视图… / 新建存储桶…」;
  集合行上还有「新建集合…」与以它为源的「新建视图…」,库行三样都有。桶行右键可直接「上传文件… / 上传文件夹…」
  (打开那个桶的标签,走同一条上传路径)与「删除存储桶…」(`.files` 与 `.chunks` 一起删,有文件时手打名称确认)。
- **检查器(网格右侧)**:对象 / 数组那一行点任何位置(箭头、键、值)都展开 / 收起,双击不再翻回去;
  编辑中焦点一离开(点回网格、点别的字段)就把值写进暂存区并收起编辑框,解析不了的值留着红框不丢;
  选中行只在检查器拿着焦点时着色 —— 换一份文档后那块底色不会落在新文档的同名字段上。
- **日期**:网格、树视图、检查器里内联编辑日期字段时,编辑框右边是日历按钮:月历 + 时刻框 +「现在」/「应用」,
  点一天即按时刻框里的时刻写入(全程本地时间,存为 UTC)。

## 四、编辑与写护栏

- **暂存区**按 `_id` 记录字段级修改(含嵌套路径)、新增与删除;提交生成一次 BulkWrite。`updateOne` 的筛选带上
  被改字段的原值(或 `updatedAt`),`matched = 0` 即视为冲突,弹「我的 vs 服务器」逐字段对话框,而不是覆盖别人。
- **撤销**:提交前保存原像,提示里的「撤销 (10)」用原像回滚。
- **只读**:每一条写路径先调 `EnsureWritable(db)`;只读时弹提示并给「解锁写入」(生产连接要确认)。
  真正的只读应落在服务器端权限上;这一层拦的是"在一个以为是测试库的标签页里批量改了数据"那类事故。
- **危险操作**一律红色描边按钮 + 明确后果;生产连接(或删除的东西里有数据)要手打名称;`dropDatabase` 可整体禁用。

## 五、配色:设计稿色板 → 宿主令牌

设计稿 09 的 BSON 色板逐色等于宿主终端十六色在 VelaDark 下的值,因此直接映射到 `VelaShellBlue / Cyan / Green /
Yellow / Magenta`、`VelaWarning`、`VelaTextTertiary`,换主题时跟着走。设计稿的 `warningDim / errorDim / successDim /
infoDim` 在宿主里没有对应令牌,插件按宿主的派生规则(种子色 + 固定透明度)现算,换肤时就地改色。
唯一的私有颜色是监控图表的四个分类色(`MongoChart1–4`):宿主的语义色各有含义(Warning 是告警),拿来当分类色会被误读。

## 六、凭据边界

MongoDB 连接的口令由插件交给宿主的加密密钥库保管(`ISecretsApi`),插件存储里只有不含口令的设置。
插件仍然读不到宿主的会话库:SSH 跳板只按已保存连接的 id 请宿主打开,跳板机的凭据一个字节都不经过插件。
数据传输的"目标连接"是**本插件此刻开着的另一条连接**,或用户手填的一条连接串(那是用户主动交出来的)。
