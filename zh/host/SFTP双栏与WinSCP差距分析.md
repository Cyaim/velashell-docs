# SFTP 双栏与 WinSCP 差距分析

> 编写日期：2026-07-22　　基准代码：`tmds-ssh` 分支
>
> 用途：**决策清单**。逐项列出 VelaShell 双栏 SFTP 与 WinSCP 的差距，供后续挑选要实现的功能。
> 每一项都标注了当前状态与实现代价，未核实的一律标注"未核实"，不做推测。

---

## 一、先看结论

VelaShell 目前是一个**做得相当扎实的单向文件传输器**，但还不是一个**双栏文件管理器**。

传输管道本身的质量明显高于同类小工具：递归上传/下载规划、四种冲突策略、断点续传（含起点核实）、
限速、并发、进度浮窗、传输日志、取消语义、`LocalPathSafety` 路径穿越校验。
远端栏的表格（7 列、可排序、可隐藏、可拖宽、双击自适应）也超出预期。

差距集中在三个层面，**处理方式完全不同，不要混在一起排期**：

| 类别 | 含义 | 用户感知 | 建议 |
|---|---|---|---|
| **A. 接线债** | 代码写好了，但没接到双栏这条路 | **像 bug** | 优先修，代价极低 |
| **B. 能力缺失** | 确实没做，但架构支持 | 功能少 | 按需求排期 |
| **C. 架构级缺失** | 连接口层都没预留 | 与 WinSCP 的本质差距 | 需要专门设计 |

## 四、C 类：架构级缺失

这三项**连接口层都没有预留**（`ISftpService.cs` 全文 82 行无相关签名），需要专门设计。
（C1 已于 2026-09-12 完成，见第七节。）

### C1. 同步与目录比较 —— ✅ 已实现（2026-09-12）

WinSCP 的三大同步能力现已具备，适用于 SFTP、FTP、FTPS 双栏文档，规则见[第七节](#七附2026-09-12-目录比较与同步)：

- **目录比较**：双栏文档工具条「比较目录」，在两栏各自选中不同的条目（仅当前一层，与 WinSCP 同名命令同一口径）
- **同步（单向 / 双向 / 镜像 / 仅时间戳）**：扫描 → 预览（可逐项取消勾选）→ 确认删除 → 批量执行 → 自动复查
- **保持远程目录最新**：监视本地改动自动上传

~~原判断：零行代码，需要新增比较结果模型、差异计算、预览 UI、执行引擎。~~
差异计算默认**先比 SHA-256**（服务器端算摘要），不支持或出错时回退到大小 + 修改时间（见 7.4）。

### C2. 搜索能力

`ISftpService` 需要新增递归搜索 API。注意远端递归遍历的成本，
需要流式返回 + 可取消（现有 `ListDirectoryAsync` 是一次性返回 `List`，不适合直接递归）。

### C3. 终端联动

- 文件栏右键无"在此处打开终端"
- 终端当前目录无法同步到 SFTP 栏

SFTP 文档目前是纯双栏（`SftpDocumentView.axaml` 无终端控件）。
本项目**已有完整终端栈**，这一项的架构基础其实是现成的，主要是 UI 编排。

## 七、附：2026-09-12 目录比较与同步

适用于 SFTP、FTP、FTPS 双栏文档（插件协议的文件文档同样能用，限制见 7.5）。入口在双栏文档顶部的工具条；
终端侧边栏里的文件浏览器没有本地栏，不提供这两个入口。

### 7.1 比较目录（不递归）

- 比较两栏**当前所在的目录**这一层，比较依据取同步窗口上次用的设置（默认修改时间 + 文件大小）。
- 本地栏选中：只有本地有的、本地较新的；远端栏选中：只有远端有的、远端较新的；
  时间相同而大小不同的、以及冲突的，两栏都选中。
- 工具条右侧给出一句结论（「本地 N 项不同 · 远端 N 项不同 · N 项相同」），任一栏换了目录即清除。
- 远端栏隐藏点文件时，本地栏的点文件也不参与比较，免得每个 `.git`、`.env` 都被标成「只有本地有」。

### 7.2 同步窗口

| 选项 | 取值 | 说明 |
| --- | --- | --- |
| 方向 | 本地 → 远端 / 远端 → 本地 / 双向 | 双向时模式固定为「同步文件」，且从不删除 |
| 模式 | 同步文件 / 镜像文件 / 仅同步时间戳 | **同步**：传新增的、较新的、大小不同的，不覆盖较新的目标；**镜像**：只要不同就覆盖，哪怕目标更新；**时间戳**：不传内容，两边都有且大小相同、时间不同的文件，把目标时间改成源的 |
| 比较依据 | SHA-256 校验（默认勾选）、修改时间、文件大小 | 三样都不选 = 只补齐缺失的；SHA-256 的口径见 7.4 |
| 删除多余文件 | 仅单向 | 删除只在目标一侧存在的条目；目录整棵删除，其下条目不再单列；执行前二次确认 |
| 仅已存在的文件 | — | 只更新两边都有的文件，不新建任何东西 |
| 文件掩码 | WinSCP 写法 `包含 \| 排除` | `;` 分隔多个掩码；以 `/` 结尾的是目录掩码；中间含 `/` 的按相对路径匹配；`*` `?` 不区分大小写；`*.*` 等同 `*`。被排除的目录**不扫描**，也就不会被删除 |

流程：**比较**（两边并行扫描，状态栏显示已扫描的目录数，可取消）→ **预览**（每一步一行：操作、路径、两边的大小与时间，
可逐项取消勾选；改动任何选项都会作废预览）→ **同步** → **自动复查**（结论写明「没有剩余差异」或「仍有 N 项待同步」）。

执行规则：

- 顺序：建目录 → 改时间 → 传文件 → 删除。**中途取消后不再执行删除。**
- 传文件与普通上传下载走同一条管道（传输浮窗、全局并发上限、传输日志），但**不走「文件已存在时」的冲突策略，
  也不做续传探测** —— 预览就是确认；目标比源小正是「内容不同」的常态，不能当半截文件去续传。
- 传完**总是**回写修改时间（不看「保留时间戳」设置）：上传后用 SFTP setstat / FTP `MFMT` 把远端时间对齐本地，
  下载后把本地时间对齐远端。不回写的话，下一次比较会把刚传上去的文件判成「远端较新」。服务器不支持时窗口里给出提示。
- 从远端名字拼出的本地路径逐段校验：Windows 上不合法的名字（如 `a:b`、`CON`）报错跳过，而不是写到别处。
- 父目录由执行器逐级补齐：在预览里取消勾选「新建目录」、只留下其中的文件，照样能传。

### 7.3 保持远端目录最新

- 恒为本地 → 远端，沿用窗口里的文件掩码、比较依据与「删除多余文件」（勾了删除会先确认）。
- 开始时先完整对齐一次；之后监视本地目录树，改动防抖 1 秒后**只对变化所在的那一层目录**重新比较，
  新出现的目录（解压、`git clone`）整棵比较；监视缓冲溢出（事件被丢）时整棵重对一遍。
- 列表区换成活动记录（最新在上），记下每次上传与删除；关闭窗口或关闭文档即停止。

### 7.4 比较口径

- **SHA-256 优先**（2026-09-13 补上）：两边都有、**大小相同**的文件先比内容摘要（大小不同已经证明内容不同，不必再读）。
  - 摘要相同 = 同一个文件，**时间不同也不传**（`git checkout`、解压、`touch` 之后不再整片重传）；
    摘要不同 = 内容确实变了，由修改时间判断哪边较新，时间也相同时算「内容不同」（单向照传，双向不动）。
  - 远端摘要在**服务器上算**，不经网络传内容：SFTP 经 SSH exec 通道跑 `sha256sum`（没有则 `shasum -a 256`），
    每批最多 200 个路径；FTP / FTPS 用 `HASH`（SHA-256）或 `XSHA256`。先算远端，服务器不支持时本地一个字节都不读。
  - **回退**：服务器整体不支持或出错（纯 SFTP 账号禁了 exec、主机没有这两个工具、Windows 远端、FTP 服务器不提供这两条命令、
    插件协议）→ 这一轮全部按大小与修改时间比较，窗口附注写明原因；单个文件读不了 → 只有它回退，附注写明「N 个中有 M 个」。
    只勾了 SHA-256 而没勾时间与大小时，回退按两样都比。
  - 时间戳模式下也生效：算出摘要而内容不同的文件，不会被改时间掩盖差异。
  - 摘要按「路径 + 大小 + 修改时间」缓存到窗口 / 文档关闭：同步后的自动复查只重算刚传过的文件（等于顺带做了传输后校验）。
  - 「比较目录」同样先比 SHA-256，回退时结论后面带一句提示。
- **时间精度**：两边先截到较粗的一级再比。SFTP 为秒；FTP 的 Unix LIST 只给到分钟（半年以前的文件只给到日期），
  按原始值推断精度；容差 1 秒（吸收 FAT/exFAT 的 2 秒粒度）。
- **大小写**：Windows / macOS 上路径配对不区分大小写；远端有两个只差大小写的名字时标为冲突、不处理。
- **类型冲突**：一边是文件一边是目录，标为冲突，其下子项不再比较（否则勾上删除会去删一棵没打算动的树）。
- **链接**：两边都不进入指向目录的链接（跳过的个数会提示，与文件夹下载同一口径）；远端指向文件的链接按文件处理；
  本地只跳过真正的符号链接与目录联接，OneDrive「按需下载」的占位文件照常参与。

### 7.5 未做 / 已知限制

- **SHA-256 的代价**：大小相同的文件要在两边各完整读一遍（本地读盘、远端服务器读盘），大目录第一次比较会明显变慢；
  不需要时可取消勾选。缓存不跨窗口：内容改了但大小与修改时间都没变（刻意 `touch -r`）的文件，在同一个窗口里第二次比较时会用到旧摘要。
- 同步选项只在同一个文档标签里记住，不写进设置，重启后回到默认。
- **FTP 时区**：LIST 的时间按服务器当地时间给出、按本机时区解释。服务器与本机不在同一时区时，时间比较会整体偏移 ——
  这时请只勾「文件大小」。WinSCP 在会话设置里提供「时区偏移」，VelaShell 暂无此项。
- 不支持 `MFMT` 的 FTP 服务器与插件协议，上传后无法对齐远端时间：单向「本地 → 远端」不受影响（远端较新不会被当成要上传），
  但**双向同步会把刚上传的文件再下载回来**，窗口会提示这一点。
- 「保持最新」只有本地 → 远端（与 WinSCP 相同）。
