# VelaShell 交互逻辑与界面规格说明书

> 本文档基于设计稿 `VelaShell-zh.pen` 编写，用于交付给 AI Agent 进行功能实现。
> 目标技术栈：**Avalonia**（UI）+ **VelaDock**（可拖拽/分屏的标签停靠,已替换 Dock.Avalonia;浮动窗口按产品决策禁用）+ VT 引擎（parser / buffer / emulator / render）。
> 全文以设计稿为唯一视觉基准，凡"应改为…"的条目为对现有设计稿结构的**重构要求**，实现时以本文档为准。

---

## 0. 产品定位与设计基调

VelaShell 是一款面向运维/开发的现代化 SSH/SFTP 终端客户端。核心体验目标：

- **键盘优先**：几乎所有功能都可通过命令面板（Ctrl+P）或快捷键完成。
- **信息密度高但不拥挤**：等宽字体承载数据，UI 字体承载操作，配色克制。
- **浮层化的辅助功能**：文件传输、隧道、资源监控均以可召之即来、用完即走的悬浮面板形式呈现，不占用主终端空间。
- **暗色为主，亮色可切换**：设计稿提供 dark / light 双主题，所有颜色走 token。

### 1.2 字体

- `font-mono` = **JetBrains Mono**：终端内容、主机名/IP、端口、路径、快捷键、数值、标签页名。
- `font-ui` = **Inter**：菜单、按钮、设置项、说明文字、分组标题。
- 常用字号：终端 12–13、正文 11–14、二级说明 9–10、分组标题 10（`letterSpacing:1`，常大写/加粗）。

### 1.3 形状与间距

- 圆角：浮层 6–8、按钮/输入框 3、徽章 2、标签点 圆形。
- 浮层阴影：**全部浮层与自绘窗体卡片共用一个令牌** `VelaShadowWindow`（两层：近处压边 + 远处扩散）。暗色 `0 1 3 #40000000, 0 4 12 #66000000`，亮色 `0 1 3 #1A000000, 0 4 12 #33000000`。**延展（offsetY + blur）上限 16**，与卡片外边距一致（Linux Wayland 装饰层的阴影宽度取同一个值）——自绘透明窗体的投影只能画在窗口矩形内，超出的部分会被窗口边缘裁成一道糊边；不透明度必须分主题，同一个浓黑压在亮底上会发脏。值与理由见代码仓 `DESIGN.md` §4.5。
- 图标库统一 **lucide**，尺寸 11–16。
- 常用行高：工具栏行 28–36、列表行 28–38、状态栏 24。

## 2. 主界面结构总览

主窗口 1440×900（可自由缩放）。**〔2026-07 定稿,用户决策〕窗体为无边框自绘样式**：`WindowDecorations="None"`（Avalonia 12.x 的 `BorderOnly`/`ExtendClientArea` 托管装饰在 Win32 上会拦截标题栏输入——按钮点不动、窗口拖不动，实测弃用；改以自绘 + `BeginMoveDrag` 原生移动循环 + WndProc 钩子补 Win11 贴靠）。**〔2026-09 起〕macOS 例外**：主窗口用系统外框与原生红绿灯（关闭 / 最小化 / 全屏，位于标题栏左侧），自绘的最小化/最大化/关闭隐去，logo 左侧给红绿灯让位（全屏时撤掉），标题栏高度跟系统标题栏一致（当前 28pt，红绿灯位置改不了，只能让标题栏去对齐它）；Windows 与 Linux 不变。各平台外框的做法与依据见 [`architecture.md`](architecture.md) §5「窗口壳」。首行为 28px 自绘标题栏（`TitleBarView`：左 = 产品 logo + 名称；右 = 全局功能按钮组 `GQQwj` + 最小化/最大化/关闭窗口按钮），**文字菜单已整体移除**（功能与命令面板重复）。客户区自上而下为：**自绘标题栏 → （侧边栏 ‖ 右区）→ 状态栏**。

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 自绘标题栏 28px： ▣ VelaShell   …弹性空隙…  [功能按钮组 GQQwj]      ─  □  ✕    │
├──────────────┬────────────────────────────────────────────────────────────┤
│              │  标签页行：[Tab1][Tab2]…[+]      ……空隙……   [◀][▶][▾]          │
│   侧边栏      ├────────────────────────────────────────────────────────────┤
│  Sidebar     │  终端主区 Terminal（VT 渲染 + 可选 行号/时间侧栏）             │
│  260px       ├────────────────────────────────────────────────────────────┤
│              │  文件浏览器 / SFTP（可折叠，默认 220px）                       │
│              │  广播输入栏（按需显示，固定在状态栏上方）                       │
├──────────────┴────────────────────────────────────────────────────────────┤
│  状态栏 Status Bar（跨整宽，24px）                                            │
└─────────────────────────────────────────────────────────────────────────┘
```

- **自绘标题栏为跨整宽首行**（`bg-sidebar` 底 + 底部分隔线）：左 = logo+产品名，右 = 全局功能按钮组 `GQQwj`（详见 §4A；「广播」已实现，「组同步」仍禁用）+ 最小化/最大化/关闭窗口控制按钮（27×27 方块，关闭 hover 系统红；macOS 上没有这三个按钮，由左侧的系统红绿灯代替）。
- **弹窗与独立窗口的外框按平台区分**（全部弹窗、任务管理器 / 资源监视 / 链路追踪 / 目录同步 / 插件管理 / 插件面板 / 录制回放 / 远程编辑等独立窗口，含隔离插件的窗口）：Windows 上是透明窗口里浮起的卡片（圆角 8、1px 描边、16px 边距里的 `VelaShadowWindow` 阴影）；macOS 上圆角、描边与阴影由系统画，窗口不透明，弹窗不显示红绿灯、独立窗口用红绿灯代替自绘的窗口按钮；Linux 原生 Wayland 上阴影与描边由 Avalonia 的装饰层画，合成器以卡片边缘为窗口边界；Linux X11 上是不透明直角矩形。卡片的可见尺寸各平台一致；独立窗口最大化 / 全屏时卡片铺满成直角。
- **全部窗口的标题栏统一 28px**（主窗口、独立窗口、弹窗，2026-09-26 起；此前主窗口 36、弹窗 48、独立窗口 34–56 不等）：标题栏放图标、标题、窗口级的操作与窗口按钮（弹窗是右上角的 ×）。窗口按钮一律是贴住右上角的 27×27 方块，关闭 hover 系统红；卡片按圆角裁剪，方块的悬停底色跟着圆角走，不会伸出窗口外。**窗口级的操作收进标题栏**（2026-09-29 起）：排在窗口按钮左边，是一组只有图标的按钮，与主窗口的全局功能按钮组 `GQQwj` 同一个样式 —— 悬停提示写明是什么、带读屏名称，开关打开时、或一件事正等着做时图标转强调色。资源监视：主机标识（连通绿点 / 断开灰点 + 主机名）与暂停 / 继续（暂停中换成强调色的「继续」）；录制回放：导出 / 刷新 / 清理 / 自动录制（开着时转强调色）；远程编辑：保存（有未保存的改动时转强调色，原先是一颗常亮的强调色按钮）；连接诊断：导出报告（还没有报告时禁用）/ 重新检测。这四扇窗口原先两行的头部，第二行只剩副标题（采样说明 / 功能说明 / 远端路径 / 诊断目标），与标题栏同底色、同样可拖动；双击标题栏里的按钮不会触发最大化。新建连接、导入会话、连接诊断这几个弹窗的标题栏与独立窗口同一个样子：15px 线条图标（强调色）+ 13px 标题靠左 + 右上角的 ×；弹窗固定尺寸，不放最大化，macOS 上照常显示 ×（弹窗不显示红绿灯）。macOS 上显示红绿灯的窗口，标题栏跟系统标题栏同高（当前 28pt），红绿灯与标题在同一条中线上。两处例外，头部没有窗口按钮、不算标题栏，保持 48：设置窗口左上角那条是左侧导航的抬头兼拖动区（没有关闭 / 最小化按钮）；消息框（提示 / 确认 / 输入）没有右上角的 ×，关闭一律走按钮栏或 Esc。
- 标题栏之下直接分「侧边栏 ‖ 右区」两栏；右区顶部为标签页行（详见 §4B）。

- 侧边栏与右区之间、右区上下分栏之间均为可拖拽分隔(VelaDock / GridSplitter)，允许调节宽/高，可整块折叠。
- 终端主区 + 文件区共同构成"一个会话视图"，随激活标签页切换整体内容。

## 3. 侧边栏 Sidebar（宽 260，`bg-sidebar`）

> **窗口标题栏说明**：本应用为**自绘无边框窗口**（`WindowDecorations="None"`，非原生标题栏；macOS 上换成系统外框，只借用原生红绿灯，标题栏仍自绘），由 `TitleBarView` 自绘 28px 标题栏，其左侧已含应用图标 + "VelaShell" 名称。
> 因此**侧边栏顶部不再重复显示应用图标与名称**——原设计稿中的"Logo 栏"（暗色 `tGM2H`、亮色 `4RBrb`）已删除，避免与自绘标题栏中的图标+名称重复。侧边栏第一行直接从「工具栏」开始，下方会话资源树相应向上填满释放出的空间。

自上而下：

1. **工具栏（36px，侧边栏首行，`cnUAB`）**：左侧分组标题「资源管理器」（`126Cj`）；右侧两枚按钮——
   - `plus`（`2mkdr`）：新建连接（打开 §13 新建连接弹窗）。
   - `ellipsis`（`oPsSE`）：更多（2026-10-09，joesdu/VelaShell#571）。自上而下：导入连接文件… / 导出全部连接… /
     保存 CSV 导入模板… / 从其他工具导入会话…（[会话导入](会话导入.md)）—— 分隔线 —— 分组按名称排序 / 全部折叠 / 全部展开。
     前三项与「导入到此分组 / 导出此分组 / 导出所选」见 [会话导入](会话导入.md) 第七节；没有任何连接时「导出全部连接」是灰的。
     「分组按名称排序」是一次性的重排（自然序：「机房 2」排在「机房 10」前面；按当前区域的排序规则，中文按拼音），
     排完照样可以再手动调。
2. **会话资源树（`fill_container`，可滚动）**：分组折叠列表，占据侧边栏中部主要空间。
   - 分组行：可折叠三角 + 分组名（如「生产环境」「测试环境」）+ 计数。
   - 主机行：状态圆点（绿/黄/红）+ 主机名 + 可选标签（如「跳板」`accent-dim` 底）。
     - **圆点是该配置名下所有活会话的合并结果**，不是最后一次状态变更说了算。一条配置可以同时
       开着多个终端标签与多个文档（独立 SFTP / FTP / S3 等插件文件系统 / Redis 等工作台），
       而树上只有一个节点：合并优先级 `Connected > Connecting > Error > Disconnected`，
       全部关掉才回到「未连接」。
     - 反例（都出过）：按"最后一次变更"更新时，在已连上的会话上再开一个标签、趁它还在握手就
       关掉，节点会永远停在「连接中」（#321）；对同一条 FTP 配置开两个标签、关掉其中一个，
       节点会变成「未连接」——明明还有一个活着。
   - 当前会话行高亮 `bg-active` 左侧 accent 竖条。
   - **悬停显示备注**（#549）：鼠标停在写了备注（§13.1「整理」）的连接上，弹出那段备注；指着整行任何一处都弹，
     没写备注的连接、分组行都不弹。提示框到最大宽度就折行，超过 12 行或 500 个字符的截断并补 `…` ——
     提示框只管宽不管高，一大段粘贴进来的备注会弹出比侧栏还高的浮层，把正要点的那几行全盖住；完整内容在编辑对话框里看。
   - 交互：单击选中；**双击=连接并激活标签页**；右键=§12 会话右键菜单；支持拖拽调整分组归属；
     **拖动分组行=调整分组顺序**（见下）。
   - **多选**（2026-10-09，joesdu/VelaShell#571；由 #524 的 Ctrl 双选扩展而来；macOS 上 ⌘ 同样有效）：
     - **Ctrl 单击**加入 / 移出一条，不设上限（#524 时只能两条、第三条会把最早那条顶掉，现在一直往里加）；
       移到只剩一条即退回普通单选。**Shift 单击**选中「起点」到这一行之间的全部行，起点是上一次普通单击或 Ctrl 加选的那一行；
       **Ctrl+Shift 单击**把这一段并进已有的多选。区间按眼睛看到的行算：折叠着的分组里的连接不进来，分组行本身跳过。
     - 被选中的几行与选中行同一种高亮（`bg-active` + accent 名称）。右键其中任一行弹「多选菜单」（§12），
       作用于全部选中的连接；右键多选之外的行，多选随之结束、弹那一行原本的菜单。
     - 同一条配置不会被选两次（一条配置在树上只有一个节点）；同一台机器内部复制用单栏文件浏览器的「复制到」。
     - 分组行不参与。普通单击、方向键移到多选之外，多选都随之结束；折叠分组时被收进去的那几条从多选里摘掉，
       选中项本身被收进去（或剩不到两条）则多选结束。
     - **恰好两条**时多选菜单里多一项「在双栏 SFTP 中打开」（§6.2），**先选的在左栏**。
       能进双栏的是 SSH / SFTP / FTP 与插件的**文件协议**（S3、WebDAV…）；插件的工作台（Redis…）不行，菜单项置灰，下面一行说明原因。
       终端类插件协议（Telnet…）要等插件激活才认得出，打开时报「不是文件协议」。三条及以上不出现这一项。
     - 列表控件本身仍是单选：多选由会话树自己记，**行上原有的右键菜单一项未改**，多选菜单是另一份。
   - **分组排序**（#571）：分组行可以直接拖动。拖动超过 5px 才算拖（没拖动就照旧是展开 / 折叠）；
     鼠标在某个分组行的上半截 = 插在它前面、下半截 = 插在它后面，在组内的连接行上 = 插在这一组后面，
     在根级连接、置顶连接或空白处 = 排到最后。落点处画一条 2px accent 插入线（那一行滚出视口时不画线），
     跟随光标的幽灵标签写明「分组 → 移到「X」之前 / 移到最后」；落回原处给「不可放置」光标，不画线。
     分组右键菜单的「上移 / 下移」是同一件事，给不方便拖的人用。顺序立刻落库：
     全部分组的排序序号重编成 0、1、2…（原先删过分组、按个数取过号的序号是断开甚至重复的）；
     新建连接时新建的分组接在最大序号之后。
   - 默认跟随活动终端标签：自动展开父分组、选中并滚动到对应连接，但不夺取终端键盘焦点；可在“设置 → 常规 → 行为”关闭。
   - **置顶连接**（`pin` 图标，右键菜单「置顶 / 取消置顶」）：置顶的连接被提到**整棵树的最前面**，
     按名称排，行首带一枚 accent 色 `pin` 徽标、按分组行的缩进画。
     - 提到最前而不是在组内上浮，是因为它要与下面那条「启动时折叠分组」配套：**分组全折上之后，
       组内上浮的置顶项照样看不见，等于没置顶**。
     - 置顶只改**显示位置**，不改数据：连接仍属于原分组（`GroupId` 不变），分组行的计数照旧按
       成员数显示（因此展开一个含置顶成员的分组，可见行数会比计数少，这是对的）；取消置顶后它
       回到自己那一组。拖放落点、「分组空了就连分组一并删除」等规则一概不受影响。
   - **启动时折叠分组**（“设置 → 常规”，默认关闭）：开启后分组以折叠态载入。
     - 它只决定**本次运行首次见到**某个分组时的初始状态。手动展开/折叠之后的选择由会话树在进程内
       记着，新建 / 编辑 / 删除连接、云同步回写等触发的整树重建**不会**把它折回去——否则每加一条
       连接就得把刚展开的分组再点开一遍。记忆不落盘：重启后回到设置说的那个状态。
3. **会话列表 / 快速连接区（320px，顶部分隔线）**：
   - 头部（36px）：标题「快速连接」+ 折叠按钮。
   - 快速连接输入框（`bg-input`，32px）：可直接输入 `user@host[:port]` 回车连接。
   - 「最近连接」分组标题 + 最近 3 条记录行（`user@host` + 时间），单击回填输入框，双击直接连接。
   - 快捷命令与最近连接区域均可折叠和拖动高度；折叠状态与最后展开高度保存在本机，下次启动恢复。
4. **底部用户栏（40px，顶部分隔线）**：左=当前身份（头像 + 活动会话的 `用户名@主机`，本地终端为本机用户名；没有活动标签时整块隐藏）；右依次为 `bell` 消息中心、`plug` 插件管理、`settings` 设置齿轮（打开 §14 设置）。
   - **当前身份**：名称只占按钮左侧剩下的宽度（与按钮之间留 8px），放不下时截成尾部省略号，悬停提示给出完整名称。侧栏拖到最窄（180px）时也不会压到右侧按钮上。
   - **消息中心（`bell`）**：有未读时铃铛右上角出现 6px 强调色圆点（24px 见方放不下数字，一个点足以说明"有没有新东西"）。点击切换 360px 非模态浮层，**锚在左下贴着铃铛**，按住标题栏可拖到窗口任意位置（位置跨会话记忆）。装的是要留存、可回看的消息（有可用更新、订阅资讯源的公告与安全资讯），**不收运行时告警**——指纹变更、会话断开各有当场反馈，混进来会把要读的淹掉。详见 [消息中心与资讯源.md](消息中心与资讯源.md)。

### 4A.3 X 窗口(内置 X Server 的原生窗口)

内置 X Server 的每个 X 顶层窗口是一个 Avalonia 原生窗口(库与接口见 [X Server 架构](../xserver/design/architecture.md) §6)。宿主就是窗口管理器,行为如下:

- **哪些窗口不开原生窗口**:桌面类窗口(`_NET_WM_WINDOW_TYPE_DESKTOP`:xfdesktop、caja、pcmanfm 画的桌面,大小等于所有显示器的外接矩形)——
  rootless 下没有能放它的「桌面底层」,给它一个原生窗口,一激活就挡住本机所有程序;映射之后才改成桌面类型的收掉原生窗口,改回别的类型时重新显示。
  InputOnly 的顶层(GTK 拿 GtkInvisible 占选区、接拖放)看不见,也不开(原先多出一个黑窗口)。
- **摆放**:原生窗口的内容区对准 X 窗口的内区(X 的边框不画,原生外框代替它)。客户端给了位置的,按 ICCCM 的窗口重力把原生窗口的**外框**对准请求的位置
  (NorthWest 时外框左上角就在请求的坐标上),显示出来、量到外框尺寸之后把 X 窗口的位置报回服务端;请求 (0, 0) 又不是用户指定的(没有 USPosition)才替它
  居中 —— 对话框按父窗口的内容区居中,其余在主显示器工作区居中,居中的是外框;`xterm -geometry +0+0` 带着 USPosition,照放在 (0, 0)。
  系统边框要等窗口打开才量得到,显示之前按最近一个有边框的窗口量到的边框预估,第一帧不再先按 0 摆、随后跳一下。显示器布局变化让根原点挪了
  (插拔左侧或上方的副屏、扩展坞、休眠唤醒)之后,按每个窗口此刻的原生位置重报 X 坐标。工作区按系统的 `Screen.WorkingArea` 交给 X Server,
  菜单、最大化与对话框避开任务栏。拖动原生窗口时 X 那边的位置按程序处理的进度跟上(处理完上一次移动才交下一个位置),
  慢链路上松手之后程序不再冻住一阵。
- **映射时照客户端设好的状态**:映射前就写好最大化 / 全屏的照样显示成最大化 / 全屏;`WM_HINTS` 的 initial_state 是 IconicState(`xterm -iconic`)的
  一映射就最小化,不抢前台。这些状态是客户端自己写的,不回报。之后用户点最大化 / 最小化,只改原生窗口管的那几个状态(最大化、全屏、最小化、置顶),
  客户端设的「不进任务栏」「模态」「常驻所有工作区」等照旧。最大化 / 全屏时客户端自己改尺寸,把原生窗口此刻的尺寸推回去,客户端随即按系统给的尺寸重画。
  原生窗口的尺寸变化不靠 `Resized` 的原因判断是不是用户缩放(Avalonia 的 X11 后端一律报 `Unspecified`):与最后一次按服务端几何设的尺寸差一个像素以上才回报。
- **按钮跟着 Motif 提示**:`_MOTIF_WM_HINTS` 的 functions 里没有的缩放 / 最小化 / 最大化,原生窗口相应的按钮禁用(不能缩放的对话框、不让最小化的启动画面)。
  无装饰的(GTK 的 HeaderBar、Electron)给无边框窗口,GTK 的窗口沿内沿约 4 像素按下即开始原生的边缘缩放。
- **激活与置顶(焦点窃取防护)**:远端程序要求激活自己的窗口(`_NET_ACTIVE_WINDOW`)时,只有是用户刚在 X 窗口里的操作引起的、而且用户此刻正在用 X 窗口才切到前台;
  否则只闪任务栏(Windows 上 FlashWindowEx;别的平台什么也不做)—— 免得用户在终端里输 sudo 口令时,按键被跳到前台的远端窗口接走。客户端抬高自己的窗口
  (XRaiseWindow、Java 的 toFront)只在另一个 X 窗口正活动时照办;客户端自己把键盘焦点挪到另一个顶层时,在用户正用着 X 窗口的前提下激活那个原生窗口,
  用户看得出键盘去了哪儿。菜单、提示框(override-redirect)与「总在最前」的窗口只在 X 窗口活动时置顶,用户回到本机窗口时退到后面。
  `WM_HINTS` 的 urgency 或 `_NET_WM_STATE_DEMANDS_ATTENTION` 一变成「要求引起注意」、窗口又不是活动窗口时闪任务栏。
- **形状与透明**:非矩形窗口(SHAPE:xeyes、不规则弹层)形状以外画成全透明;Windows 上无装饰的这类窗口再用窗口区域把命中范围裁成边界形状,
  形状以外的点击穿透到下面的窗口(别的平台没有对应的做法,形状以外仍接住鼠标)。`_NET_WM_WINDOW_OPACITY` 小于 1 的窗口用透明底,看得到后面的窗口。
  带 alpha 的(ARGB 视觉的)窗口只在「X 窗口透明与圆角」开着时逐像素透明;关着时(默认)按不透明显示,与没有合成管理器的 X 一样 ——
  客户端用输入形状声明了边缘不是窗口一部分的除外(GTK 4 的下拉菜单、弹出菜单四周的阴影区),它们照透明度显示,不再是一圈黑边。
- **X 窗口的标题、任务栏与位置**:经 SSH 转发来的窗口标题写成「user@host:22 — 标题」(设置「标出 X 窗口的来源」,默认开、改了立即生效 ——
  开着的窗口当场改标题;本机直接连的不标),来源与标题各自做双向隔离(来源里的 U+202E 倒不过后面的标题),几台主机的窗口分得清,远端程序冒充
  本机的凭据框也容易露馅;自己画标题栏的窗口(GTK 的客户端装饰、Electron)没有系统标题栏,来源只在任务栏上看得到。Windows 上同一个远端程序
  (按 WM_CLASS 的类名)的窗口在任务栏归成一组,不能固定到任务栏(远端程序没法从本机启动)。程序没给位置的窗口摆回这个程序上次关掉时的位置与尺寸
  (按类名、实例名与 WM_WINDOW_ROLE 记,只记在这次运行里、不落盘,停了再开 X Server 照样记得;记的是系统桌面坐标,左边插拔显示器不会整体错开;
  标题栏左段已经不在任何一块屏幕的工作区里时不摆;同一个程序已经开着窗口时照常居中;客户端自己指定了尺寸的不改尺寸)。
- **截图**:Windows 上 X 窗口的系统菜单(标题栏右键 / Alt+空格)里多两项「复制截图」「截图另存为…」:截窗口自己的内容(不含系统边框,
  非矩形窗口形状以外透明),另存为默认用窗口标题当文件名。X 窗口里的键鼠都归 X 程序,所以入口放在系统菜单、不加快捷键;macOS / Linux 暂时没有入口。
- **输入法、剪贴板、光标与屏保**:「X 窗口里用本机输入法」开着时(默认),X 窗口就是本机输入法的客户端,上屏的字直接输入给 X 程序
  (上屏的字与之后按的键按先后到达;按着 Shift 时上屏的字照样输入;组着字切到别的窗口时预编辑收掉)。远端程序经 XIM 连上内置 X Server 时
  (xterm、Emacs、Java、Tk、Motif、GTK 2/3 —— 它们得在 `XMODIFIERS=@im=velashell` 下启动,VelaShell 连接后在 shell 里替用户设上:会话开着
  X11 转发、没指定显示地址、引擎是内置的;远端已经设了别的输入法的不动),候选框跟着程序报的插入点走;支持 on-the-spot 的程序(Swing 的文本框、
  GTK)把组字时的预编辑画在自己的输入框里、加下划线,over-the-spot 的程序(xterm、Emacs)由 VelaShell 把预编辑叠在插入点那一行上。
  不经 XIM 的程序(Qt 5 / 6、GTK 4,或者没设那个变量)照旧:预编辑叠画在窗口里、候选框摆在最后一次点击处。剪贴板除文本外还带 HTML 与图片(截图工具、GIMP、LibreOffice
  复制的图片与富文本能贴到本机,本机的截图也能贴进远端程序)。远端程序抓着指针时把指针拉回某处(连续拖拽、CAD 旋转),本机光标跟着挪;
  要求把指针关在窗口里时,X 窗口活动期间光标出不去,切到本机窗口就放开(Windows 与 Linux 的 X11 桌面;macOS、Wayland 不做)。
  远端视频播放器挂起屏保时本机屏保与关显示器也一并抑制,恢复或停 X Server 时恢复(目前只在 Windows 上)。改尺寸时等声明了
  `_NET_WM_SYNC_REQUEST` 的程序重画完再显示,拖边框不闪。
- **远端 GTK 4 程序用 cairo 渲染**:开着 X11 转发的会话(不论显示交给哪个 X 服务端),连接后与 `XMODIFIERS` 同一句静默注入 `GSK_RENDERER=cairo`
  (远端 shell 里已经设了的不动)。GTK 4 默认的 GL 经 SSH 只能退到远端的软件渲染、每帧把整窗像素发过来(`gnome-calculator` 点一下按钮 29 MB,
  cairo 下 0.15 MB)。只对从这个终端里启动的程序生效。
- **单窗口模式**:设置的「窗口模式」选单个大窗口 / 无标题栏 / 全屏时,内置 X Server 以单窗口模式起:启动时就开一个「X 桌面 :N」窗口
  (起步是主显示器工作区的八成大、居中;无标题栏时不带系统边框,全屏时一开就全屏),整个 X 屏幕在里面,远端程序不再各开一个窗口,
  由远端的窗口管理器(xfwm4、metacity、twm……)管 —— 在 SSH 会话里跑 `startxfce4` 之类就得到整个远端桌面。拖大拖小这个窗口就是改屏幕尺寸
  (远端桌面跟着重排);画面按物理像素一比一显示。点它的关闭按钮当作停 X Server(有程序连着时照常先确认);开着「每个 SSH 会话一个显示」时,
  每个会话一个「X 桌面 user@host:22」窗口,关掉它只收掉这个会话的显示 —— 有程序连着时先问「关掉 user@host:22 的 X 桌面会断开它的 N 个 X 程序……
  别的会话的 X 程序不受影响」(危险样式的「关闭」),别的会话与共用的那个照旧。单窗口模式下没有托盘图标转发
  (托盘归远端桌面的面板),也不做「X 程序关闭到托盘」那一条。
- **托盘图标**:内置 X Server 当系统托盘,X 程序的托盘图标(GtkStatusIcon、Java 的 SystemTray、Qt、Electron 的 XEmbed 退路)显示成本机托盘里的
  图标,和 VelaShell 自己的托盘图标并排(那个照常由「关闭时最小化到托盘」管,两者互不覆盖)。图标是 X 程序画的样子(重画后约 0.2 秒跟上),
  悬停提示是图标的名字,经 SSH 转发来的按「标出 X 窗口的来源」在前面标出 `user@host:22`(与窗口标题同一个开关);单击送一次左键,
  右键菜单里「打开(单击)」送左键、「菜单(右键单击)」送右键 —— 程序据此弹出自己的菜单
  (X 的弹出菜单,出现在屏幕右下角托盘那一带)。程序退出、图标窗口没了,托盘图标随之消失;停 X Server 时全部收掉。
- **拖放进 X 窗口**:本机的文本、文件可以拖进 X 程序的窗口(X 程序要支持 XDND,GTK、Qt、Java、浏览器都支持;xterm 不支持),
  光标照目标的回应显示能不能放。文本直接交过去。文件要看程序在哪:经 SSH 会话转发来的程序打不开本机路径,所以先经**同一个会话的 SFTP**
  把文件(目录连同里面的文件)传到远端新建的 `/tmp/velashell-drop-随机串/`(权限 0700),交给程序的是远端路径(`text/uri-list` 与纯文本路径),
  传的时候提示「正在把 N 项传到 user@host:port,交给 X 程序…」;会话已经断开就不接文件,传失败给错误提示。传上去的文件留在远端,程序之后还要用,
  不替它删。本机直接连进来的程序交本机路径。
- **从 X 程序往本机拖出来**(多窗口模式下):在 X 程序里按住拖动、拖到所有 X 窗口以外(本机桌面、资源管理器 / 访达、本机程序的窗口)时,
  VelaShell 接住它、发起一次本机的拖放,目的地放下就是**复制**(远端的原件不动)。文字直接给。文件要看程序在哪:经 SSH 会话转发来的程序给的是
  远端路径,所以先经**同一个会话的 SFTP** 把文件(目录连同里面的文件)取回本机临时目录 `velashell-xdrag` 下的一个新目录,取的时候提示
  「正在从 user@host:port 取回拖出的 N 项,请按住鼠标…」—— 取完才变成本机的拖放,期间要一直按着鼠标;取完之前就松手的不放,提示一句;
  会话已经断开、传输失败给错误提示。取回的文件留在临时目录(放下的程序可能还在拷),一天以后在下一次拖出时清掉;远端本机名不合法的字符换成 `_`。
  本机直接连进来的程序给的就是本机路径。拖出来的东西再拖回 X 窗口不接(那只是把刚取回的文件再传回去)。单窗口模式下不接
  (拖到 X 桌面窗口外面的东西归远端桌面)。
- **关闭**:点原生窗口的关闭按钮请客户端自己关(`WM_DELETE_WINDOW`);菜单、提示框不转发关闭。程序卡住时 —— 它声明了 `_NET_WM_PING`,5 秒内没回 ——
  弹警告样式的确认框「程序无响应」:「“标题”没有响应。要强制结束这个 X 程序吗？它的其他窗口也会一起关闭，未保存的内容会丢失。」,危险按钮「强制结束」
  断开这个程序。原生窗口之间的从属关系只认 `WM_TRANSIENT_FOR`(弹层不借用「当前活动的 X 窗口」当父窗口,免得关 A 的窗口连带关掉 B 的):宿主收掉一个窗口时
  连同它拥有的窗口一起收,X 里还映射着的不带父窗口重新显示;用户点父窗口的关闭键时子窗口不跟着关,改为请父窗口的程序关;应用退出与系统注销 / 关机一律放行。
  主窗口真正关闭(不是缩到托盘)时停掉内置 X Server。
- **键盘与鼠标**:按物理键注入 X 键码,布局跟随系统(或设置里手选的);在 X 窗口里每次按下先看一眼系统布局,切了布局随即跟上(非 Windows 平台至多每秒看一次)。
  同一个键按着又来按下时按自动重复转交,节奏是系统的。X 窗口得到焦点时把系统真实的 CapsLock / NumLock 推给 X(Linux 上桌面的键位表与锁定键改在后台线程读,
  激活窗口不再卡界面)。macOS 上带 Command 的组合键收不到 KeyUp 时,Command 松开把它们一并松开。指针坐标夹到 X 的 16 位范围再注入。
  图像光标每个窗口留最近用的 16 个,多了释放最久没用的,窗口关闭时全部释放。用户在宿主自己的界面里打字、点鼠标也报给 X Server,远端看到的空闲时间不再只按 X 输入算。
- **停服后马上重启**:旧服务端收工时交出的回调不认(窗口按句柄认,不按 XID),不会用旧句柄建窗口、也不会关掉新服务端的窗口。

剪贴板只与键盘焦点所在的会话互通、「限制经 SSH 转发来的程序」两项见 §14「X Server」页与 [settings-audit.md](settings-audit.md) 第十一批;
用户会碰到的现象与处理见 [X Server 排障](../xserver/troubleshooting.md)。

## 4B. 标签页行 Tab Bar（默认单行 36px，可切多行，`bg-page` 底）★重构

> 位于右区顶部。**只承载标签页与溢出控制，不再放全局功能按钮**（后者已上移至菜单栏 §4A.2）。设计稿节点：`nunbT`，溢出控制组 `Tab Overflow Controls`（`pZGS4`）。

### 4B.1 布局

```
┌───────────────────────────────────────────────────────────────────────┐
│ [Tab1][Tab2][Tab3 …可横向滚动区…] [+]   ……弹性空隙……          [◀][▶][▾]     │
└───────────────────────────────────────────────────────────────────────┘
     ← 标签滚动容器（clip） →       新建   spacer        左滚动 右滚动 列表下拉
```

- **标签滚动容器**（`clip:true`，`fill_container` 抢占中部）：横向排列全部标签，超出部分裁剪、可横向滚轮滚动；激活标签自动 `ScrollIntoView`。
- **`+` 新建标签**：跟在最后一个标签后。
- **弹性空隙 spacer**：把溢出控制推到最右。
- **溢出控制组 `◀ ▶ ▾`**（右侧，24×24 图标按钮）：
  1. `◀` chevron-left：向左滚动一屏/一个 tab；到最左端禁用置灰。
  2. `▶` chevron-right：向右滚动；到最右端禁用置灰。
  3. `▾` chevron-down：**标签下拉列表**（VS Code 式），列出全部会话名 + 状态点，点击任一项直接激活并滚入可视区；溢出时尤其有用。`◀ ▶` 仅在溢出时可用，`▾` 始终可用。

### 4B.2 单个标签页（Tab）内容

- 结构：状态圆点（`status-connected/connecting/disconnected`，7px）+ 会话名（JetBrains Mono 11）+ 关闭 `x`（12px）。
- 激活态：`bg-terminal` 底 + 顶部 2px accent 竖线 + 文字 `text-primary`。
- 非激活态：`tab-inactive-bg` 底 + 文字 `text-tertiary` + 关闭图标 `text-muted`（hover 才明显）。
- 连接中标签的圆点用黄色；断开用红色。
- 宽度随标题走（#521）：放得下就是标题原宽；一行放不下时按 §4B.3 收窄，**只削标题**（出省略号），圆点、图标与右端按钮原样不动。
- 固定的标签（§4B.5）右端不是 `x` 而是一枚图钉。
- 交互：
  - 单击=激活；中键/点 `x`=关闭（有未保存/传输中给二次确认）。固定标签不响应中键。
  - 双击标签空白=重命名（inline 编辑）。
  - 拖拽=重排顺序；拖出到边缘=触发 Dock 分屏/浮动窗口。固定标签只在固定区里挪，普通标签拖不进固定区。
  - 右键=标签上下文菜单。现状（2026-09-27）：同步输入（仅终端）｜关闭、关闭其他标签页、关闭所有标签页、关闭左侧标签页、关闭右侧标签页｜固定标签页 / 取消固定标签页｜水平拆分、垂直拆分、窗格最大化 / 还原｜标签位置、多行显示标签页（勾选项）。「关闭其他 / 所有 / 左侧 / 右侧」一律**绕开固定标签**。复制会话、重命名、移动到新窗口尚未实现。

### 4B.3 标签溢出逻辑（VS Code 式）★用户指定

- 当所有标签总宽 ≤ 容器宽：正常排列，`◀ ▶` 隐藏/禁用，`▾` 仍可用。
- 放不下时**先收窄、再溢出**（#521，照 VS Code 的 `tabSizing: shrink`）：只削**最宽的那几个**标签、削到同一宽度为止，比这个宽度窄的标签原样保留（「FTP」这种短标签不陪长标签一起变窄）；削到下限 **120px** 仍放不下才进入下面的溢出。
- 当溢出：
  1. 容器裁剪，激活标签自动 `ScrollIntoView` 保持可见。
  2. `◀ / ▶` 可点击滚动（到边界时对应按钮禁用置灰）。
  3. 鼠标在容器上横向滚轮可滚动。
  4. `▾` 下拉列表始终列出全部标签，作为溢出时的快速跳转兜底。
- 下拉列表项：状态点 + 会话名 + 右侧当前项勾选标记；支持键盘上下 + 回车选择；可在此直接关闭标签（悬停出现 `x`）。
- **多行显示**（#521，对标 Visual Studio 的「多行显示选项卡」）：开了之后放不下就换到下一行，不收窄、不溢出，标签条随行数长高（每行 35px，1px 分割线留在最后一行之下），激活标签的强调线跟着换到它那一行。入口两个、改的是同一个值：任一标签的右键菜单「多行显示标签页」（勾选项），与 设置 → 外观 → 窗口 里的同名开关（`AppearanceOptions.MultiRowTabs`，默认关）。整个工作区一个开关，所有窗格一起变；只对顶置的标签条生效 —— 停到左 / 右侧的标签条本来就是一个标签一行，菜单项在那里置灰。

### 4B.4 悬停唤出资源监控 ★用户指定（详见 §11）

- 鼠标移动到**任意标签页名称**上，**静止悬停 > 400ms** → 在**鼠标当前位置**浮现「系统资源监控面板」。
- 鼠标移出标签（或移入其他标签）→ 面板**自动消失**（建议 150ms 淡出防抖，移入面板本身则保持）。
- 面板展示的是**该标签所对应会话**的资源数据（非当前激活会话），因此可用于快速巡检其他会话。

### 4B.5 固定标签页 ★用户指定（#521）

> 对标 Visual Studio 的「固定选项卡」。与原 Dock.Avalonia 的 Pin（把面板钉到侧边自动隐藏，见 [dock-replacement-plan.md](dock-replacement-plan.md) 的产品红线）**不是一回事**，那一条仍然不做。

- 入口：标签右键菜单「固定标签页」/「取消固定标签页」（按状态二选一显示）；固定标签右端的图钉，点一下 = 取消固定。
- 位置：固定的标签永远排在所在窗格的最前面。固定 = 挪到固定区末尾，取消固定 = 挪到普通区开头（都是离原位最近的合法位置）。拖动与跨窗格移动守同一条顺序：固定标签落进目标窗格的固定区，普通标签只能落在固定区之后，插入线画在真正会落下的位置。
- 保护：「关闭其他 / 所有 / 左侧 / 右侧」绕开固定标签；中键关不掉它。冲着它本人的关闭照常生效：右键「关闭」、`Ctrl+W`。
- 「连接中」的占位标签也能固定，连上之后的真标签接手固定状态。
- 固定状态只在本次运行内有效，与分屏布局一样不落盘（布局持久化是宿主仓 `feature-plan.md` 里单独的一项）。

## 5. 终端主区 Terminal（`bg-terminal`）

### 5.1 终端内工具栏（28px，标签栏下方，`BdPtF`）

> `GQQwj` 已迁至菜单栏（§4A.2），此行仅保留**当前会话的只读信息**（左）+ 可选的少量右侧动作：
- 左（`termInfo`）：`root@web-prod-01:~`（accent）+ `uptime: 42d 7h 23m`（muted）+ `|` + `latency: 12ms`（绿）。
- 右：可选保留"清屏 / 全屏 / 更多"等与当前终端强绑定的次要按钮（全局功能已上移菜单栏）。

### 5.2 终端画布

- VT 引擎渲染：等宽逐行绘制，支持 xterm-256color、真彩、光标、选区、超链接识别。
- 支持鼠标选区复制、右键粘贴、Ctrl+滚轮缩放字号、滚动回看 buffer。
- **选中文本后高亮同屏匹配**（#628，2026-10-15）：双击选词或松开线性拖选后，在当前可见区域中按不区分大小写的纯文本子串规则高亮所有匹配；滚动到历史时只查正在查看的屏幕，折叠隐藏行不参与。查询至少 2 个字素（字母加组合音标算一个），误拖一格不会把满屏同一个字母都点亮；单个字只在它本身就是整词时生效（左右都不是词字符，如双击变量 `i`），此时也只匹配整词。视口里被自动换行折开的相邻行接成一段再找，跨折行的命中按行切段；选区本身跨自动换行也照常触发（双击被折开的长 URL）。实际选区与复制内容不变，匹配色不盖住真实选区；新选区替换旧匹配，输入、清除选区、调整网格和切换主/备用屏时清除。输出、滚动和折叠变化后按最新可见文本更新，但不在拖拽每一步或光标闪烁时重复扫描。空白、矩形块选、不连续多段与跨硬换行的多行选区不触发；拖过行尾时选区盖住的从未写过的格不算进查询（按复制取文本的口径收到最后一个写过的格），程序真打印出来的尾空格仍按原文匹配，不受复制裁尾设置影响。与 Ctrl+F 分开保存，关闭搜索栏不清除此高亮；Ctrl+F 的查找口径不变，跳转仍按原规则选中当前命中并结束此前的选区匹配。默认启用，无新增设置或快捷键。
- **Alt+左键拖拽 = 矩形块选**（#128，行为对齐 Windows Terminal）：按下鼠标那一刻是否按住 Alt 决定本次是块选还是常规线性选区，拖拽途中改变 Alt 不切换模式；复制时逐行取同一段列区间，行与行之间始终换行。应用开启鼠标追踪（htop/vim/tmux）时鼠标事件优先交给应用，此时用 Shift+Alt+拖拽强制块选。
- **Shift+左键点击 = 扩展选区**（#266，行为对齐 Windows Terminal / xterm）：已有选区时，Shift+点击保持锚点不动、只把选区另一端挪到点击处（点击前后皆可，选区随之翻向），按住不放还能继续拖拽微调；跨屏选长段日志时可先选起点、滚动回滚区、再 Shift+点击收尾。扩展沿用本次选区在按下那一刻定下的线性/块选模式。尚无选区时 Shift+点击仍是新建选区，以保住「按 Shift 绕过应用鼠标上报以便选文本」的既有语义。
- **Ctrl+Shift+左键拖拽 = 再添一段不连续选区**：把进行中那段定稿后另起一段，可反复追加；复制时各段按**文档顺序自上而下**拼接、段间断一行，于是「选中第 1 行，再 Ctrl+Shift 选中第 3 行，一次复制得到这两行」成立（与挑选先后无关）。每段各记各的模式，故 Ctrl+Shift+Alt+拖拽 = 追加一段矩形块选，可与线性段并存；Ctrl+Shift+双击 = 再添一个词。不带 Ctrl+Shift 的普通拖拽 = 从头选起（丢弃所有已追加段），搜索命中高亮亦然。落在 URL 上的 Ctrl+**Shift**+点击不跳浏览器（开链接是不带 Shift 的 Ctrl+点击）。终端里没有先例（Windows Terminal / iTerm2 / xterm 都只有单段选区），键位因此自定。
- **认证时服务端发来的横幅**（`SSH_MSG_USERAUTH_BANNER`：法律声明、PAM 的「密码将于 3 天后过期」）在第一个 shell 打开时以灰色 `●` 提示行写在终端最前面，跳板链上每一跳的都收、按到达先后；只显示一次，同一连接上再开的 shell 不重复。横幅来自**未认证**的对端：逐行把控制字符与双向控制符换成 `?`（终端转义序列因此失效；规则是 SSH 库公开的 `PeerText.Sanitize`，键盘交互认证的提示框也用它）后才写进终端，最多 64 行（多出的折成一行 `…`）、每行最多 512 字符。曾经宿主不接这个回调，横幅被静默丢掉。
  **标识串之前的前导行**（有的堡垒机、网络设备在 SSH 标识串之前就打印法律声明或维护公告，SSH 库规格 02 §3）同样处理：当成一段横幅，排在那一跳认证横幅的前面（2026-10-05 起；此前 SSH 库收集了它们，宿主没接）。
- 空闲/断开态覆盖层见 §7"断开连接状态"，连接中覆盖层见 §7"连接中状态"。

### 5.2.1 填入共享密码（#628，2026-10-15；入口形态 2026-10-16 重做）

- 无常驻入口。实时主屏的当前光标行出现 `Password:`、`Enter password:`、`[sudo] password for …:`、git / svn 的 `Password for 'https://host:8000':`（`for` 后的对象整段包在引号里时允许含冒号，#638）、SSH 的 `…'s password:` 或「密码：」「请输入密码：」等明确形态时，直接贴着光标行下沿弹出共享密码列表（WindTerm 式）；下方放不下（如最大化后提示符在末行）时翻到光标行上沿之上，两种情况都不挡住提示行，与光标行之间各留 2px 缝（缝做在锚点矩形上而不是 `VerticalOffset` 上 —— 翻转时偏移量不跟着反向，翻上去就成了往提示行里压）；窄窗格里被自动换行折成几行的长提示按整段逻辑行识别（只回溯活动屏幕内的折行），光标行本身就是完整提示时也照认。命令面板「填入共享密码」是同一入口的手动版，不依赖识别；它先把键盘焦点交回终端，↑↓ / Enter / Esc 才到得了列表。无默认快捷键，Ctrl+Shift+K 仍是清屏。右键粘贴不变，不扩展插件自有终端契约。
- 列表只列有密码的密码认证共享凭据，显示名称与用户名；弹层顶部常驻风险说明（不再有二次确认那一步），无可用凭据或出错时在列表上方给一行状态文字；列表读取失败时如实提示「无法读取或解密凭据，未发送任何内容。」并写 Trace，不说成「没有凭据」。列表只读元数据、不解密；**点中一行即读取、填入并自动回车提交**（2026-10-24 起；此前只填正文、要用户再按一次 Enter，选完顺手敲的字符会混进口令），没有确认按钮，也没有搜索框 —— 提示符前打的字必须原样进终端（可能正是用户在手敲密码），长列表靠滚动。
- 键盘（#638，2026-10-19）：列表打开时 ↑/↓ 只移动高亮（↓ 从第一项、↑ 从最后一项开始，首尾循环），不读取也不发送；Enter 填入高亮项，同样自动回车提交，填完列表收口、焦点回终端，之后的按键都落在提交之后。打开时不预先高亮任何一项：没按方向键就按 Enter，原样交给终端（用户自己的提交，哪怕是空口令），不会变成「把第一个密码发出去」。读取在途（列表禁用）时 Enter 被吞掉，↑/↓ 原地不动 —— 连按的第二个 Enter 若放过去，会抢在密码前面到达远端，交上去的是空口令，这次键入还会让在途的填入作废。Esc 收口不变。方向键在密码提示前只会把 ESC 序列塞进口令，所以列表开着时 ↑/↓ 一律归列表；打字仍原样进终端。
- 弹层不可聚焦，不得把键盘焦点从终端抢走（否则终端一失焦，弹层自己就会被收口规则关掉，点选永远落不上）；上面那几个键与命令补全弹层一样，由终端标签页在隧道阶段截下。识别是启发式的，不能可靠区别所有日志与提问；误判的代价只是多出一个可忽略的列表。
- 备用屏（vim/htop 等）、历史视口（回滚中）、无焦点、非活动标签、窗口失活、不生效的视图下都不弹出；验证码与私钥 passphrase 不识别。切换活动标签、失焦、滚动、窗口失活、断连、命令补全接线的标签页换绑、以及视图脱离可视树时收口。收口或按 Esc 后请求作废；用户对同一行提示开始手输（或已按 Esc 收口、已填入过）后不再反复重开，换一条新的提示才重新给出入口。不改变跟踪输入、却让请求作废的按键（空口令上的 Backspace、Enter 等）随即收起列表，但不记成拒绝 —— 不会留下一个点哪项都只回「已过期」的列表；输错后原地重新提示（光标所在提示行换了一条）时按新请求重开。
- 填入绑定原标签、桥、连接代次和打开时的光标行、列、屏幕代次、会话编码。切换活动标签（即使切回）、重连/断连、关闭、输入、提示上下文变化或弹层关闭后请求永久失效，迟到的读取结果不发送。
- 使用会话编码，经桥的串行输入通道发送密码正文与紧随其后的一次回车（与此刻按 Enter 发出的字节相同，远端开了换行模式时是 CR LF），两者拼成一段、同一次入队；出站输入代次与入队原子校验，期间若有同步输入或其他注入则拒绝。不走剪贴板、TypedInput、同步输入广播、命令补全跟踪或输入诊断。控制字符、不可编码字符、缺失/不适用凭据及解密失败均拒绝；不会把保护器返回的失败密文当密码发送。发送到队列不代表远端已接收。
- **安全限制**：远端是否关闭回显无法由 SSH 通道或提示文字可靠证明，EchoSuppressor 也不是证明。远端回显可能将密码写入屏幕、会话日志或录制；风险说明常驻在列表上方即为此。此功能不改变静态加密/系统密钥链方案，也不处理 SSH 登录前的结构化认证回调。

## 6. 文件浏览器 / SFTP（右区下部，默认 220px，可折叠/拖高）

- **头部（36px）**：左=当前路径面包屑（可点击逐级跳转），末尾铅笔按钮或 Ctrl+L 切换为手动输入路径（回车跳转、Esc 取消；`~`、`~/…` 展开成登录家目录，`~用户名`、`~用户名/…` 请服务端展开（SFTP 的 `expand-path` / `home-directory`，2026-10-05 起），展开不了就原样交给服务端报错），再往右一枚 `copy` 按钮**一键复制当前目录的完整远端路径**（与空白处右键的「复制当前文件夹路径」是同一个命令——此前必须先进编辑态才能选中复制），最后是刷新；右=视图切换、上传、新建文件夹、隐藏文件开关等图标。上传按钮左边是当前目录所在分区的剩余空间「可用 12 GB / 共 50 GB」（2026-10-05 起，`VelaTextMuted`、等宽 10px；SFTP 的 `statvfs@openssh.com`，进目录、刷新时更新；服务端不支持、FTP、插件协议查不到时不显示）。
- **跟随终端目录**（头部右侧的 `terminal` 开关，悬停提示「跟随终端目录(同步到终端当前路径)」，开着时 accent 色）：开着时终端 `cd` 到哪，列表就跳到哪。数据源是 shell 自己上报的工作目录（OSC 7 / 633；用户在 rc 里配的 OSC 1337、OSC 9;9 同样认）。SSH 会话连上后按对端 shell 的种类（bash / zsh / fish / dash 等 POSIX sh）静默注入一段上报钩子；「设置 → 终端 → 上报终端工作目录」关着、探不出 shell 种类、Windows 对端（cmd / PowerShell）一律不注入。
  - **切换用户、换 shell 之后照样跟随**（2026-10-19 起，#637）：钩子只装进了登录 shell，`su - node`、`sudo -i`、`sudo su -`、直接敲 `zsh` 起来的新 shell 都没有它——此前跟随就此停住，`exit` 回去才恢复。现在每次回车之后，终端静默约 0.4 秒仍没收到目录上报，就经同一条连接另开一个 exec 通道读一次进程表（Linux 读 `/proc`，macOS / BSD 用 `ps`），看本连接终端的前台是不是一个停在提示符前、还没注入过的交互式 shell（sudo 默认 `use_pty` 另开的终端也沿着找过去）；是就按它的种类补注一次，屏幕上同样不留痕。认登录 shell 靠进程树（exec 通道与 shell 通道同属一个 sshd 会话进程），不靠 shell 自报——自报谁都能在终端里伪造。
  - 不补的情形：前台在问密码、在跑脚本或命令、是 REPL 或开着备用屏幕的程序（vim、less、top）、是 `ssh` 到别的机器或 `docker exec`（那些目录不在 SFTP 看得到的这台机器上）、是 tmux / screen 里的 shell；等待或探测期间用户又按了键、终端又有了输出，这一次也作废，下一次回车再看。装着钩子的 shell 每个提示符都会上报，所以平时的回车根本走不到探测。
- **上传前预检空间**（2026-10-05 起）：这批从本机传上去的文件（扣掉续传起点）加起来比目标分区普通用户还能写的空间大时，先弹黄色确认框「空间可能不够」（「目标分区还剩 X，这批文件共 Y，可能放不下 —— 传到一半磁盘满会在服务器上留下不完整的文件。仍要上传吗？」，按钮「仍要上传」/ 取消），取消就一个都不传。查不到用量时不拦。
- **上传选择框**（「上传」打开；应用内绘制，文件与文件夹在同一个列表里混选、多选，可框选）：
  - 路径栏与上面头部的路径栏同一套手势：面包屑末尾的铅笔按钮、点面包屑后面的空白或 `Ctrl+L` 切成输入框（预填并全选当前路径），回车跳转、Esc 只收起输入框（再按一次才关选择框）、失焦取消；跳转失败时输入框留着、文本不动，红条显示原因。认两头的双引号（资源管理器「复制为路径」会带上）、`%VAR%` 环境变量、`~` / `~/…`、相对当前目录的路径与 `..`；只写盘符的 `D:` 当作 `D:\`。输入的是文件时进入它所在的目录并选中它，再按回车即可上传（2026-10-12 起）。
  - **键入定位**（资源管理器同款，2026-10-12 起）：焦点不在输入框里时直接敲名称开头的几个字母，选中以此开头的项、滚进视口、焦点跟过去；1 秒内连敲的字符攒成一个前缀（敲 `fxyc` 直达 `fxyc.txt`），连按同一个字母在同字母开头的项之间轮转；不分大小写，`..` 不参与。定位会替换掉之前的多选。
  - 列表里的回车与双击同一套规矩（2026-10-12 起）：只选着一个文件夹（含 `..`）时进入它，焦点给新列表的第一行；选着文件或多项时即上传。此前回车被列表行吃掉，到不了「上传」按钮。
  - **窗口尺寸**（2026-10-13 起）：默认 920×640（此前 672×552），四边与四角可拖动缩放，最小 560×380；屏幕放不下时打开即夹进工作区并居中。
  - **列表 / 图标两种视图**（2026-10-13 起）：标题栏右上角、关闭键左边是一个分段切换器（`list` | `layout-grid` 两段连成一体，选中的一段 `VelaAccentDim` 底 + `VelaAccent` 图标，悬停提示「列表视图」「图标视图」）。

    - **图标**（资源管理器「中等图标」）：108×96 的格子从左到右排、排满换行，没有列头；40px 图标在上、名称在下最多两行（超出省略号）。文件夹琥珀色（`VelaFileFolderIcon`），文件图标上印大写扩展名（不超过 4 个字符，如 `PFX`、`JPEG`；没有扩展名或更长时不印），`..` 用 `corner-left-up`；大小与修改时间放在悬停提示里。选中 / 悬停的底色是 4px 圆角块，格子之间留 2px。

- **列标题（26px，`bg-surface`）**：`文件名(280) | 大小(100) | 权限(120) | 修改时间`。可点击列排序。
- **文件列表（`fill_container`，可滚动）**：每行 28px。图标（文件夹/文件类型）+ 名称 + 大小 + 权限（`drwxr-xr-x`）+ 时间。首行可为 `..` 返回上级。

  - **远程编辑：三个打开入口**（#396，2026-09-08 起）。外观一样的几个「打开」曾经一个回传、一个不回传（双击那条从来没盯过本地副本），
    现在入口只决定**谁来打开**：
    - **右键「打开」**（菜单里的主操作）：下载到 `%TEMP%/VelaShell/builtin-edit/<8 位>/` 后弹出内置编辑器（非模态窗口）；超过 5 MB 不开，
      提示下载后在本地编辑。回传就是编辑器里的「保存」/ `Ctrl+S`，存一次传一次，不靠文件监视。
    - **右键「使用默认编辑器打开」**：交给「设置 → 文件传输 → 默认编辑器」里配置的程序（Windows 填完整路径或命令名，Linux 填命令名，
      macOS 填应用名、经 `open -a` 启动）；没配置时弹「未配置默认编辑器」，可一键直达那一页设置。
    - **双击文件**：按「双击文件时」三选一 —— 系统默认程序（默认）/ 内置编辑器（等同右键「打开」）/ 配置的编辑器（等同「使用默认编辑器打开」）。
      默认仍是系统默认程序，存量用户的肌肉记忆不动；它同样会回传。
  - **自动回传**（系统默认程序与配置的编辑器这两条；内置编辑器见上）：
    - 下载经传输浮窗（进度、限速、可取消）落到 `%TEMP%/VelaShell/remote-edit/<8 位>/` 的独占子目录，再交给对应的程序打开。
    - 盯住这份本地副本：写入、大小与改名都算（很多编辑器的「安全保存」是写临时文件再改名顶上去）。保存后防抖 600ms、等文件可读
      （被编辑器短暂锁住时最多再等 3 次 × 300ms），经传输浮窗传回原路径，浮窗里照常出现一行；传的途中又存了，传完接着再传一轮。
    - 同一个远程文件（同一会话、同一路径）再打开就**复用**同一个会话：本地副本干净时先重新下载最新内容再打开；有没传上去的改动、
      或上次回传失败时不覆盖本地副本，提示「X 还有没上传成功的改动，已沿用本地副本（路径），没有重新下载覆盖它。」
    - **不跟踪编辑器进程**（单实例编辑器的引导进程把路径交给已有实例就退，进程退没退与「文件还开着」没有对应关系）。会话只在两种时候结束：
      SFTP 文档标签（单栏、双栏）关闭时，赶在断开 SFTP 之前把最后一次改动传完（最多等 2 分钟）；应用退出时（最多等 5 秒）。
      终端侧栏的文件浏览器开出的会话没有前一种出口，一直挂到应用退出。
    - 回传失败：传输行标红，文件面板报「远程更新失败（文件名）：原因」，本地副本留着。收尾时还没传上去的，副本连同临时目录一起保留，
      并提示「X 未能上传。你改过的副本保留在 路径。」；全部传上去了才删临时目录。界面上没有常驻的「正在编辑」一类状态（2026-09-08 撤掉）。
  - **远程编辑的两个设置项**（设置 → 文件传输 →「远程编辑」一节）：
    - **双击文件时**（`Transfer.DoubleClickAction`：`system`（默认）/ `builtin` / `editor`，存着别的值按 `system` 读）；
      说明文字「三种方式都会把本地副本的每次保存自动传回服务器」。
    - **编辑后自动上传**（`Transfer.AutoUploadOnEdit`，默认开）：关掉 = 根本不监视本地副本，改动一律不回传，关标签、退出应用时也不补传。
      它只管外部程序那两条；内置编辑器的「保存」本身就是上传，不受它影响。
  - **远程编辑的诊断日志** `<数据根>/logs/remote-edit.log`（默认 `~/.velashell/logs/remote-edit.log`，用 `--data-root` 换了数据根就随之搬走）：
    常开，每行 `时间 [环节] 详情`，环节是 open / watch / upload / close —— 看得到 watcher 收没收到事件、上传发没发起、败在哪一步
    （这条链路的失败形态是「存了但什么都没发生」，没有异常也没有界面反馈）。超过 1 MB 就整份清空重开；写不进去时静默，不影响编辑与上传。
    只记外部程序那两条，内置编辑器不经过这里。
  - 拖拽本地文件到此=**上传**（触发 §9 文件传输组件）；拖拽列表项到本地=**下载**。
  - **键入定位**（2026-10-12 起；远端栏、双栏文档的本地栏、终端侧边栏的文件浏览器都有）：焦点在这一栏里时直接敲名称开头的几个字母，规则同上传选择框（1 秒内连敲攒成前缀、连按同一个字母轮转、不分大小写、`..` 不参与、滚进视口、焦点跟过去）；进了别的目录就从头攒。焦点在终端或另一栏时不生效。行整批换掉（进目录、刷新、后台自动刷新）后焦点留在这一栏的列表里 —— 给视口里的一整行、不滚动 —— 接着就能敲。只选着一个文件夹（含 `..`）时按回车进入它（与双击一样）；文件上的回车不做事（双击文件是下载并打开，不该被顺手的回车触发）。
  - **双栏文档的本地栏**路径栏（2026-10-12 起，与上传选择框共用一份）：面包屑末尾的铅笔、点面包屑后面的空白或 `Ctrl+L`（焦点在本地栏里时；在远端栏里是远端栏自己的路径栏）切成输入框，回车跳转、Esc / 失焦取消，跳转失败时输入框留着；认的写法同上传选择框（引号、`%VAR%`、`~`、相对路径、只写盘符），输入的是文件时进它所在的目录并选中它。
  - **同名冲突**：上传/下载遇目标已有同名文件时按设置（§14 文件传输「文件已存在时」）处理——询问（弹确认框：覆盖 or 跳过）/覆盖/跳过/重命名（`file (1).txt`）。
  - 右键=文件上下文菜单（下载、上传、重命名、删除、属性、复制路径、新建）。「新建」含**新建符号链接**：先问链接指向的路径（在某一行上右键时预填该行路径），再问链接名称（预填目标的最后一段）；目标原样写入，相对路径按链接所在目录解析（`ln -s` 语义）。FTP 只有支持 `SITE SYMLINK` 的服务器能创建，插件协议提示不支持。
  - **属性弹窗**：基本信息（类型、路径、链接目标、大小、修改时间）+ 属主 / 属组 + rwx 权限矩阵与八进制输入（两者双向同步，旁边回显 `chmod 640`）。
    - SFTP 会话上属主 / 属组是**可编辑下拉**：候选是远端 passwd / group 库里的用户名与组名（与列表显示名称同一张查表），也可以直接填数字 UID / GID；与 `chown` 命令同一个顺序，先当名称认，认不出再当数字。纯 SFTP 账号查不到表时候选为空，只能填数字。
    - 列表里的属主 / 属组名：有 exec 的会话整表一次读回（`getent`）；表里没有的 id（只开了 SFTP 的账号整张表都没有）经 SFTP 的 `users-groups-by-id@openssh.com` 补上（2026-10-06 起，每个 id 每个会话只问一次），还查不到才显示数字。
    - 清空输入框等于不改；填了远端没有的名字，错误条当场说出来，什么都不发。
    - 点确定只应用改了的项，**先 chown 再 chmod**：属主最容易被拒（非 root 只能把属组改成自己所在的组），被拒时什么都还没改；chown 成了而 chmod 被拒时照样刷新列表。
    - FTP 与插件协议改不了属主，两行只读。不递归、不批量；符号链接改的是它指向的对象。
  - **符号链接**：图标为 `folder-symlink`（指向目录，琥珀色，可双击进入）或 `file-symlink`（指向文件或断链）；名称悬停显示「→ 目标」；类型列为「符号链接」；权限串首字符为 `l`；属性弹窗多一行「链接目标」。
    - **删除**只删链接本身，不碰目标；递归删除遇到子目录里的链接同样只删链接。进子目录之前用不跟随链接的 stat 再确认一次它是真目录 ——
      列表里的属性按 lstat 还是 stat 给，SFTP 草案没有规定，服务端给的是跟随之后的属性时，指向目录的链接在列表里就像一个真目录。
    - **复制**（远端→远端）得到的是链接（`cp -P`）。
  - **同一台服务器上的复制**（2026-10-06 起）：服务端支持 `copy-data`（OpenSSH 的 sftp-server 支持）时在服务端内复制，数据不出服务器 ——
    此前一律下载到本机临时文件再上传，几 GB 的文件要几分钟。进度照常；保留时间戳时目标的修改时间设成源的。服务端不支持时照旧下载再上传。
    - **下载文件夹**时不跟进其中嵌套的目录链接（`rsync -r` 口径，避免指向 `/` 或指回上级无限展开）；显式选中的那一个链接照常跟随，指向文件的链接下载其内容。
  - **目录比较与同步**（仅双栏 SFTP / FTP / FTPS 文档；终端侧边栏的文件浏览器没有本地栏，不提供）：文档顶部 32px 工具条放「比较目录」（`git-compare`）与「同步…」（`folder-sync`）两个图标加文字按钮，右侧显示上一次比较的结论。
    - **比较目录**：比较两栏当前目录这一层，在两栏各自选中不同的条目（较新的、独有的；大小不同与冲突两栏都选）；任一栏换了目录，结论即清除。
    - **同步…** 打开独立窗口（窗体规格同链路追踪；同一文档只开一个，再点把它提到前面）。自上而下：选项区（本地目录 + 浏览、远端目录、方向分段、模式分段、比较依据（修改时间 / 文件大小 / SHA-256 校验，后者默认勾选、悬停说明回退规则）、删除多余文件、仅已存在的文件、文件掩码）→ 预览列表（勾选框 | 操作 | 路径 | 本地大小与时间 | 远端大小与时间，删除类以危险色显示）→ 汇总 / 附注（未处理的冲突、未进入的目录链接、服务器设不了修改时间）/ 错误 → 状态栏（进度与状态文字；全选、全不选、保持远端最新、比较、取消、同步）。
    - 改动任何选项都会作废预览；计划里有删除时执行前二次确认；执行完自动复查并在状态栏写明是否还有剩余差异。
    - **保持远端最新**：列表区换成活动记录（最新在上），按钮文案变为「停止监视」；关闭窗口或关闭文档即停止。
    - 选项含义、执行顺序与比较口径见 [SFTP双栏与WinSCP差距分析.md](SFTP双栏与WinSCP差距分析.md) 第七节。
  - **目录收藏**（2026-10-14 起）：文档工具条提供「收藏当前目录」与「目录收藏」。收藏项按当前连接保存名称、本地绝对目录与远程绝对目录，列表可直接同时应用两栏路径，也可编辑或删除；「管理收藏」打开独立管理窗口。
    - 保存时规范化本地路径与远程 POSIX 路径，并按规范化后的本地 + 远程路径去重；不检查目录是否存在。远程路径首尾的空格原样保留（POSIX 目录名可以以空格开头或结尾；名称照旧修剪）；相对路径按远程栏当前目录解析；`~`、`~/x` 用远程栏的家目录展开，`~用户名` 交服务端展开，展不开就拒收（「无法展开“~”：远程家目录未知，请输入绝对路径。」），不会存成「当前目录/~/x」。
    - 应用时两栏并行导航，失败的一侧保留原路径并显示该栏错误，成功的一侧不回滚；收藏本身不会因目录不存在而被删除。
    - 收藏随连接配置保存并随连接导出。已保存连接的收藏按字段落盘：新增、编辑、删除都在库里最新的那份收藏上执行，先落盘、成功后才改界面上的列表；编辑连接、连接成功后的写回、置顶、拖动分组、证书信任等整条保存配置的操作一律保留库里的收藏，不会把它清空或回滚；只有 Gist 同步拉取与导入 JSON 备份（覆盖已有连接）整条替换配置，收藏随之采用拉取到 / 文件里的那份；CSV 表达不了收藏，覆盖导入时保留本机的。文档打开时先换成库里最新的收藏，别的文档刚加的收藏照样看得到。最近连接产生的临时配置只在当前文档生命周期内有效。双远程文档、访问历史、分组与快捷键不提供。
    - 管理窗口的新增、编辑、删除对话框以管理窗口自己为属主弹出（文档不是当前标签时照样能用），失败提示显示在窗口底栏；文档关闭时管理窗口随之关闭。工具条下拉菜单里的收藏名与路径按原样显示，`_` 不会被当成访问键吞掉。
  - 选中态 `bg-hover`；多选（Ctrl/Shift）批量操作。
  - 导航采用“先加载、后提交”：失败保留原路径、列表、选择与滚动位置；进入新目录后清空选择并回到顶部。
  - 刷新当前目录保留仍存在的选中项与滚动位置；内容未变化时不重建列表。并发导航只接受最新请求结果。

### 6.1 多终端同步输入频道（替代原广播输入栏）

- 入口在标签页右键菜单"同步输入":固定四个频道 A/B/C/D,以颜色区分(粉/蓝/橙/绿),另有"离开所有频道"。
- 对等模型:频道内任意标签的用户输入(键盘/IME/粘贴)实时复制到频道内其他标签;切换到频道内任一标签继续输入同样互通。每个标签同时只能属于一个频道。
- 已加入频道的标签在标签头状态点前显示频道字母(A/B/C/D,频道色);终端上方出现频道横条:色块 + "同步通道 X 中的输入" + [暂停] [离开频道] [关闭频道]。
  - **暂停**:本标签暂不发送也不接收频道输入,再次点击恢复;
  - **离开频道**:仅本标签退出(横条右侧关闭钮等价);
  - **关闭频道**:频道内全部标签一并退出。
- 转发直写各目标的 PTY(桥的 SendRaw),不经接收端终端控件的输入事件:不会二次转发(防回环),也不会在非焦点标签触发命令补全弹层——智能建议只出现在用户正在键入的焦点标签。
- 断开的标签不接收转发(以 IsConnected 为闸门);关闭标签自动退出频道。快捷命令的多目标下发不再经频道二次转发,避免重复注入。

### 6.2 远程 + 远程双栏（#524）

由 §3 的多选（恰好两条）打开：一个文件标签里两栏各连一台机器，标签标题「左 ⇄ 右」，色条与图标取左栏那条配置，状态灯取两条连接中较差的一条。

- **连接**：两条依次连接（各自照常弹凭据框、指纹 / 证书确认），占位标签写「左 ⇄ 右」。**任一条没连上就整体回滚**：已连上的那条随即断开，失败留在占位标签的失败卡片上，取消则撤掉占位；不会出现只有一栏的文档。两条连接都归本文档所有，关标签时一起断开；不复用别的标签已开着的会话。SSH / SFTP / FTP / FTPS / 插件文件协议任意组合。
- **插件文件协议那一栏**：带协议自己的右键动作（如 S3 的「复制分享链接」），标签图标取插件自报的那个（左栏是插件时）。插件兼实现了 SDK 的 `IProtocolStreamUpload` 才能**接收**从另一栏搬来的文件；没实现的那一栏只能作为源 —— 往它那边的复制按钮置灰、拖放不接受。
- **两栏**：各是一个完整的远程文件浏览器（§6 的全部交互），头部的服务器徽章带各自那台机器的标识色（与标签色条同一套），两边都是远端，光看路径分不清哪栏是哪台。
- **在两栏之间搬文件**：
  - 工具条「复制到右栏 ›」「‹ 复制到左栏」：把一栏选中的文件与文件夹搬进另一栏的当前目录；
  - 把一栏的行拖到另一栏（只接受同一文档里另一栏的行；同一栏里拖放仍不做，见 #474）。
  - 数据经本机**内存流式中转，不落本地磁盘**：源端顺序读、目标端边收边写，耗时约等于较慢的那一段。协议本身没有服务器到服务器的复制原语，不走在 A 上执行 `scp` / `rsync` 直连 B 的做法（要在 A 上持有 B 的凭据或转发 agent，还要 A 能直连 B）。
  - 与上传共用同一条传输管线：冲突策略、并发上限、限速（按上传方向计）、保留时间戳、传输日志（方向记为 `RELAY`）、失败后在传输浮窗里重试。传输浮窗里方向记为 `⇄`。
  - **断点续传**：与上传同一口径（设置 → 文件传输 → 断点续传）。取消或失败后目标上的半截保留，重试或下次传同一个文件时，核实目标是源的前缀（此刻的目标长度、回退一个在途写入窗口、比对尾部）后从那里接着写。续传要在源里来回定位，所以**只有源是 SFTP 时才续**；源是 FTP 或插件协议（只能顺序读）、或目标是插件协议（SDK 的流式上传不续传）时核实不了，**按同名冲突策略处理**（与核实了但对不上同一条路），而不是悄悄整份重传 —— 那会不经询问覆盖一个可能与此无关的同名文件。关掉断点续传时，中途失败按「清理半截文件」设置处理。源端在开始写之前就读不到（被删 / 改名）时，目标原封不动，**不会**把同名的原有文件当半截文件删掉。取消就是取消：不会被报成「传输中断、可以续传」。
  - 文件夹递归；目录里嵌套的指向目录的链接不进入（与下载同一口径）。
- **比较目录**：比较两栏当前这一层（按大小与修改时间，任一栏是 FTP 时按推断出的时间精度），在各自一栏选中较新、独有或内容不同的条目，结论显示在工具条右侧。
- **不提供**：同步窗口与「保持远端最新」（它们按「本地 ↔ 远端」设计）；启动时恢复会话不恢复这类标签。

## 7. 状态栏 Status Bar（跨整宽 24px，`bg-sidebar`）

- **左侧**：`wifi` 图标（连接色）+ `SSH • web-prod-01:22` + `｜` + `Latency: 12ms`（accent）+ `｜` + `↑ 2h 34m`（在线时长）。

- CPU/内存/网络为当前会话的实时轻量指标（与 §11 资源面板同源，此处为常驻精简版）。
- 各字段可点击：如点击尺寸=触发一次 resize 同步，点击编码=切换编码菜单。

### 断开连接状态（`ZufZw`）

当会话断开：终端画布变暗并居中显示断开提示（红色状态 + "连接已断开" + 「重新连接」按钮 + 断开原因/时间）；对应标签圆点转红；状态栏连接图标转红；侧边栏该主机圆点转红。支持自动重连开关（指数退避）。

**自动重连只救「没人要它结束」的断开** —— 掉线、超时、服务端崩溃。以下五种一律不自动重连，
断开提示照常显示，重连留给用户按「重新连接」（与隧道那条「用户手动按停过的不会被自动拉起」同理）：

- 用户点了工具栏的「断开」；
- 在远端敲了 `exit` / `logout`，即远端 shell 自己退出（协议上表现为对端正常关闭通道）；
- 本地终端的 shell 退出；
- 初次连接就没连上（尤其是认证失败——自动重试只会连着撞几次密码）；
- 重连败在主机指纹上：用户在确认框里拒绝了、变更被「指纹变更时阻断并告警」拦下，或者自动重连时指纹需要确认（见 §主机指纹确认：自动重连不弹这个框）。
  再试多少次结果都一样；用户手动「重新连接」时才弹框问他，连上之后自动重连照常。

### 连接中状态

**标签先建，会话后连。** 用户一点"连接"，标签页当场就在，处于连接中态；会话建好之后再原位
换成真内容。四类文档型连接（SFTP / FTP / 插件文件系统 S3… / 插件工作台 Redis…）以前是
"连上了才有标签页"，链路一慢，屏幕上没有标签、没有圆点、也没有转圈，看起来就是"点了没反应"。

连接期间三个地方同时给回执：

| 位置 | 内容 |
| --- | --- |
| 标签页正文 | 居中卡片：48px 圆底里一圈**不确定**进度环 + 「正在连接 &lt;会话名&gt;」+ 连接类型（SFTP / FTP / S3 / Redis…）+ 一个出口 |
| 标签页签 | 黄色状态圆点 + 12px 进度环（取代该类型的图标），环色取该会话的强调色 |
| 状态栏右下角 | 后台活动圆环 + 一行摘要，悬停列出全部进行中的活动 |

几条容易做错的：

- **等用户输入的时候不转圈**：凭据框与证书信任提示是在等人，不是在等网络。弹框之前先把
  右下角那条活动销掉，回来再开一条。
- 进度**一律不确定**：连接没有可数的阶段，编一条平滑的假进度条只是好看。
- 标签页正文的「取消」与标签上的 ×、`Ctrl+W`、右键关闭是同一件事：关掉一个还在连的
  占位标签 = 不连了，取消一路传到底层握手。
- 连接期间资源管理器树上该配置的圆点同样转黄。

### 文档型连接的失败提示

有了上一节的占位标签，失败就**落在它自己那个标签里**：同一张卡片换成失败态（红色图标 +
具体原因 + 「重新连接」+ 「关闭标签页」），与终端标签页内的断开覆盖层完全一致。
**不再弹模态框**——模态框会挡住用户手上正在做的、与这次失败毫不相干的事；文档型连接
以前弹框，只是因为"连不上就没有标签，失败没有地方可画"，而现在有了。

- **用户主动取消不算失败**：凭据框上点取消不弹任何东西，占位标签一并撤走（留个空壳等于
  用户取消了个寂寞）。取消时还要把 `LastConnectionError` 清空，插件代开会话那条路径靠它区分
  "没连上"与"人不同意"。证书信任提示上点"不信任"同理不弹框，但原因写进失败卡片——
  那是这条连接的结局，得留在它自己的标签里。
- 三次凭据都没过、循环退出时最后一条原因也要落到卡片上，否则用户输三遍密码之后得到的是一片安静。
- 插件协议族的异常消息（`ProtocolConnectionException` 等）按 SDK 契约本就是面向用户的、并且已带端点，
  宿主原样呈现，不再套一层"连接 X 失败："把同一个地址写两遍。
- 凭据框自己仍走那道串行闸：启动恢复多条会话是并发发起的，两扇模态框叠在同一个 owner 上会互相锁死。

### 后台活动圆环（状态栏右下角）

任何可能超过一瞬的后台工作都在这里登记，圆环据此显示、悬停列清单。已登记的有：
插件装载 / 校验 / 预读、配置同步，以及**全部连接路径**——SSH 首连与重连、插件终端
（Telnet / 串口）的打开与重连、四类文档型连接、以及插件面板的打开。

边界：插件的惰性激活由插件管理器自己登记；面板打开之后插件再去拉自己的数据，那段宿主
看不见也管不着，不给它编一个转圈。

## 9. 文件传输提示组件 ★用户指定（悬浮 / 可拖拽 / 自动消失）

**出现条件**：**当且仅当存在进行中的文件传输任务时**，在**主窗口右上角**悬浮出现（280px 宽，`bg-surface` + 小阴影 + 圆角 6）。无任务时不存在。

**结构**：
- **头部（32px，底部分隔线）**：左=`arrow-up-down`（accent）+「传输」+ 计数徽章（`accent` 底，如 `2`）；右=`x` 关闭（仅隐藏面板，不取消任务）。**整个头部为拖拽把手**。
- **传输条目（每条竖排）**：
  - 首行：文件名（如 `backup-2025.tar.gz`）+ 右侧百分比（`67%` accent）或状态（`完成` 绿）。
  - 进度条（3px，`border-primary` 底 + `accent` 填充按比例）。
  - 说明行（9号 muted）：`142 MB / 212 MB • 4.2 MB/s • ↑ 上传中` / `1.2 KB • 已完成 • ↓ 已下载`。
  - 悬停条目右侧出现操作：暂停/继续、取消、打开所在文件夹。

**交互逻辑（★关键）**：
1. **可拖拽移动**：按住头部可在主窗口内自由拖动，位置记忆（下次出现沿用），限制在窗口可视范围内。
2. **自动出现**：新传输任务开始 → 若面板不存在则从右上角淡入。
3. **进度实时更新**：多任务纵向堆叠，徽章数=进行中任务数。
   - **SFTP 上传**按 `WRITE` 收到 `STATUS OK` 后的连续确认水位 `DurableLength` 计字节，不按流水线入队量计；等待 `Flush` 排空在途写入时每 200ms 采样，上报 UI 按 100ms 节流。确认字节到达总数时绕过节流强制更新，满格只报一次（`Flush` 采样与最后一次写回调都碰到满格时只放第一帧，成功收尾也不再补一帧），但 **100% 不等于 `Completed`**：完成仍须等待可选的 `fsync` 与 `CLOSE` 成功；收尾失败仍报失败。插件经远程文件能力发起的上传 / 下载，满格那一帧（插件拿它当「完成」）不随宿主进度转发，而是在传输任务成功之后补发一次；任务失败就不发。
   - **SFTP 上传 / 下载续传**的百分比包含已经核实的前缀；速度为「累计字节 − 核实前缀」除以核实后开始计的本次耗时，仍是**本次传输全程平均**，不是瞬时速度，也不把已有前缀或核实耗时算进去。
   - **亚字节速率**（`0 < 速度 < 1 B/s`）按 `B/s` 安全格式化，不得因单位索引越界而阻断界面更新。
4. **自动消失**：**当所有传输任务完成（或全部被取消/失败已确认）时，面板自动消失**（建议全部完成后停留约 3s 展示"完成"态再淡出；若中途有新任务加入则重置计时）。
5. 失败任务红色标注 + 「重试」；用户手动点 `x` 仅收起，任务仍在后台（可从状态栏/命令面板重新唤出）。

- 若该会话已断开，显示"数据不可用"占位。

**GPU 采集口径**：NVIDIA 使用 `nvidia-smi`，AMD 使用 DRM sysfs；Intel `i915` / `xe` 读取 DRM 客户端在 `/proc/<pid>/fdinfo` 里的逐类引擎累计计数与 resident 内存。只有 `/sys/bus/pci/drivers/i915` 或 `xe` 下确有已绑定的设备才扫描；扫描时先用 `ls -ln /proc/[0-9]*/fd` 挑出指向 `/dev/dri/` 的 fd，只读这些 fd 的 fdinfo，每轮一次，按 `drm-pdev` 分到各张卡、按 `drm-client-id` 去重。i915 的引擎计数是纳秒，分母取远端 `/proc/uptime` 的差值（读不到才退回本地采样间隔）；xe 只给周期计数，按 Δcycles / Δtotal-cycles 计算。差分按（客户端, 引擎）配对，只认两次采样都在的客户端 —— 新客户端这一轮只当基线，退出的客户端不再参与；同类引擎有多个实例时按 `engine-capacity` 折算，利用率取最忙的那一类引擎（与 `intel_gpu_top` 同口径），不把各类引擎相加。内存：`local*` / `vram*` 区域是 Arc 等 Intel 独显的板载显存，标为“显存”，sysfs 不给总量，只显示已用量；`system*` / `stolen-system*` / `gtt` 区域是核显共享的系统内存，标为“内存”，总量采用系统内存总量。GPU 进程表只来自 `nvidia-smi`，显存一列的表头固定为“显存”，不随选中的卡改成“内存”。非 root 用户只能看到有权限读取的客户端，不能把它当成整卡全局利用率。缺少权限或驱动接口时显示“不可用”，不把缺失值显示为 0%。列卡时，没有 PCI 厂商号的 DRM 设备（树莓派 vc4 / v3d、Rockchip、simpledrm）一个指标也读不到，不单列成卡；没绑驱动的 PCI 显示设备，驱动一栏留空。

| 用户名 | 这批连接原本一样就预填那个值，不一样留空 |
| 端口 | 1–65535，原本一样就预填，不一样预填 22 |
| 认证方式 | 标题下全宽分段：共享凭据（下拉选一条，#550）/ 密码（可留空，连接时再问）/ 私钥（文件 + 可选口令）/ Agent / Tailscale SSH。FTP 与插件协议只认密码，选了别的那几条跳过 |
| 跳板主机 | 直连或本机的一条 SSH / SFTP 连接（不含正在改的这几条）；只对 SSH / SFTP 生效，会接出环的整批跳过 |

分组不在这里：多选菜单的「移动到分组」就是改分组，它带着「分组空了就删掉」那条规矩，这里再开一个入口两边迟早对不上。
点「应用」之前，底下一行已经算好「将修改 N 个连接；M 个连接的协议不支持所选认证方式，认证不变」之类 ——
混着 FTP 时把认证改成私钥，用户应该在按下去之前就知道那几条不会跟着变。一项都没勾、端口越界、选了共享凭据却没挑哪一条、
私钥没给文件时「应用」是灰的。应用完刷新资源管理器，浮层提示改了几条（有跳过时是警告级）。

同理，标签页、文件行也各有其上下文菜单（见对应章节）。

  - 换协议后当前页不存在（从 SSH 的「转发」页切到 FTP）就落回「常规」，页还在（SSH ↔ SFTP 的「SSH 选项」）就不动。
- **「常规」页**分节，节标题是 10px 的 `text-tertiary` 小标题 + 一条延伸到右边的细线：
  - **连接目标**：Host / Port 一行，下面是跳板主机（说明收进标签旁的 ⓘ 悬停提示——跳板决定连不连得上，
    所以留在「常规」页，而不是藏进哪一页）。
    - **IPv6**（#611）：Host 栏直接填裸地址（`2001:db8::1`，带 zone id 的 `fe80::1%en0` 也行）；从别处抄来的 `[2001:db8::1]`、
      `[2001:db8::1]:2222` 也认 —— 保存与测试时去掉方括号，方括号后面的端口取代 Port 栏（页脚预览照实显示）。方括号写坏了
      （不闭合、后面不是 `:端口`）就在栏下提示、三个按钮灰着。配置里只存裸地址：带着方括号的话，经跳板时会原样发给服务端，
      主机密钥也会与裸地址记成两台。各处显示 `host:port` 时 IPv6 一律加方括号。
  - **身份验证**（声明 `NoCredentials` 的协议整节收起）：用户名下方全宽单行认证分段（密码 / 私钥 / 证书 / Agent / Tailscale SSH，顺序即 `AuthMethod` 枚举值）；FTP 的加密方式仍在用户名右侧，插件协议这一格空着。
    其下依次是 FTP 的匿名登录 / 被动模式、明文 FTP 警告、密码或证书 + 私钥 + 口令、Agent 说明、记住密码。
  - **凭据来源**（#550，2026-10-03 起，身份验证一节的第一行；匿名 FTP、不带凭据的协议与 Tailscale SSH 不显示）：下拉第一项
    「在本配置中填写」，其后是全部共享凭据（「名称 (用户名)」）；旁边一个「新建…」（描边按钮），把表单里现有的
    用户名与密码 / 私钥带进共享凭据编辑框（不显示「使用这条凭据的连接」清单），建好即选中。
    - **选了共享凭据**：认证方式分段按钮、密码 / 私钥 / 证书几栏、Agent 说明与「记住密码」一并收起，下拉下方一行
      `text-tertiary` 摘要「共享凭据：用户名 X · 认证方式」并指向 设置 → 共享凭据。**用户名照常可填**：填了就覆盖凭据里的，
      留空跟着凭据走，占位提示写明会用哪个（「留空则使用凭据中的 admin」）；凭据自带用户名时用户名不再是必填。
      选中的凭据用户名与表单里的相同时，表单里那份清掉——否则凭据日后改名，这条连接还钉在旧名字上。
    - **保存**：配置只存引用（`CredentialSource`），认证材料一律不存；收起来那几栏里残留的旧值随之清掉，
      免得「测试」拿一份看不见的旧密码去连。
    - **两条阻止保存的错误**：引用的凭据已不存在（下拉里显示「(引用的共享凭据已不存在)」并选中它，让用户看见并改选，
      而不是悄悄落回「在本配置中填写」）；FTP 与插件协议选了非密码类的凭据（它们只认密码）。
    - **切回「在本配置中填写」**：把凭据的用户名（表单空着时）、认证方式与密码 / 私钥拷进表单，而不是丢下一排空框。
  - **插件协议的常用字段**：节标题是「<协议名> 设置」，只画没标 `IsAdvanced` 的字段。
  - **整理**：显示名称 / 会话分组 / 标签三栏并排；下面一整行**备注**（#549，`SessionProfile.Notes`）。
    - 多行文本框：回车换行（对话框没有默认按钮，回车不会误触保存），Tab 照常跳到下一个控件；
      最多约五行高，再长就在框里滚动，不把整页撑高。
    - 不分协议，每种连接都有。保存时去掉首尾的空行空格，只剩空白的存成 null；行内的换行原样保留。
    - 明文保存（不经过 `ISecretProtector`），云同步没开端到端口令时也照原样上传 ——
      框下的提示写明了这一点，口令请放在身份验证里。
    - 资源管理器里悬停这条连接时显示（§4）。
  - **Host / Port 那一行的形态由协议描述符决定**：
    - 声明 `ProtocolFeatures.NoEndpoint` 时 `Port` 整格收起（串口是一根线、SQLite 是一个文件，
      端口填什么都不会被用上）。**只收显示、不改判定**——端口取值照旧参与按钮可用性，
      收起一栏不该顺手把保存/连接按钮堵死。
    - `HostKind` 可以把 Host 那格换成下拉：`Choice`（只读）/ `DynamicChoice`（候选项在表单
      打开时向插件现取，旁边多一个刷新按钮）；配 `HostAllowsCustomValue` 则是**可编辑**下拉。
      串口用的正是「动态 + 可编辑」：端口是可枚举的（所以该给下拉），但没插的适配器、
      容器里映射进来的 `/dev/ttyS10` 也必须填得进去，而一条存着 `COM7` 的旧配置
      更不能因为「这次没枚举到」就被下拉悄悄改成别的口。
  - 只有表单区**可滚动**（滚动条走全应用的两态方案，未激活时是一根 2px 细条，不常驻展开），
    标题栏、协议栏、页签、反馈条与页脚都不参与滚动。字段多的协议（S3、Redis）、证书认证这类长表单在页内滚；
    矮屏上窗口高度取 `min(设计上限 768，屏幕工作区 − 48)` 钳制（`ApplyScreenBounds`；768 与设置窗口 948×768 对齐），
    底部按钮始终点得到。
  - 插件协议里标了 `IsAdvanced` 的调优字段放在「高级」页，「常规」页只画常用的那些；
    编辑既有配置时只要有高级字段值非默认，「高级」页签上就点出圆点。
  - **「终端」页（只对 SSH）的「认证后执行命令」+ 延迟（0~60 秒）**：
    - 它是**每条配置各一份**的（`SessionProfile.PostAuthCommand` /
      `PostAuthCommandDelaySeconds`），与「设置 → 终端 → 会话」里那条对**所有**终端生效的
      「连接后执行命令」是两件事：每台机器登进去要做的事本来就不一样（堡垒机要 `sudo su -`，
      开发机要 `tmux attach`），挤进同一个全局框里只能二选一。两处都配则**先全局、后本条**，
      顺序与用户在两个界面上看到的一致。
    - **只对 SSH 出现**：命令是往 shell 通道里注入的，SFTP / FTP / 对象存储根本没有终端；
      换到这些协议时该栏收起，保存下来的值也一并归 null——留着它就是一条永远不执行的命令，
      而且切回 SSH 时会诈尸执行一次。
    - **延迟的意义**：PTY 输入由内核缓冲，本不必等提示符；需要它是因为对端登录后还会自己
      往终端里写东西（motd 脚本、企业登录横幅、把 stdin 一起读掉的 banner），立刻注入会被
      这些输出盖住甚至吞掉。`0` = 握手完立刻发；上限 60 秒**钳在模型的 setter 上**而不是只靠
      界面——配置文件可以手改，一个 `99999` 会让那条命令看起来永远不执行。
    - **重连同样执行**（就地重连复用同一标签），因为它描述的是「每次登进这台机器要做什么」。
      延迟 > 0 时用 `DispatcherTimer.RunOnce` 延后发而不是阻塞握手流程，回调里以
      会话 id + 连接状态复核身份——这几秒里标签可能已断开、被关掉或重连成了另一条会话。
  - **「终端」页的会话级终端项（只对 SSH 出现）**：编码、终端类型、配色方案、标签颜色（取色器，见 §14.3；
    没有颜色 = 自动配色，浮层底部一键清回自动）、
    起始目录、保活间隔，以及**防空闲（秒）**。全局设置只能有一套，但机器不是一样的——堡垒机的
    输出是 GBK、开发机是 UTF-8；生产环境希望标签一眼看出是红的。这些差异按机器走，挤进一个
    全局开关里就只能二选一。除防空闲外每一项都是「留空 / `-1` = 跟随全局」。
    - **防空闲与保活防的不是同一件事，互补，不能互相替代**：保活是 SSH **协议层**的心跳
      （`KeepAliveSeconds` → `SshConnectionOptions.KeepAlive`），防的是 NAT 与防火墙把闲置的
      TCP 连接悄悄回收；防空闲防的是**服务端**按空闲把人踢掉（bash 的 `TMOUT`、堡垒机的会话
      超时），而那些一律按「tty 上有没有输入」计时——协议层的心跳包它们根本看不见。两个「秒」
      并排摆着，提示文字必须把这层区别说死，否则用户只会以为自己设错了地方。
    - **送的是 `NUL`（0x00），不是空格**：空格会被 shell 当成用户输入留在命令行上，也会被全屏
      程序（vim / less / htop）当成按键吃掉——人离开一小时回来，命令行前面多了三十个空格，
      或者 less 已经翻到了文件末尾。`NUL` 在行规范里被丢弃，却照样刷新 tty 的读活动：
      有输入，但什么也没发生。
    - **只按会话，没有全局开关**——与同组其余各项不同，它的 `null` 是「没开」而不是「跟随全局」：
      会按空闲踢人的只是特定那几台机器，而注入的字节终究是打进对端 tty 的，给每条会话都撒一份，
      只会让其余那些平白多担一份风险。界面上 `0` = 关闭，存回配置时归一成 `null`，免得给每条
      从没碰过这一项的配置留下一段「设过、设的是关」的假痕迹。上限 3600 秒**钳在模型的 setter 上**，
      与保活同一口径。
    - **只在真的空闲时才发**：计时从**最后一次出站写**算起（击键、程序注入，以及它自己发的那一下），
      不是从上一次注入算起。定时器醒来发现距上次击键还不够久，就把闹钟改到刚好满一个间隔的那一刻
      再睡回去——用户正在打字的那段时间里，一个多余的字节都不会有。
    - **ZMODEM 会话进行中不发**：那条流上跑的是协议帧，插一个字节轻则 CRC 错重传，重则整笔失败，
      与击键在传输期间被拦下是同一个理由；传输本身就是流量，服务端此刻也不认为会话空闲。
      拦下的那一发不作废，能发了立刻补。
    - **重连同样生效**（与「认证后执行命令」同一条纪律）：按会话配置设在挂载传输那一步，首连与
      重连各设一次——漏掉重连的表现是「断线重连之后又开始被踢」，而没人会把这件事和重连联系起来。
      改了配置要**下次连接**才生效，与同一栏里的保活一个口径；本地终端没有会话配置，那条路上
      一个字节都不会发。
  - **「SSH 选项」页与「转发」页**（`SessionProfile.Ssh` → `SshSessionOptions`）：压缩、
    ssh-agent 转发、X11 转发三项，**默认全关**（与 OpenSSH 一致）；以及算法协商的两项
    （允许老算法、自定义算法清单，2026-09-29 起，见下）。每项下面一行灰字说清
    「什么时候该开」—— 压缩开错了只是多耗 CPU，两个转发开错了是把本机能力借给远端。
    「允许老算法」与「ssh-agent 转发」的标题旁各有一个警示色描边标签（「不安全」/「仅限可信主机」）。
    全部是默认值时整个对象存 `null`，老配置零迁移。
    - **可见性**：压缩与算法协商两项在「SSH 选项」页，对 SSH 与 SFTP 都出现（两者走同一条 SSH 连接）；
      两个转发在「转发」页，只挂在交互式 shell 上，**只对 SSH 出现**，SFTP 配置保存时一并归 false ——
      与「认证后执行命令」同一个理由。
    - **压缩（高延迟 / 低带宽链路）**：延迟较高（跨境、跨洋，往返 100 ms 以上）或带宽紧张时
      建议开启，终端输出与文本文件能省下大量流量；局域网、或主要传输图片 / 压缩包这类已压缩
      数据时不建议开 —— 只会白白多占 CPU。协商用 `zlib@openssh.com`（认证之后才开始压缩），
      **不提供**老式 `zlib`（认证之前就压缩，是 CRIME 一类攻击的入口）；`none` 始终排在后面，
      服务端 `Compression no` 时自动落回不压缩，不会因此连不上。跳板链上逐跳各按各的配置协商。
    - **ssh-agent 转发（`-A`）**：在这台服务器上继续 ssh 到下一跳时用本机 agent 里的密钥，私钥不必
      拷上服务器。灰字里写明代价：会话期间远端的 root 也能借你的 agent 签名，只对信得过的机器开启。
      只转发给终点那一跳的交互式 shell（跳板只开隧道、不开 shell）。打开后缩进出现两道收紧：
      - **只转发选中的密钥**（`SshSessionOptions.AgentForwardKeys`，存 OpenSSH 公钥行；`null` = 整个 agent 可见）：
        勾上后列出候选清单，每行是名字、类型、`SHA256:` 指纹与来源。候选按指纹去重合并三处：本机 agent 里现有的钥、
        `~/.ssh` 下的公钥、这条配置里已经存过的钥 —— 后者即使已不在前两处也照样列出并保持勾选，免得打开再保存就悄悄少一把。
        清单为空（agent 没在跑、`~/.ssh` 也没有 `.pub`）时一行黄字说明怎么补。没选中的钥，远端 `ssh-add -l` 根本看不见。
        - **勾上却一把都没选不许保存**（页脚报错）：那是一条永远不转发、用户却以为开着的配置。
        - **运行时存下的钥一把都解析不出来就不转发**，终端顶部写一行黄字 —— 绝不退回「整个 agent 可见」
          （SSH 库把空的 `AllowedKeys` 解释成不限，那会把最严的设置翻成最宽的一档）。
      - **每次签名前询问**（`AgentForwardConfirm`）：远端每次借 agent 签名都弹一个模态确认框（见下）。
      - 开成之后那行灰字带上这两项，如「ssh-agent 转发已开启 · 仅转发 1 把密钥 · 每次签名都要确认」。
      - SFTP 配置与转发本身关着时，两项一并不存。
    - **agent 签名确认框**（`AgentSignPromptView`，外壳同主机密钥弹窗）：告警条写「远端会话请求用你本机 ssh-agent
      里的密钥签名」，说明里点名正当来源（自己在远端执行 ssh / git）与该拒绝的情形（自己什么都没做）；信息条列出
      **会话**（`用户@主机:端口`）、**用途**、**目的主机**（仅登录时）、密钥类型、指纹、agent 注释（通常是私钥路径）；
      底部一行「60 秒内不作答将自动拒绝」。
      - **用途**与**目的主机**是用户分辨「自己刚敲的 `git pull`」与「有人拿这把钥登录别处」的依据，取自 SSH 库从被签数据里认出的上下文
        （[spec/07 §7.2.1](../ssh/spec/07-forwarding.md#721-签名确认要说得出签来做什么)）：用途写「以「git」身份登录 SSH 服务器」
        「数据签名（命名空间 git）」或「无法识别的数据 —— 不是 SSH 登录」；目的主机写已知主机里对得上的名字（非 22 端口带端口），
        不在已知主机里时写「不在已知主机里（指纹）」，核实不了时写「无法核实 —— 远端没有证明要登录哪台主机」，**后两种用警告色**。
        已知主机读不出来时只是摆不出名字，照样弹窗。
      - 三个按钮：**拒绝**（描边）/ **本次会话内允许**（描边，这条会话关闭前这把钥**做同一件事**不再问 —— 同一用户登录同一台目的主机，
        或同一命名空间的数据签名；批准了 `git pull` 到 github，不等于也批准了拿这把钥登录别处）/ **允许一次**（强调药丸）。
      - **「拒绝」同时是默认键与取消键，弹出即获焦点**：窗口会在用户正往终端里打字时弹出，顺手的回车或 Esc
        只能落在拒绝上，任何「允许」都不是默认键。
      - **fail-closed**：60 秒无人应答、通道关闭、没有主窗口、弹窗出错一律拒签，还开着的窗口当场收起；
        实现方过了期限才交回「允许」也照样拒。远端的 ssh 看到的是「agent 拒绝签名」。
      - 多条会话同时请求时**排队逐个弹**，不叠模态框 —— 否则分不清哪个框是哪条会话的。排队期间期限照样在走。
    - **X11 转发**：把远端图形程序的窗口显示到本机的 X 服务器上。宿主**内置了 X 服务端**（标题栏 X Server 按钮、
      §14「X Server」页），开箱即用、各平台都有；Windows 上也可以改用自己装的 VcXsrv，用 Xming / X410 的照旧自备
      （不捆绑第三方 X 服务端的二进制，理由见 `feature-plan.md`「确认不做」）。打开后多出两项，排成两行：
      「本机 X 显示」的标签单占一行，输入框与「受信任（`-Y`）」勾选框同在第二行、各自垂直居中：
      - **本机 X 显示**：留空时依次取 ① VelaShell 管理的本机 X Server（在运行就用它的显示；没运行且
        「X11 转发时自动启动」开着，就先把它起来 —— 但本机已经有别的 X 服务端在用（Windows 上是当前用户会话里的进程在 `localhost:0`
        听 —— 终端服务器上别的用户开着的不算，其它平台是设了 `DISPLAY`）、或选了 VcXsrv 却没装时不插手，也不提示）② `DISPLAY` 环境变量
        ③ `localhost:0.0`（Windows 上几乎没人设 `DISPLAY`，而那几款 X 服务器默认都监听 TCP 6000）。占位文字显示的是
        后两档。自动启动失败只写一行黄字，不拦 shell。**填了就只用填的**，本机 X Server 不插手。
        取自内置 X 服务端、且为受信模式时，x11 通道**直接接进进程内的服务端**，不经本机端口，并把会话的 `user@host:端口`
        作为连接名交给服务端（日志、客户端清单与「剪贴板跟着焦点所在的会话」都按它认会话）。之后内置引擎停了（比如换成 VcXsrv），
        这条会话里新开的 X 程序改走本机 TCP，连此刻在运行的那个 X 服务端（只在 Windows 上；Linux / macOS 没有别的引擎，不退）。
        Linux / macOS 上内置 X Server 默认不开 TCP 端口，这里**填** `localhost:N` 的连不上 —— 留空（经连接器）或填 `:N`。
      - **受信任（`-Y`）**，**默认勾上**。没勾就是非受信（相当于 `ssh -X`）：远端程序只碰得到非受信程序的窗口 —— 截不了别的程序的画面、
        读不到别的程序的键盘输入、不能伪造输入。内置 X 服务端两种都支持（2026-10-10 起；非受信的通道经连接器直接以非受信客户端接入，
        不跑 `xauth`）；外部 X 服务器的非受信模式要它支持 SECURITY 扩展、本机装有 `xauth`。悬浮提示写明两档各意味着什么，
        以及少数老程序在非受信模式下工作不正常。（此前内置 X 服务端没有 SECURITY 扩展，没勾时不开转发、终端顶部一行黄字说明原因。）
      - 转发**整条会话有效**，不设有效期 —— 「开了半小时之后新窗口打不开」只会让人以为转发坏了。
    - **被拒不连累会话**：服务端 `X11Forwarding no`、没装 xauth、本机 agent 没在跑、`AllowAgentForwarding no` 都很常见，
      为一个附带功能让整条会话连不上是本末倒置。X11 与 agent 转发都按「没开成就不开」请求（SSH 库的
      `ForwardFailureMode.Continue`）：设置失败时库不抛、shell 照常一次开成，原因由 `SshShell.X11SetupFailure` /
      `SshShell.AgentSetupFailure` 交回，各在终端顶部写一行**黄字**说明原因（本机 agent 没在跑时按原因码给本地化的提示，
      Windows 上点出要启动的服务）；开成了则写一行**灰字**（「X11 转发已开启 → 本机显示 localhost:0.0」；Linux / macOS 上内置 X Server 的显示是 `:0` 这种），与跳板链那行同一格式。
      首连与就地重连都会写。〔历史〕agent 转发曾经是被拒之后去掉它、再把整个 shell 重开一遍。
    - **允许老算法（连老设备用）**（`SshSessionOptions.LegacyAlgorithms`，默认关）：老网络设备、老系统往往只剩
      `diffie-hellman-group14-sha1`、SHA-1 的 `ssh-rsa` 与 `hmac-sha1`，默认清单谈不成。打开后把这三个**追加在默认清单
      之后** —— 服务端同时支持新算法时照样先用新的；灰字写明放开的就是这三个。CBC 一类本版没有实现，只剩 CBC 的设备
      放开了也连不上。
    - **自定义算法清单**（展开后四个输入框：密钥交换 `KexAlgorithms`、主机密钥 `HostKeyAlgorithms`、加密 `Ciphers`、
      MAC `Macs`；等宽字体，占位「默认」）：写法照 OpenSSH 的 `ssh_config` —— `+a,b` 追加到默认之后、`-a,b` 从默认里删掉
      （可带 `*` / `?` 通配）、`^a,b` 提到最前，不带前缀则整个替换。「默认」指放开老算法之后的那一份，所以从
      `~/.ssh/config` 里照抄一行就能用。悬停输入框看此刻的默认清单与另外可加的算法（随老算法开关刷新）。
      - 能写哪些名字以 SSH 库实际实现了的为准。不认识的名字报「不认识」；OpenSSH 认得、本版没实现的（CBC、3des、
        group1、group-exchange-sha1、ssh-dss、hmac-md5、umac…）报「本版没有实现」—— 抄来的配置里最常见的就是 CBC，
        用户要知道的是「放开也没用」，而不是「拼错了」。删除项同样要是认得的名字（拼错了什么都删不掉，用户却以为
        已经关了）；删光了、或者只写了前缀，也当场报。
      - 写错时字段下方报错，说清是哪一类、哪个名字，保存 / 连接 / 测试三个按钮灰掉；切到 FTP 这类不走 SSH 的协议时
        这条校验一并撤掉。清单收起时不存，与 X11 关着时不存显示地址同一个理由。
    - **协商失败的提示多一行下一步**：对端提供的算法里有本版实现了、只是没放开的，点名这些算法，并指到这里
      （「允许老算法」或自定义清单）；一个都没有时如实说放开也没用（典型是只剩 CBC 的老设备）。
  - **认证方式「证书」**（`AuthMethod.Certificate=2`，OpenSSH 用户证书）：不另起一套表单，就是私钥认证再加一栏「证书文件」——
    签名始终由私钥出，证书只是 CA 的背书，私钥与口令两栏照用。证书栏排在私钥栏**前面**，因为只能由证书推出私钥，反过来推不出。
    - **选完证书自动补私钥**：用证书栏的「浏览...」选中证书后，若私钥栏还空着，按 ssh-keygen 的命名约定去掉末尾的
      `-cert.pub`（不分大小写）推出私钥路径，该文件确实存在才填进去；私钥栏已有内容、文件名不合约定或推出的文件不存在时
      什么都不做，交回用户自己选。只有经文件选择器选证书时才推，手敲路径不推。登录弹窗（§13.2）与共享凭据编辑框是同一条规则。
      不自动补的话，用户要把同一个目录翻两遍，还容易挑到隔壁那把不匹配的私钥，到连接时只换来一句笼统的 publickey 被拒。
    - **两栏留空都是硬错**：私钥认证的私钥栏可以留空，证书认证不行。证书栏空着，栏下报「请选择证书文件」（证书没有任何默认位置可退）；
      私钥栏空着报「证书认证还需要与之匹配的私钥」；填了路径而文件不在，分别报「找不到该证书文件」/「找不到该私钥文件」。
      这几条是字段下方的提示，不挡保存；连接时缺任一个文件先弹凭据框（§13.2）要齐，连接服务再兜一道，分开报
      「证书认证需要选择证书文件。」与「证书认证需要与证书匹配的私钥文件。」，好让用户知道该补哪一个。
    - 连接时当场核对两样：是不是用户证书（ssh-keygen 带 `-h` 签出的主机证书不能拿来登录），证书里的公钥与私钥是不是一对 ——
      对不上就报出两边的类型与 SHA256 指纹，而不是交给服务端回一句与「CA 不被信任」「主体不匹配」分不开的 Permission denied。
  - **认证方式「Agent」**（`AuthMethod.Agent=3`；枚举落盘的是序号，新值只能加在末尾）：
    用本机 ssh-agent 里的密钥签名，配置里**不存任何凭据**，选中后密码与私钥字段都收起，只留一行
    灰字说明 agent 从哪来。Windows 上是「OpenSSH Authentication Agent」服务的命名管道；
    `SSH_AUTH_SOCK` 只在它本身就是 `\\.\pipe\…` 时才采用（1Password、KeePassXC 会这样配），
    指向 Git Bash / WSL 的 Unix 套接字则忽略 —— 那是另一套 agent，连不上。
    - agent 里有几把钥就逐把试（先探询再签名，不为服务端不认的钥去触发 agent 的确认弹窗）。
    - agent 没在运行时 **3 秒**内就报「连不上本机 ssh-agent」并给出 `Start-Service ssh-agent` 的提示 ——
      不带超时的命名管道连接会一直等到管道出现，用户看到的只会是转圈转到整条连接超时。
      agent 里一把钥都没有也单独说清楚（「请先 ssh-add」），而不是笼统的「认证方法已用尽」。
    - **只有显式选了它才会去碰 agent**；其余认证方式一律不做隐式回退。
  - **Tailscale SSH**（`AuthMethod.Tailscale=4`）：复用系统已登录的 Tailscale 网络，地址填 MagicDNS 名或 tailnet IP、通常端口 22，并填写远端系统用户名。主机指纹、代理与跳板策略照常执行；不准备 SSH 密码、私钥、证书、Agent 或键盘交互凭据。切换/保存/导入时清掉旧秘密、共享引用与「记住密码」，不能从隐藏的共享凭据补用户名，也不能保存为共享条目。
    - 外部 Tailscale 共享条目在登录重试中明确显示不支持，不继承它的用户名或认证方式，也不回写该条目；用户仍可显式选择 Tailscale SSH 并使用自己填写的系统用户名。
    - `accept` / `check` 是服务端授权策略，不是客户端配置。每次实际握手重新采用服务端应答，同一配置、同一进程可随管理面板切换；不缓存批准结果、checkPeriod 或链接，不调用管理面板 API。
    - 无验证挑战时直接继续（包括有效 checkPeriod）；USERAUTH_BANNER 带合法官方 HTTPS 验证链接时，按实际认证跳显示一个 owned 非模态等待窗。只有用户点击「打开浏览器」才打开；链接可选择/复制，显示与更新不等待窗口关闭，不提供「我已验证」按钮。链接框显示的就是打开 / 复制的那一串完整 `AbsoluteUri`（转义后的原样，不是解码过的版本）；下方一行警示色提示「批准前请确认：打开的页面是在请你批准对这台服务器的 SSH 访问。如果页面要求登录，或要把新设备、新机器加入 tailnet，请不要批准，并取消本次连接。」—— 设备登录链接与 SSH 验证链接同在 `login.tailscale.com/a/` 下，链接本身分不出来。
    - **等待期限**：这一跳不用库的固定认证计时，由 `TailscaleAuthDeadline` 管。主机密钥裁决结束后才起算 **2 分钟**守卫期（看指纹的时间不算），服务端一声不吭时照旧尽快失败；收到第一条合法验证链接时放宽到 **30 分钟**（与服务端等用户批准的时长相当，SSO + 多因素也来得及），只放宽一次，之后的新链接沿用同一截止时刻。等待窗写明「最长等待 N 分钟；到 HH:mm 服务器仍未批准，本次连接会自动取消。」
    - 同一次等待中的新链接更新原窗口；SUCCESS 即使没有点击浏览器也继续原连接并收窗。取消/Esc/关闭只取消当前尝试，拒绝/超时显示当前跳的安全原因，不回退目标密码。链接在普通横幅、日志、异常链、历史与配置中脱敏/不保存。等待窗只拦用户直接关它（改走取消），不拦主窗口的关闭：点一次主窗口的关闭键就能关掉，等待窗随之关闭并取消本次认证；主窗口自己拦下了关闭（最小化到托盘、关闭前确认）时验证照常等。
    - 服务端以「说明横幅 + DISCONNECT」结束认证时按**拒绝**报，失败消息后附「服务器说明：…」（去掉全部链接、净化控制字符、压成一行、最多 300 字符）；验证链接之前的横幅（法律声明之类）不算理由。
    - 只有出现过验证链接、或服务端明确拒绝时，才暂停终端和隧道后台恢复，已排队的程序启动隧道任务也遵守暂停；显式手动重连/启动仍允许，成功后解除。认证途中连接被重置、没等到验证链接就超时这类临时失败与其他认证方式一样照常退避重试，首次连接留在失败覆盖层，不弹凭据框。
    - 认证方式是密码 / 私钥 / 证书 / Agent 的配置连上 check 模式的节点：一认出横幅里的验证链接就立即失败，提示「该主机要求 Tailscale SSH 浏览器验证。请把会话的认证方式改为 Tailscale SSH 后重新连接。」，密码不会发出，也不再干等 2 分钟拿一句笼统的认证超时；这种失败同样暂停后台重连。
    - 连接诊断对 Tailscale 配置只要求远端用户名：有用户名就跑认证测试（check 模式照常弹等待窗），缺了就跳过认证测试并提示到编辑窗口填写；认证失败时给 Tailscale 专属建议（本机已登录 Tailscale、远端用户名正确、tailnet 的 SSH 策略允许这个用户），不再叫人去保存凭据或核对密码。
    - 已有 SSH/SFTP/隧道是否保留由服务器决定；单纯切换是否就地释放等待/终止已有连接不作保证。权限撤销与真实策略传播需专用节点验收；协议回归不是实际 Tailscale 策略验收。
  - **FTP 的「高级」页：「默认打开路径」**（`FtpSettings.InitialRemotePath`，
    只在协议栏选中 `FTP` 时出现）。连上后远程面板直接打开该目录，而不是登录工作目录——
    上传目标常年是同一个 `/var/www/html` 或 `/pub/incoming`，而 FTP 服务器给的登录目录
    往往就是根，每连一次手点四五层是纯粹的重复劳动。
    - **它是候选路径的第一位，不是硬性要求**：进不去（打错字、目录被删、账号被 chroot）
      就依次回退到登录工作目录与根目录，与家目录进不去时回退根目录是同一条纪律——
      配错一个路径不该把用户堵在一张报错的空白页上。
    - **归一化在 `FtpSettings` 的 setter 上**（去首尾空白、反斜杠转正斜杠、补前导 `/`、
      去尾部 `/`、空串与纯 `/` 归 null），因此界面、导入器与手改的配置文件共用同一套规则：
      用户会照 Windows 的习惯敲 `\pub`，也会粘一个带尾斜杠的路径进来，而 FTP 的 `CWD`
      对这些写法并不一律宽容。
    - 落在 `FtpSettings` 而不是 `SessionProfile` 的平铺字段上：后者全仓是逐字段手写拷贝，
      新增一个就要四处同步；协议专属设置进各自的可空嵌套对象，只需配套改 `Clone()`。
      SSH / SFTP 仍走登录家目录，插件协议（S3…）自己在描述符里声明字段。
- **反馈条**：测试 / 保存的结论（成功一行强调色；失败是错误原文 + 复制按钮）钉在页脚上方、表单滚动区之外——
  用户按下「测试」时眼睛盯着页脚，结论不能落在滚动区里看不见的地方。
- **页脚**：左=连接目标预览（等宽 11px `text-tertiary`，前面是协议图标）：SSH 是 `user@host:port`，
  SFTP / FTP 带 `sftp://` / `ftp://` / `ftps://`（显式、隐式 FTPS 都算 `ftps`），IPv6 字面量加方括号，
  匿名 FTP 与不带凭据的插件协议不写用户名，声明 `NoEndpoint` 的协议不写端口；主机为空时整块收起。随输入实时更新，
  填完一眼就能核对要连的是哪。右=`测试` / `保存`（描边）/ `连接`（强调药丸，DESIGN.md §5.1），同高 28。

### 13.2 密码验证弹窗（两步式）

- **第 1 步（`oNZIM`，窗口 520 DIP）**：输入用户名，展示目标与已知主机指纹；`取消`/`下一步`。
- **第 2 步（`twD13`）**：全宽四分段「密码 / 证书 / 密钥 / Tailscale SSH」与对应材料；`上一步`/`登录`。UI 索引显式映射枚举；Tailscale 只要求用户名，不索取秘密、不记住密码或回写共享条目。证书段要证书与私钥两个文件都填了「登录」才可点，选证书时同样按 `-cert.pub` 自动补私钥（§13.1「认证方式「证书」」）。FTP 与插件协议只认密码，整条分段不显示、直接是密码框（别的段对它们没有意义，选了只会改掉本次的认证方式、把密码清空，登录时发出去的是空密码）。动态码框与主机指纹裁决是另外的交互。
- **动态码框（keyboard-interactive，2026-09-29 起，`KeyboardInteractivePromptDialog`）**：只放行 keyboard-interactive 的
  两步验证服务器（PAM + TOTP、Duo、堡垒机 MFA）问验证码时弹出。
  - **何时弹**：单条不回显、看起来是口令的提示（英中日韩的「密码」字样，且不带验证码 / OTP / token 之类字样 ——
    那要的往往是「口令 + 动态码」拼起来的串）用已存的密码**代答一次**，不弹框；再问一遍口令（改密码流程、或刚才那个
    不对）就交给用户。其余一律弹框。纯展示的一轮（服务端只发说明、没有提示）不弹，说明攒进下一个框里。
  - **私钥 / 证书 / SSH Agent 不回退到口令**：单纯的口令提示答空串让服务端拒掉，只有验证码之类才弹框 —— 这是
    `AuthenticationMethods publickey,keyboard-interactive`（钥 + 动态码）的第二步；钥被拒之后冒出一个密码框，
    与「只用用户选的那一种认证方式」相悖。
  - **框的样子**：标题取服务端给的名字，没有就是「两步验证」；第一行是连接目标（`用户@主机:端口`，几条会话同时要码时
    分得清是哪台），下面是服务端的说明与每条提示一个输入框，不回显的（`echo = false`）遮住；打开即聚焦第一个输入框。
    对端文字先去掉控制字符与双向文本控制符、统一换行、限长再上界面。同一时刻只弹一个。
  - **取消 = 不连了**：不报错、不再弹凭据框。首连撤掉那个标签；重连按用户主动断开处理（不然自动重连过几秒又弹
    同一个框）；SFTP 文档连接撤掉占位。关掉正在连的标签、认证超时时框当场收起，仍按原来的取消 / 超时处理。
  - **「修改密码」框（2026-10-05 起）**：密码认证时服务端要求先改密码（密码过期，`PASSWD_CHANGEREQ`）就用同一个框问：
    标题「修改密码」，说明是「服务器要求先修改密码才能登录。保存着的密码不会随之自动更新。」加服务端的原话（清洗过），
    两条不回显的输入「新密码」「再输一次新密码」。两遍对不上或空着不交出去，说明换成「两次输入的新密码不一致或为空」再问
    —— 协议里没有确认这一步，输错的会直接成为账户密码；服务端不接受上一次的新密码时说明换成「请换一个」（最多问 3 次）。
    取消同上，报「已取消修改密码」。改成之后连接里保存的旧密码就过时了：下次被拒时走凭据框重输、存回。
    私钥 / 证书 / Agent 认证不会出现这个框；没有弹框服务时不改，报「服务器要求先修改密码……密码没有改成」。
- **引用共享凭据的连接（#550，2026-10-03 起）**：这类连接**从不先弹**凭据框——用户名与认证材料都由凭据提供；
  凭据取不到（被删了、在本机没有密码）或被服务器拒绝时，才退回凭据框，并在信息条下方加一条说明
  （`VelaBgActive` 底 + `triangle-alert` 图标 + `text-secondary` 文字）：
  - **被拒**：「使用共享凭据「X」登录被拒绝。如果刚改过密码……」；**不完整**：凭据在本机缺用户名、密码或密钥
    （云同步没设端到端口令时拉来的凭据就是这样）；**已不存在**：本次输入只用于这一次，要长期保存请编辑连接改选来源。
    本次手输的又被拒时不再复述原因。
  - 第 2 步多一个勾选框「同时更新共享凭据「X」（N 条连接在用）」：勾上就把这次输入存回凭据，所有引用它的连接
    下次连接一起换上——这是「改完服务器密码只输一次」的那一下。**不完整时默认勾、被拒时默认不勾**（可能只是这一台密码不同，
    勾错的代价是另外几十台一起连不上）；凭据已不存在时不出现。
  - 「记住密码」与 AES 徽标不显示：引用凭据的连接自己不存密码，要长期保存就存回凭据。
  - 用户名预填连接自己的，没有就填凭据里的；一直跟着凭据走的连接，输入与凭据相同（或已存回凭据）时不往连接上写，
    免得连上之后存回去就从「跟着凭据走」变成了覆盖。
  - **凭据框交回的是副本**（所有连接都是，不只是引用凭据的）：传进来的那一份是会话树、命令面板缓存里的，就地改的话，
    没让记住的密码会跟着拖动分组、复制配置之类的保存落盘。失败卡片上的「重新连接」用最近一次尝试的那份副本，
    所以重试不必再输一遍。
  - 跳板那几跳的凭据取不到时**不**弹框（框问的是目标机的凭据），直接以「跳板 X：原因」的连接错误结束。
- **主机指纹确认**：首次连接未知主机、或已记录的指纹发生变更 → 弹「主机信任」确认（指纹 + 接受并保存/仅本次/拒绝；变更时并排摆出 known_hosts 里的旧指纹），关联 §15 主机信任中心。变更默认走这个框而不是直接拒（#476），要严格 fail-closed 的在安全审计页打开「指纹变更时阻断并告警」。
  **自动重连不弹这个框**（终端标签的倒计时重连、睡眠唤醒后的批量重连、隧道的自动重拨）：这时多半没有人在屏幕前，
  弹出来要么叠成一摞没人点的模态框、让重连一直挂着，要么被随手点掉 —— 都违背让人核对指纹的初衷。本该弹框问的一律直接拒绝，
  断开提示写明「已停止自动重连，请手动重新连接核对指纹」，并照样记一条安全告警（审计日志「拒绝了主机指纹」）；跳板链上每一跳同样如此。
  不问的那两条默认不受影响：关着「首次连接确认」时没见过的主机照旧按 TOFU 记下，开着「变更即阻断」照旧阻断。
  凭据缺失时的登录框、动态码框不在此列，照旧弹。
  **一台主机的每种密钥类型各记一条**（服务端常常同时有 RSA、ECDSA、Ed25519 几把）：与记着的任一把相同就放行；接受一把新类型的钥是**添一条**，不覆盖原来那一把，
  之后谈成哪一种都认；同一种类型换了钥才替换。变更框摆的旧指纹是同一种类型的那一把，没有这种类型的就摆最近见过的那一把。
  建连时把记着的类型排到主机密钥算法的最前面，正常的服务端谈成的就是已记下的那一种。
  **主机密钥轮换开着**（OpenSSH 的 `UpdateHostKeys` 默认也开）：连上一台已经永久信任过的主机之后，服务端证明它还持有的别的主机密钥按类型补记为受信，
  并发一条安全告警（「已补记为受信」）—— 运维加了一把 Ed25519、或者轮换掉老的 RSA 钥之后，用户不会再看到「指纹已变更」。服务端不再出示的旧钥按类型从信任库删掉，同样发一条安全告警（「已从受信记录里删掉」）—— 一种类型的记录全都对得上要删的指纹才删那一种；「仅本次信任」的不做。「已信任主机」列表每种类型一行，删的是那一行的那一种。
  〔历史〕曾经每个 host:port 只记一把：服务端多一把别的类型的钥、或者改了这条连接的主机密钥算法，就报「指纹已变更」；接受之后覆盖掉原来那一把，换回去时再报一次。
  选了「接受并保存」而信任库写不进去时，**本次连接照常进行**，本次运行内不再询问这把指纹，并发一条安全告警（审计日志记「主机指纹未能保存」）——
  不说一声的话，用户重启之后又被问一遍，不会知道为什么。

**连接状态机**：`空闲 → 连接中(黄) → 认证 → 已连接(绿)` / 任一步失败 `→ 断开(红)` 并给出原因与重试。

关于页的「更新日志」打开应用内模态窗口，按本机安装版本选择日志：**先读取最新正式版**的 `releases/latest/download/latest.json`，与本机版本比较；有更高的正式版时展示该正式版日志和「可用更新」徽标，否则展示本机版本日志和「当前版本」徽标。没有更高正式版且最新正式版恰好就是本机版本时复用本次结果；需要展示本机日志而不能复用时，才按本机版本读取 `releases/download/<tag>/latest.json`，本机版本可以是预发布版。这不是先展示当前版再并行查询更新，也不是历史版本选择器。指定版本只在 404 时尝试有 / 无 `v` 前缀及三段版本号规范化的有限标签变体，不枚举发布列表；清单标签必须与请求标签及预期版本一致。最新正式版发现失败时仍尝试读取本机版本，并单独提示「检查可用正式版失败」及提供重试，不能把失败说成「没有更新」；本机版本无法解析时明确提示无法识别。此窗口的正式版发现不读取或修改更新通道设置，关于页「检查更新」和启动检查原有的 preview 逻辑不变。

日志显示根级 `tag` 和 `releaseNotes` 中的完整发布正文。请求走附件下载客户端并流式解析，不查询发布列表，也不在失败时回退匿名 Release API；各 URL 的结果在进程内缓存 5 分钟，过期后在服务端提供 ETag 时用 `If-None-Match` 复验，304 沿用缓存。商店版也能查看；仅打开窗口不自动下载或安装。窗口头部显示版本标签、发布日期及上述版本徽标；保留 `ReleaseNotes_Latest` 资源键但其含义改为「可用更新」（英文 `Update available`），未启用版本选择的兼容构造入口暂时也沿用该标签。底部的「在 GitHub 查看」打开清单中该版本的 `releaseNotes.htmlUrl`（只放行绝对 HTTPS 地址，拿不到时按钮不可点）。

**更新动作绑定正在展示的版本**：只有展示更高的正式版且同一响应包含当前平台可用的安装清单快照时，才提供更新动作；日志可读但安装资产缺失或无效时，保留日志，不提供不完整的更新目标。Windows / macOS 的可写安装目录显示「立即更新」，按展示快照中的 tag、版本、资产 URL 与校验值下载，不重新发现 latest、不被后台检查切换成另一个版本，也不更改 preview 设置。下载完成后只进入「已准备好」状态，**用户再点重启更新才安装**；「已准备好」只认手里真有、通过校验的包，没有选定目标的下载报失败而不是报就绪。换版前按就绪时的校验值重新核对已下载的包，被删或被改写就删掉它、退出「已准备好」并报失败，下一次检查更新或立即更新重新下载；文件被占用、解包失败等其余失败仍保持「已准备好」，可直接重试。关闭日志窗口不会取消已开始的下载；窗内明确提示「关闭此窗口后下载仍会继续，完成后可在关于页重启更新。」，关于页承接同一任务的进度、失败与重启入口，不另开下载。已有更新在进行或已准备好时不覆盖它；同目标复用状态，不同目标明确提示冲突并引导到关于页。Linux 或安装目录不可写时，动作改为「前往发布页」，打开**所选 tag 的发布页**供手动下载安装，不跳通用发布列表或新的 latest；Microsoft Store 版仍由商店管理，不提供应用内下载安装动作。进度、速率与停滞处理见[消息中心与资讯源](消息中心与资讯源.md)。

正文渲染 Markdown 标题、段落、列表、强调与行内代码，以及 GitHub 风格的自动链接（自动生成的发布说明里 PR 与 Full Changelog 都是裸 URL）、管道表格、删除线与任务列表，可跨段选择复制并垂直滚动；链接（含自动链接）仅在用户点击时打开绝对 HTTPS 地址，其余协议降为纯文本。全部图片节点在生成控件前移除并保留替代文字，HTTP、本地文件、data 与资源图片均不加载，原始 HTML 不执行。正文、链接与代码区配色及字号跟随应用主题和字体设置。点击后立即展示加载状态；本机 tag 没有清单附件（404）时提示「暂无当前版本的更新日志，可能是本地构建或该版本尚未附带日志清单。」，不展示别的版本冒充当前版，也不回退匿名 API。它与清单存在但正文为空分开处理，旧清单缺少 `releaseNotes` 时保留版本标签并显示正文为空；网络失败或超时在窗内提示并提供「重试」；下载服务回 403 / 429 时改为提示「GitHub 暂时限制了请求次数，请稍后再试。」，不再让用户去查网络。关闭按钮或 `Esc` 关闭窗口并取消本次读取，重复点击不会叠开窗口，也不会影响进行中的更新下载。

更新日志的发布契约：`latest.json` 保留原有 `version`、`tag`、`assets`，追加可选 `releaseNotes` 对象，其中 `body` 为完整 Markdown 字符串，`publishedAt` 为 ISO 8601 发布时间或 null，`htmlUrl` 为发布页地址或 null，日志标签复用根级 `tag`。CI 在认证后从 Release 读取这些字段，生成清单后再计算 `SHA256SUMS.txt`；客户端不需要 GitHub 登录或 Token。编辑已发布 Release 时仅同步日志字段及清单的校验和，不重建安装包；手动运行发布工作流时可启用 `notes_only` 为已有清单补齐日志，默认仍执行完整发布。只缺原清单而 `SHA256SUMS.txt` 还在时（例如上次同步断在删旧附件与传新附件之间），按校验表里的哈希与 Release 现存附件的大小重建 `latest.json`，任一平台缺产物或校验记录仍然失败；缺校验表时同步失败，须先完成完整发布；两份附件都不在（多半是构建还在跑，它的附加任务会带上最新正文）时打 notice 后跳过。同一标签的发布与同步串行，但两份附件上传不是原子操作，失败后可重跑恢复。旧客户端忽略新增字段，本地打包默认生成空正文及 null 日期、链接，不新增联网要求。关于页「检查更新」及预发布通道保持原有发现逻辑；日志窗口的正式版发现与固定目标下载不替换它们。工作流须进入默认分支，并为要查看的最新正式版或本机历史 tag 生成 / 补齐清单附件后，新日志字段才可用；**历史附件是前置条件**，`notes_only` 只能按现存的校验表与安装包补回清单，不能凭空创建缺失的校验表或安装包。缺附件时如实提示无法取得，不回退匿名 API；下载服务自身的限流、网络故障及缓存传播仍可能影响读取。

关于页的「导出诊断包…」（2026-10-19 起）把诊断日志目录（`~/.velashell/logs`）里的 `*.log` 与崩溃记录（从新到旧，原文合计不超过 32 MB）、版本与平台概况、已发现插件的 id / 版本 / 状态 / 运行方式打成一个 zip，存到用户在另存为对话框里选的位置，**不上传、不发任何网络请求**。写入前逐个文件遮盖：已保存连接、最近连接与共享凭据里的主机和登录名换成 `<host-N>` / `<user-N>`（同一个值在整个包里换成同一个占位符；`root`、`ubuntu` 这类常见登录名与两个字符以内的值不换），本机主目录换成 `~`，本机登录名、机器名、其它 IPv4（回环除外）、邮箱，以及 `password=` / `token:` / `Bearer …` 这类片段的值也都遮盖。设置、连接配置与任何凭据都不收。包里的 `README.txt` 用界面语言说明这些，并列出各类替换次数。按钮下方一行显示保存位置与收进的日志份数，失败时显示原因。诊断日志里，每条 SSH 连接（含跳板链上的每一跳）结束时记一行英文：目标、连了多久、为什么结束（本端关闭记 `closed locally`；否则是库给的原因与阶段，收到对端 DISCONNECT 时带原因码与对端原话 —— 去掉控制字符并截断，永远只占一行）。

### 14.2 快捷命令的变量占位（2026-09-29）

快捷命令（侧栏的快捷命令面板、设置 → 代码片段）的命令正文里可以写占位，发送前询问填什么。
`kubectl logs -f <pod>`、`journalctl -u <服务> -n 200` 这类每次只差一两个参数的命令，不必再存成缺参数的半截。

- **写法**：`{{名字}}` 或 `{{名字=默认值}}`。同名写多处只问一次，取第一个非空的默认值；没填的取默认值（没有默认值就是
  空串）。快捷命令的数据结构不变，云同步与导入导出照旧。
- **哪些双花括号不算占位**：运维命令里本来就有大量 `{{…}}`（`docker inspect -f '{{.State.Status}}'`、kubectl 的
  go-template、Ansible 的 `{{ inventory_hostname }}`），所以占位收得很窄：名字只能以字母或下划线开头、由字母数字下划线
  连字符组成，**花括号里不许有空白**（`.` 开头的、带空格的都不算）；Go 模板的无参动作 `end` / `else` / `break` /
  `continue` 不算；默认值里不许有花括号与换行。不是占位的原样发出；一个占位都没有的命令照旧直接发送，不弹框。
- **询问框**：每个变量一行（名字 + 预填了默认值的输入框，读屏按变量名念），下方「将发送：」实时预览替换后的整条命令；
  打开即聚焦第一个输入框，Enter 发送、Esc 取消。取消则一个字节都不发。
- **值里的换行换成空格**：快捷命令只发正文、不带回车，值里夹一个换行就等于替用户按了回车。
- 弹框期间目标标签可能已经断开：发送时按当下的标签再挑一遍，只发给仍连着的。
- 设置 → 代码片段的新建 / 编辑区，命令输入框下有一行写法说明。
- 终端里的命令补全把快捷命令当候选时，插入的仍是含占位的原文 —— 补全是按已键入的前缀续写的，换成替换后的文本就对不上了。

### 14.3 取色器（2026-10-01）

要人挑颜色的地方一律是取色器，不再是手敲 `#RRGGBB` 的输入框：外观页的强调色与终端前景 / 背景 / 光标 / 选区，
以及新建 / 编辑连接「终端」页的标签颜色（§13.1）。ANSI 16 色在外观页上仍是只读色块，不在此列。

- **字段**长得像输入框（`bg-input`、1px 描边、圆角 4、至少 32 高）：14px 色块 + 等宽色值 + 下拉箭头。
  没有颜色时是一个空框加一行说明（强调色写「跟随主题」，标签颜色写「自动配色」），说明用弱一档的前景与界面字体。
  浮层开着或键盘聚焦时描边转强调色。
- **浮层**（236 宽，全局浮层外框）自上而下：饱和度 / 明度面板（148 高）、色相条、新旧对比色块（左半是打开时的颜色）
  + 十六进制框、色板、清除按钮。
  - 面板与色相条可拖、可点，也可用方向键：面板左右调饱和度、上下调明度，每次 1%；色相条每次 1 度，Home / End 到两端；
    按住 Shift 都是十倍步长。
  - 十六进制框留给要精确值的人（从设计稿、别的终端配置里抄一个色号）：回车或离开即生效；认不出的色值**不写进设置**，
    框里退回当前颜色 —— 终端四色认不出会整套落回出厂色。只认十六进制，不认颜色名。
  - 色板：终端四色给**当前配色方案的 ANSI 16 色**（从方案自己的颜色里挑，改出来的前景、选区与方案协调），
    其余用**当前主题的色板**（`VelaAccentPalette0..7`，与标签的自动配色同一家族）。与当前颜色相同的那一格加粗描边；
    悬停提示与读屏名字都是色值本身。
  - 清除按钮只在值允许为空时出现：标签颜色的「自动配色」。强调色清回跟随走行首的「跟随主题」按钮，浮层里不重复给；
    终端四色必填，没有这一键。
- **松手才写回**：拖动过程中只刷浮层里的预览；松手、按一次方向键、点色板、十六进制框回车或失焦时才写回设置。
  强调色一改就要重派生全套主题令牌，终端颜色一改就要重刷所有终端，跟着鼠标每像素写一次是白费。
- 写出去一律是大写 `#RRGGBB`，强调色、终端四色、标签颜色三处的解析都认；读进来还认 `#RGB` 与八位
  （手改过的配置也能回显）。
- 状态按 H / S / V 保存：在灰色上拖饱和度时色相不会跳回红色，选一个灰色色板时色相条也不乱跑。

### 14.4 快捷命令：内置命令可改可删、多行命令、拖动排序（2026-10-03，joesdu/VelaShell#555）

适用于设置 → 代码片段与侧栏的快捷命令面板（两处共用同一份数据，在设置页排好的顺序侧栏直接跟着变）。

**内置命令**

- 内置命令与自己建的命令一样有「编辑」「删除」。内置目录本身不变，改动叠在上面一层：删掉的记成「不再显示」，
  改过的存成一条同标识的自定义命令、顶替目录里的那一条。没动过的内置命令仍跟着界面语言换描述，新版本新增的内置命令照常出现。
- 删除一条改过的内置命令就是删掉，不会退回原样。打开编辑框什么都没改就保存，它仍是原样的内置命令。
- 改过（含挪到别的分组）的行多一个「恢复默认」：换回目录里的原样，回到原来的分组与位置。
- 列表上方的「恢复内置命令」只在删过或改过内置命令时出现，先确认：删掉的回来、改过的还原，自己建的命令不受影响。

**多行命令**

- 命令输入框可以回车换行（自动折行、等宽字体，超过约十行在框内滚动）。保存时换行统一成 `\n`，首尾空白去掉。
- 侧栏只显示第一行，后面跟「+N 行」；整条命令在悬停提示里。
- 发送时整段走括号粘贴（bracketed paste）：远端开着括号粘贴（bash 5.1 起默认、zsh、fish）时，shell 把整段放进命令行，
  等用户按回车，不会逐行执行。目标终端里有没开括号粘贴的（sh、老版本 bash、网络设备命令行等），那边每一行都会被立即执行，
  所以先弹「发送多行命令」确认框（预览前五行）；确认开关沿用「设置 → 终端 → 粘贴时确认多行内容」，关掉它就不问。
- 只有末尾带换行的命令不算多行，照旧按键入发送。
- 多行命令不进终端里的命令补全：补全是按已键入的前缀续写一行，接受一条多行候选等于替用户敲了回车。
- 与变量占位（§14.2）可以同时用：先问变量，替换后的整段再按上面的规则发送。
- 快捷命令**不会**在点击后自动执行（维护者决定，#555）：很多命令要先在终端里改一改参数，发送后自己按回车本身就是一道确认。

**拖动排序**（设置 → 代码片段）

- 分组头与每一行最左侧有六点手柄，按住拖动；移动超过 5px 才算拖。拖动中的那一行 / 那一组变淡，落点处画一条强调色插入线
  （命令的插入线从手柄之后开始，分组的贯穿整行）。
- 落点取离指针最近的插入位置：命令可以插到任意两行之间、组头下方（= 这一组的最前面），也可以拖进别的分组；
  收起的分组拖到它的组头上就是放进这一组的最前面。内置命令拖进别的分组算作「改过」，可以恢复默认。
- 分组插在分组之间。「未分组」固定排在最后：它没有手柄，也不能有分组排到它后面。
- 落回原处、拖到离列表 40px 以外再松手，都等于取消。拖到设置页滚动区的上下边缘时自动滚动，越贴边越快。
- 只能用鼠标排序，目前没有键盘替代。侧栏面板不提供拖动（那里点一下就是发送）。

**同步与旧版本**：删掉的内置命令、分组的组内顺序与内置分组之间的先后都随云同步走，只加字段、不抬版本。
没升级的设备读到时忽略这些字段；它再推一次，删掉的内置命令会重新出现、顺序回到默认，自己写的命令一条不丢
（改过的内置命令在旧版本里与原样那条并排显示）。

### 14.5 启动画面（2026-10-10）

**为什么要有**：冷启动实测首帧约 8 秒（Avalonia 平台初始化加 XAML 加载 3 秒多，大头是 Defender 对未签名程序集的首次扫描），
这段时间屏幕上什么都没有，用户以为程序打不开。Windows 只给一个几秒就消失的忙碌光标；macOS 的 Dock 弹跳、Linux 桌面的启动通知
已经说了「正在打开」，所以启动画面只在 Windows 上有。

**行为**

- 进程拿到单实例锁后立即显示，在 `Main` 之后约 50 ms（热启动时离进程创建约 0.2 s）。第二次双击只是把已有窗口唤到前台，不闪启动画面。
- 主窗口画完第一帧时淡出（160 ms）。启动中途失败时先收掉启动画面再弹错误框，免得错误框被压在下面；第一帧 60 秒还没来，它自己收掉。
- 不抢焦点：显示时不激活，启动期间用户切去别的窗口不会被拽回来；有任务栏按钮，鼠标移上去是「后台忙」光标。放在鼠标所在那块屏幕的正中。
- 600 × 340 的卡片，圆角 8，自己画投影，淡入 120 ms。跟随设置里的主题、强调色与界面语言。
- 进度来自真实的启动打点，分五段：运行时 → 数据库 → 界面框架 → 会话与设置 → 主窗口。进行中的一段按 `1 − e^(−t/τ)` 估计、封顶 0.95，
  不会出现进度走满了画面还停着的情况。

**五套样式**（设置 → 外观 → 窗口 → 启动画面；出厂为经典）

| 样式 | 画面 |
| --- | --- |
| 经典 | 最接近 Visual Studio：左上大 Logo 与产品名，左下当前阶段，底部一排强调色小圆点从左滑到右（两头快、中段慢） |
| 终端开机 | 迷你终端：提示符敲下 `velashell`，逐行打出每个阶段与真实耗时（`[ ok ]` 与转圈符号），第二行是 SSH 协议的版本标识串；底边细线是总进度。卡住时一眼看出停在哪一步 |
| 船帆座 | 产品名里的 Vela 是南天的船帆座：星点闪烁，每推进一段点亮一颗主星、连上一段星线，主窗口出来时星座刚好闭合；亮起的星旁标拜耳命名 |
| 提示符 | Logo 里的 `>_` 把产品名一个字一个字敲出来；下方一行状态加五格方块进度，进行中的那格呼吸闪烁 |
| 看板娘 | 抱笔记本的 Q 版看板娘（原图，正片叠底进浅色底板），气泡里用她的口吻说当前阶段，五个猫爪印逐个点亮。这是 DESIGN.md「界面不放插画」的唯一例外：需要用户自己选 |
| 不显示 | — |

**预览**：下拉下方是实时预览，与真正的启动画面是同一份绘制代码，按「一般」速度循环播放；主题与强调色取设置页里正在编辑的值（还没保存也算）。
选「不显示」时收起。改了**下次启动生效**。

**实现约束**（改动时勿破坏）

- 不能用 Avalonia 窗口：它最早也只能在 Avalonia 初始化之后出现。启动画面是原生分层窗口，在自己的线程上跑消息循环，画面由 SkiaSharp 画进 DIB。
- 主题、强调色、语言与样式从 `~/.velashell/startup.appearance` 读（那时数据库还没开），见[设置审计](settings-audit.md)第十三批。
- 字体用系统字体（Segoe UI；Cascadia Mono，没有时 Consolas）：应用内置的 Inter 与 Cascadia Mono 是 Avalonia 资源，那时读不到。
  中日韩文字与盲文点阵逐字回退到系统里有这个字的字体。
- 诊断日志的启动时间线里多一个 `SplashShown` 点；启动画面关掉时记一行
  `[Splash] style=… scale=… open=… ms frames=… render avg=… ms max=… ms`，用来判断画面本身有没有拖慢启动。
- `VELASHELL_NO_SPLASH=1` 关掉启动画面。

## 15. 高级功能面板（大尺寸独立面板）

以标签页或独立浮窗形式打开，均可从命令面板进入：

- **运维编排中心（`bR5c4`，920×760）**：头部 + 内容区 + 结果面板。批量在多主机执行脚本/剧本，选择目标组 → 编排步骤 → 执行 → 实时结果汇总（成功/失败/输出）。
- **主机信任中心（`gPWeC`）**：策略行（信任策略：严格/首次信任/宽松）+ 主机指纹表（主机、指纹、算法、首次时间、状态、操作删除/重置）。✅ **已以简化形态落地（2026-07-12）**：设置 → 安全审计 内的「主机信任策略」（首次确认三选项 / 变更阻断）+「已信任主机」列表（查看/删除/截图防泄露地址脱敏）；独立大面板暂不单独实现。
- **会话录制与回放（`NceE6`）**：录制列表 + 播放器（时间轴、倍速、搜索），asciinema 式回放，可导出。✅ **已实现（2026-07-12）**：`RecordingPlayerView` 独立窗口，入口在 设置 → 安全审计 → 回放中心；左栏录制列表（名称/时间/时长/大小、删除），右栏只读终端 + 时间轴 seek + 1x/2x/4x 倍速 + 跳过空闲片段；标题栏的动作图标组（§2）：导出录制（asciicast v2 `.cast`）、刷新、清理（删除录制并真正释放磁盘空间）与「自动录制」开关（= `Security.RecordProductionSessions`，开着时图标转强调色）；存储见 架构设计 §4.11（SonnetDB 时序）。设计中的“搜索”暂未实现。
- **审计日志（2026-09-29）**：`AuditLogView` 独立窗口（外框、标题栏与缩放手柄同录制回放），入口在 设置 → 安全审计 → 审计日志 →「查看」。列出 `audit_log` 里的连接成败、主机指纹的裁决、外部拉起登录这几类事件，列为时间、类别、事件、会话、详情：事件翻成人话（连接成功 / 连接失败 / 拒绝了主机指纹 / 仅本次信任 / 接受了变更的指纹 / 外部拉起登录，认不出的原样显示）；会话名按配置 Id 在载入时对照，配置已删的显示 —（详情里的 `用户@主机:端口` 照样看得出是哪台）。连接失败、拒绝与接受了变更的指纹算「异常」，事件名标红。筛选条三者叠加：类别（全部 / 连接 / 安全）、「只看异常」、关键字（事件、类别、会话名、详情，不区分大小写）。一次只载入最近 2000 条，载满时摘要里注明；读库失败把原因写在摘要里。Esc 先清关键字，再关窗口。
  - **保留**：`Security.AuditLogRetentionDays`（默认 180 天，1–3650），审计日志与连接历史（`conn_history`，「最近连接」的底账）共用 —— 连接历史比审计留得久没有意义，留得短又会让审计里的会话在侧栏对不上。只在**启动时**按它清理更早的记录，与会话日志、录制的过期清理同一时机；按时间 `DELETE`，不走录制那套「暂存 → 重建 → 回灌」（进程死在中途会丢掉还在保留期内的记录，审计最不该冒这个险）。
- **连接诊断中心（`RGXg1`，920×640）**：对目标执行 ping / DNS / 端口探测 / 路由跟踪 / SSH 握手分析，输出分步诊断结论与建议。

## 17. 浮层管理与边界规则（交给 Agent 的通用约束）

1. **浮层层级**：设置/新建连接/密码=**模态弹窗**（居中 + 遮罩）；命令面板=**准模态**（遮罩，Esc 关）；文件传输/隧道/资源监控=**非模态悬浮**（无遮罩，可与主界面并存）。
2. **单例性**：命令面板、隧道面板、资源监控面板、文件传输组件各自全局单例；重复触发=聚焦已存在实例而非新建。
3. **屏幕/窗口边界避让**：所有跟随鼠标或锚点的浮层出界时自动翻转方向，始终完整可见。
4. **位置记忆**：文件传输组件、消息中心、隧道面板的拖拽位置持久化。
5. **主题联动**：所有浮层跟随全局 dark/light 主题实时切换。
6. **资源面板 hover 计时**：进入标签名开始计时 400ms，中途移出即取消；移出面板与标签的合并区域后再关闭（防抖 ~150ms），避免"移向面板途中闪灭"。
7. **传输/隧道与会话生命周期**：会话断开时，其隧道置暂停、其传输任务暂停并提示；会话关闭前若有进行中传输，二次确认。
8. **空态**：无会话时终端区显示引导（新建连接/最近连接）；无传输时不渲染传输组件；无隧道时隧道面板显示"暂无隧道 + 新建"。
