# 隧道功能规划（Plan）

> 更新于 2026-10-24。原"待实现"1~4 项与后续三项迭代（断线自动恢复 / 流量统计 / 端口冲突预检）均已落地；
> 2026-10-24 又接上 SSH 库早有的四样（实时速率与当前连接、按隧道限速、远程动态 SOCKS 与放行名单、Unix 域套接字），
> 并让启动时自动建立失败的提示带「重试」。剩余想法见文末。

## 已实现

- 本地转发（-L）、远程转发（-R）、**动态转发（-D / SOCKS5）**、**远程动态 SOCKS（-R 不给目标，2026-10-24）**四种类型，创建时下拉选择（动态转发自动隐藏目标主机/端口输入）
- 远程主机从资源管理器已保存的 SSH 会话中选择（服务端口手动填写）
- 隧道行内操作：停止 / 启动 / 删除（删除活动隧道时先自动停止）
- 表单"取消"清空重置；创建失败错误内联显示
- **隧道配置持久化**：按服务器分文档存入 SonnetDB `tunnels` 集合（docId = profileId，经 `IAppDataStore`）；应用重启后恢复为"已停止"状态，可一键启动（每次运行每台服务器只恢复一次，恢复失败不影响面板）
- **独立承载会话**：隧道生命周期独立于终端标签——未连接时创建/启动隧道会自动建立仅隧道用途的后台连接；该服务器最后一条隧道删除后后台连接自动断开
- **多端同步**：隧道配置随「连接配置」范围纳入 Gist 云同步（plan.md §13.C）

### 计量转发（宿主接管数据面，2026-08-30）

底层库 Tmds.Ssh 把端口转发的搬运整个做在内部，**不暴露任何连接数或字节计数**，
`TunnelInfo.BytesTransferred` 因此长期恒为 0。要出统计只能自己接管数据面，于是
`Infrastructure/Ssh/MeteredPortForwardHandle` 取代了原先直接返回库对象的做法：

| 类型 | 监听端 | 出站 | 备注 |
| --- | --- | --- | --- |
| 本地转发 | 宿主自己的 `TcpListener` | `SshClient.OpenTcpConnectionAsync`（direct-tcpip） | 与库内部同构，无额外跳数 |
| 动态转发 | 宿主自己的 `TcpListener` | SOCKS5 握手协商出目标后同上 | 服务端握手见 `Infrastructure/Ssh/Socks5Negotiation`（RFC 1928，仅 CONNECT + 无认证） |
| 远程转发 | 服务器侧，仍由库开 | 库转发到本机临时计量监听 → 宿主接力到真实本地目标 | 多一次环回拷贝换来同样的统计 |

三条路径收敛到同一个"监听 → 建出站流 → 双向搬运"的循环，沿途累加字节数与连接数。
搬运保留**半关闭语义**（一个方向读到 EOF 就向对端发 EOF：SSH 侧用 `SshDataStream.WriteEof`，
套接字侧用 `Shutdown(Send)`），否则"发完请求就 shutdown 再等响应"的协议会读不到东西。

> 〔后续〕换到 SSH 库 VelaShell.Ssh 之后，上面这套宿主自己的数据面**已经删了**：计量本来就在库里，
> 三种转发由库的 `LocalPortForwarder`（`Start` / `StartDynamic`，含 SOCKS5 服务端）与 `RemotePortForwarder`（`StartAsync`）承担，
> 远程转发不再经本机临时监听接力。宿主只剩薄适配 `Infrastructure/Ssh/LibraryPortForwardHandle`，
> 把库的连接数、字节数（发出与收回相加）与错误事件接到 `IPortForwardHandle` 上。
> 现状见 [`architecture.md`](architecture.md)「端口转发隧道」与 [`ssh/spec/07-forwarding.md`](../ssh/spec/07-forwarding.md)。

### 流量统计（2026-08-30）

- 每条隧道的行内显示 `3 连接 · 1.4 MB`；有正在传输的连接时并发数一并点出（`3 连接（2 在传）· 1.4 MB`）
- 字节数为**上行 + 下行**合计，只统计真正流过转发的业务数据，不含 SSH 协议开销与 SOCKS 握手字节
- 读数由 `ITunnelService.RefreshStatistics()` 从底层句柄同步到 `TunnelInfo`，面板的 5 秒状态时钟调用；
  隧道停止时先取下最后一次读数再释放句柄，因此"已停止"的隧道仍显示它跑过的总量
- 设计稿 fuXS7 预留的说明行即此行

### 断线自动恢复（2026-08-30）

- 新建/编辑表单里的「掉线后自动重连」开关，落到 `TunnelConfig.AutoReconnect`（随配置持久化与云同步；
  旧配置缺该字段时按 `false` 反序列化）。勾选的隧道在列表里带一枚 `自动` 徽标
- **默认关闭**：自动重拨可能触发凭据提示，也可能对着一台真的下线了的服务器反复重试，该由用户按隧道自己决定
- 面板的状态时钟检出后台会话掉线后，为勾选的隧道重拨承载会话并按原配置重建转发；
  掉线检测覆盖**面板持有的每一台**服务器，而不只是当前选中的那台
- 失败按 10s → 30s → 1min → 2min → 5min 退避，避免服务器真的下线时每 5 秒重连一次
- **用户按停过的隧道不会被自动拉起**：`TunnelItemViewModel.StoppedByUser` 记下"这是用户按的停止键"，
  自动恢复放过它。重建出来的是新条目，自然回到可恢复状态

### 端口冲突预检（2026-08-30）

- 创建本地转发/动态转发前比对系统 TCP 监听表，命中即抛 `TunnelPortInUseException`，
  提示"本地端口 27017 已被其它程序占用"，而不是底层套接字那句只有写网络代码的人看得懂的错误
- 判定规则：端口号相同，且任一方绑在"所有接口"上、或两者监听地址相同（不同网卡的同一端口可以并存）
- 远程转发的监听在服务器上，不做本机预检
- 预检与真正的绑定之间的竞态是已知且可接受的：预检负责把最常见的情形讲清楚，真绑不上时底层异常仍会照常抛出
- 探测委托可注入（`TunnelService` 构造的 `isLocalPortInUse` 参数），否则单元测试的结论就要看运行机器上
  恰好有没有数据库在监听 5432

### 实时速率与当前连接（2026-10-24）

- `IPortForwardHandle` 交出两个方向的速率与连接快照，直接取 SSH 库转发器的 `Throughput`（最近三个整秒的平均）与 `Connections`；
  `TunnelService.RefreshStatistics` 把它们与计数一起同步到 `TunnelInfo`，隧道停止时速率清零、连接列表清空（累计字节照旧留着）
- 统计行下多一行速率：运行中 `↑ 12.5 KB/s  ↓ 468.8 KB/s`（↑ 本机送进隧道、↓ 从隧道收回）
- 「› 当前连接 N 条」默认收起，点开逐条列「来源 → 目标」与「已开多久 · ↑ 字节 ↓ 字节」，至多 20 条，其余写「还有 N 条未列出」；
  Unix 套接字上连进来的客户端没有名字，来源写「来源未知」
- **面板开着才每秒刷新**（`TunnelPanelViewModel.IsOpen` 由宿主随面板显隐设置，开着才起 1 秒的流量时钟）；存活检测与自动恢复仍是 5 秒一拍

### 按隧道限速（2026-10-24）

- `TunnelConfig.MaxBytesPerSecond`（null 不限）；表单填「限速 KB/s（每个方向，0 为不限）」，0–1048576、步进 64，配置里存字节 / 秒，
  编辑时不整除的向上取整，不会被悄悄放宽成 0 = 不限
- 两个方向分别限速，这条隧道上的全部连接共用这份额度；设了限速时速率行后面追加「· 限速 512.0 KB/s」，停着时只剩这半句
- 新建、启动、编辑后重建、自动重连、启动时自动建立都经同一条 `CreateTunnelAsync` 带上它，交给库的两种转发参数。
  库在建转发器时定额度，改了要重启隧道才生效 —— 运行中的隧道本来就不能编辑
- 突发不超过一秒的额度（2026-10-25 起）：库把一次读到的大块切成不超过 32 KiB 的段逐段放行（[spec/07 §5.1](../ssh/spec/07-forwarding.md)），
  面板上的速率与连接字节数是平稳往上走的，不会先停几秒再一跳

### 远程动态 SOCKS 与放行名单（2026-10-24）

- 新类型 `TunnelType.RemoteDynamicForward`（追加在枚举末尾：本机库存的是数值，前三个值不动）：服务器上的端口当 SOCKS5 代理，
  远端程序经它让本机替自己去连目标。服务器上的监听地址 / 端口沿用远程转发的 `RemoteHost` / `RemotePort`，`LocalPort` 存 0
- 放行名单 `TunnelConfig.PermitRemoteOpen`，写法同 ssh_config 的 `PermitRemoteOpen` / 库的 `RemoteOpenPolicy`：`主机:端口`，主机可用 `*` `?` 通配，
  端口可 `*`，IPv6 带方括号，空白或逗号隔开；单独一条 `any` 全放，和别的写在一起算写错。按远端给的名字比，不解析
- **没有默认值、不许留空**：这等于把本机变成远端的 SOCKS 代理，放哪些出去要用户明说。表单上空着「创建」点不了、写错一条红字点名；
  服务层（`Core/Tunnels/RemoteOpenRules`）对手改、同步来的空名单与写错的规则同样拒绝，不替用户当成全放或全拒
- 名单外的请求库回 SOCKS「规则不允许」（`0x02`），隧道行记一句本地化提示：远端要连的目标不在放行名单里，已拒绝
- 表单：本地端口栏收起，主机栏叫「服务器监听地址」，勾选框是「只在服务器本机监听（127.0.0.1）」（默认勾）；列表行多一行「放行：…」

### Unix 域套接字转发（2026-10-24）

- 按库支持的组合：**本地转发**两头各自可以是套接字（本机 TCP / 本机套接字 → 服务器 TCP / 服务器套接字，四种都通）；
  **远程转发**只有「两头都是套接字」；动态与远程动态没有套接字写法
- 不新开类型，`TunnelConfig` 多两个可选字段 `LocalSocketPath` / `RemoteSocketPath`（null = 用主机与端口），现有类型的形状不变。
  远程转发只给一头的配置不建，不悄悄退回端口
- 表单：本地 / 远程转发多一个复选框「改用 Unix 域套接字」，勾上出现两栏路径（远程转发两栏必填），填了路径的那头置灰端口、主机与「锁定 127.0.0.1」。
  本机路径要是完整路径、UTF-8 不超过 107 字节（macOS 103），服务器路径要以 `/` 开头
- 本机监听前预检路径：上面已经有文件就不建、**不替用户删**（多半是上次没收拾干净，也可能是别的程序的套接字），与库默认的
  `AllowSocketReplacement = false` 一致；停掉隧道时删掉自己建的套接字文件。Windows 10 1803 起支持 AF_UNIX，套接字文件沿用所在目录的 ACL
- 列表行的路由直接写路径，如「本机监听 127.0.0.1:2375 → 服务器侧目标 /var/run/docker.sock」

### 启动时自动建立失败的提示带「重试」（2026-10-24）

- **连不上服务器** → 重试即重连这台，把这台上勾了自启、还没起来的全部建起来；**一条建不起来**（如端口被占）→ 只重试那一条；再失败照样报、照样带「重试」
- 重试是人点的：主机指纹照常可以弹框问，之前因认证要人处理而暂停自动恢复的服务器也照样再认证；那条在此期间已被用户启动、改过或删掉的，重试什么也不做
- 重试建成了，右下角报一声「隧道「x」（srv）已建立」；自动重连（掉线重建）败在主机指纹 / Tailscale 认证上的提示不带重试 —— 那里要的是用户去面板手动启动、在弹窗里核对
