# 快捷键参考

本表覆盖 VelaShell 中**全部**已绑定的键盘快捷键与鼠标手势,按生效范围分组。

表里写的是**出厂键位**。「全局」「标签与面板」两组(窗格移焦除外)与「终端」组里的搜索、清屏、字号缩放,
可以在设置 → 快捷键里改键或解绑,见[自定义键位](#自定义键位)。

## 维护约定(务必先读)

**本文档不是手抄的清单,而是与代码同源的一份投影。**

- 唯一事实来源是 `src/VelaShell/ViewModels/ShortcutCatalog.cs`。设置 → 快捷键页与本文档都从它取数;
  其中可自定义的那些,出厂表在 `src/VelaShell/Services/ShortcutKeymap.cs` 的 `ShortcutBindings`。
- **后续每新增或修改一个快捷键,都必须同步登记进 `ShortcutCatalog`,并把对应行补进本文档。** 这不是靠自觉:
  - `ShortcutCatalogTests.EveryBinding_AppearsInCatalogExactlyOnce` 要求出厂表里每一条都在目录里恰好出现一次;
    `MainWindowAxaml_HasNoHardcodedKeyBindings` 拦住在 `MainWindow.axaml` 里写死 `KeyBinding`(写死的那一条用户改不掉);
  - `ShortcutCatalogTests.DefaultBindings_DoNotTakeNewTerminalKeys` 拦住新的出厂键位从终端手里抢键(`Ctrl+字母` 是控制字符);
  - `ShortcutCatalogTests.Doc_ListsEveryCatalogEntry` 会拿目录逐条比对本文档的表格,缺行时失败信息里直接给出可粘贴的 Markdown 行;
  - `ShortcutCatalogTests.Catalog_HasNoUnresolvedResourceKeys` 保证每条文案都取到了译文,而不是在界面上显示 `Sc_Xxx` 这样的裸键名。
- 新文案键统一用 `Sc_` 前缀,并且必须**同时补齐五个 `resx`**(`Strings` / `zh-Hans` / `zh-Hant` / `ja` / `ko`),否则 `AllCultures_HaveIdenticalKeySets` 会失败。与命令面板同名的动作直接复用它的 `Cmd_` 文案键,保证两处措辞一致。
- 本表只登记**真实存在的绑定**。菜单或提示里写了、代码里却没绑的键位不得列入(历史上出现过 `Ctrl+N` 只有提示没有绑定的情况,见设置审计 C-10)。

## 平台差异

全局键位在 Windows / Linux / macOS 上出厂一律是 `Ctrl`,可以在设置里改;改键时也能用 Win / Cmd(`Meta`)。

macOS 上终端里另有一组**固定的** Command 别名(`KeyboardShortcutService`):`Cmd+C` / `Cmd+V` 复制粘贴,
`Cmd+T` / `Cmd+W` / `Cmd+,` 新建标签、关闭标签、打开设置。它们不随改键变化,改键时 `Cmd+C` / `Cmd+V` 也不能占用。
`Ctrl+C` 在三个平台都保持「发送中断信号」的语义,不会被复制抢走。

## 阅读说明

- 「生效条件」为 `—` 表示无条件生效。
- 键位里的「左键 / 右键 / 中键 / 双击 / 拖拽 / 滚轮 / 侧栏 / 命令标记列 / 标题栏 / 标签页 / 标签条 / 分割条 / 连接行 / 分组行」是鼠标手势的组成部分,不是键盘按键。「命令标记列」是侧栏里那条为每条命令画一个标记的窄列,只有对端 shell 发 OSC 133 标记时才出现。
- 同一动作出现多行,表示它有多个等效键位或在不同条件下的变体(例如回滚翻页分「主屏」与「备用屏」两种)。

## 自定义键位

窗口级键位**先于终端控件吃键**(Avalonia 在分发按键事件之前就匹配 `KeyBindings`):登记了的组合键,远端程序永远收不到。
而 `Ctrl+字母` 恰好就是终端的控制字符,任何一套出厂键位都会撞上某个远端程序 ——
[joesdu/VelaShell#551](https://github.com/joesdu/VelaShell/issues/551) 就是 nano 的 `^K` 被命令面板吃掉。所以这些键位可以改,也可以解绑。

**可以改的**:「全局」「标签与面板」两组里除「窗格间移动焦点」外的全部,「终端」组里的搜索终端内容、清屏、放大 / 缩小 / 重置字号
(完整清单见本节末尾的表)。其余都是固定键位。

**怎么改**:设置 → 快捷键,可改的那些行右侧有三个按钮 ——

- **铅笔**:点了之后直接按下新的组合键;`Esc` 取消,点别处也取消。只按修饰键时不算数,框里先显示已按住的修饰键。
- **×**:解绑。这一按不再触发任何动作,原样交给终端。
- **↺**(只在改过时出现):恢复出厂键位。

搜索框旁的「全部恢复默认」一次撤掉所有改动。改动是暂存的,**保存设置**后才生效;改过的键帽用强调色显示,解绑的显示「未绑定」。

**规则**:

- 至少带 `Ctrl` 或 `Alt`(或 Win / Cmd);不带修饰键的只能用 `F1`–`F24` —— 否则这个字就打不出来了。
- 不能占固定键位:`Ctrl+Shift+C` / `Ctrl+Shift+V`(复制、粘贴)、`Ctrl+C`(中断)、`Ctrl+Shift+Up` / `Ctrl+Shift+Down`(跳提示符)、
  `Ctrl+Backspace`(删词)、`Ctrl+R`(断线重连)、`Alt+Enter`(命令补全)、`Alt+方向`(窗格移焦)、`Ctrl+L`(SFTP 路径栏);
  macOS 上另有 `Cmd+C` / `Cmd+V`。
- 新组合键已经绑给别的动作时先问:点「替换」,那一条变为未绑定;点「取消」什么都不改。恢复默认时出厂键位正被别的动作占着,同样先问。
- 录回出厂键位等于没改,不留记录。

**终端冲突提示**:当前键位会从终端手里抢走一个按键时,行下方用警示色说明。例如出厂的 `Ctrl+P`:「终端里这一按是 ^P;要把 ^P 发给远端,
请按 Ctrl+Shift+P」—— 终端对 `Ctrl+Shift+字母` 发同一个控制字符,那一按没被占用时就是替代按法;`Ctrl+W` 的替代按法被「关闭全部标签」
占着,就只说「绑定期间远端程序收不到它」。出厂键位里会抢键的有 `Ctrl+N` / `Ctrl+T` / `Ctrl+W` / `Ctrl+P` / `Ctrl+B` / `Ctrl+F` / `Ctrl+-`。

**存在哪**:设置里的 `shortcuts.overrides`,只存改过的那几条 —— 绑定 id → 手势,空串表示解绑。出厂键位以后调整时,没改过的人自动跟上。
认不出的手势、不合上面规则的手势(只可能是手改配置文件改出来的)按出厂键位处理。导出 / 导入设置带着它;云同步开了「应用设置」时它也跟着同步。

```json
"shortcuts": {
  "overrides": {
    "app.palette": "Ctrl+Shift+P",
    "session.close": ""
  }
}
```

手势用 Avalonia 的键名:修饰键写 `Ctrl` / `Shift` / `Alt` / `Meta`,数字键是 `D0`…`D9`,`,` 是 `OemComma`,`=` 是 `OemPlus`,`-` 是 `OemMinus`。
最省事的办法是在设置页里录一次,再看导出的设置。

| 取消并关闭当前对话框 | `Esc` | 对所有对话框与二级窗口生效 |
| 触发默认按钮 | `Enter` | — |
| 最大化/还原窗口 | `标题栏+双击` | — |
| 取消进行中的停靠拖拽 | `Esc` | 仅在停靠拖拽进行中 |
| 在密码框中粘贴 | `Ctrl+V` | — |
| 密码框中禁止复制 | `Ctrl+C` | Ctrl+X 同样被禁止 |
