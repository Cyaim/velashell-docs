# 消息中心与资讯源

> 新增于 2026-08-30。侧边栏底部铃铛的设计、资讯源的 JSON 契约与投放规则。
> **要做推送后台的人，看第 3 节就够了。**

## 1. 它是什么，不是什么

消息中心装的是**要留存、可回看**的东西：有新版本了、订阅源发来的公告或安全资讯、
将来后台推的运营消息。

它**不收运行时告警**。主机指纹变了会当场弹窗，会话断了会亮标签、写状态栏 ——
那些要的是立即打断，已各有归宿；把它们也塞进列表，只会把真正需要读的东西淹掉。
这条边界写在 `Core/Notifications/INotificationCenter` 的类型注释里，加新内容源前先读一遍。

| | 消息中心 | 运行时告警 |
| --- | --- | --- |
| 例子 | 有可用更新、产品公告、CVE 资讯 | 指纹变更、会话断开、传输失败 |
| 呈现 | 铃铛角标 + 列表，可回看 | 弹窗 / 状态栏 / 标签闪烁，当场即逝 |
| 留存 | 跨重启（SonnetDB `notifications`） | 不留存（安全事件另入审计日志） |
| 归属 | `INotificationCenter` | `ISecurityAlertService` / 各面板 |

## 2. 界面

入口是侧边栏底部栏的铃铛（在插件、设置按钮左侧）。有未读时铃铛右上角出现一个
6px 的强调色圆点 —— 那里只有 24px 见方，放不下数字，而“有没有新东西”一个点就够。

面板为 360px 非模态浮层，**锚在左下贴着铃铛**（浮层从哪个按钮开出来就该长在哪个按钮旁边）。
**按住标题栏可在窗口内自由拖动**，越界自动夹回可视区，松手时把位置落盘
（`ui-layout/notification-panel`），下次打开回到原处 —— 与文件传输提示共用
`PanelDragHandler` / `IDraggablePanel` 那一套，不是各写一份。

- **标题栏**：铃铛 + 「消息」+ 未读数徽标 | 只看未读（切换）· 全部已读 · 清空 · 关闭
- **每条消息**：
  - 未读的左侧有 2px 强调竖条，标题用主文本色 + Medium；已读退成次要色不加粗
  - 首行：种类徽标（资讯 / 更新 / 安全 / 活动；`severity` 为 warning/critical 时换成警示色描边）+ 相对时间
  - 标题（可换行）、正文（最多两行，超出省略）
  - 去处一行**两端对齐**：主机名钉左、动作文案 + `›` 钉右，**外链才有主机名**。
    动作贴右边缘是因为指针本来就多停在那侧（每行的删除键、滚动条都在那边），"看到→点到"的路最短；
    主机名长短不一（站内跳转干脆没有），若让它跟动作挤在一起，动作的左沿就会一行一个位置 ——
    两端各钉一边，两条竖直边就都是齐的
- **整行可点** = 跳转并标记已读。点击做成透明按钮而非给 Border 挂手势，键盘 Tab 能走到，
  焦点框与禁用态跟着 Avalonia 的按钮语义走。
  **悬停高亮挂在整行的外层容器上,而不是那个只占内容列的按钮** —— 挂在按钮上时
  删除键那一列不跟着变色,整行被切成深浅两块,中间那道边界看着就像凭空多了一条竖分割线。
- 空态按筛选给不同文案：「暂无消息」/「没有未读消息」

### 快捷跳转

一条消息可以带一个去处，二选一，**站内优先**：

| 字段 | 行为 |
| --- | --- |
| `commandId` | 走 `ICommandRegistry.Execute` —— 菜单、命令面板、快捷键共享的同一套注册表，跳转目标不会与其它入口跑偏。插件注册的命令同样可用 |
| `url` | 系统浏览器打开，**只放行 https** |

命令没注册（返回 false）时自动退回外链，而不是什么都不做。

「有可用更新」用的就是站内这条：`commandId = app.settings.about` →
打开设置并直接落到「关于」页，用户就地更新，而不是被丢在设置首页自己找。
分区定位走 `SettingsSectionKey` 枚举而非下标，`SettingsSectionKeyTests` 钉住二者对齐 ——
往分区列表中间插一页而忘了同步枚举，会当场测试失败，而不是静默跳去隔壁页。

**Linux 手动更新（2026-10-08 起）**：「关于 → 检查更新」发现新版本且有当前平台的更新包后，
用系统默认浏览器打开 GitHub Releases 发布列表，用户自行选择 deb、rpm 或便携包下载并安装。
Linux 不再检查安装目录是否可写，也不自动下载或原地换版；提示包含新版本号和发布页面地址，
浏览器无法启动时仍可手动访问。发布列表包含预发布版本，适用于预览通道。
启动时的更新检查仍只投递消息，不自动打开浏览器。Windows / macOS 的更新流程保持不变。

**下载进度带速率（2026-10-14 起）**：Windows / macOS 在应用内下载更新包时，关于页的状态行显示
「百分比 · 已下载/总量 · 当前速率」。速率取滑动 3 秒窗口的实测值（`DownloadRateMeter`），不是全程
平均值 —— 前段快后段慢时全程均值既不解释"现在慢"也不解释"刚才快"。下载线程只在收到新字节时才
汇报，所以界面另有一条 500ms 心跳（`UpdateDownloadTracker.Tick`）负责在两次汇报之间刷新：速率保鲜期
1 秒，过了就归零，不让一个不再更新的旧数字挂在界面上；连续 10 秒没有任何新字节则判定停滞，状态行换成
带提示的文案。进度链路的类型随之从 `IProgress<int>` 改为 `IProgress<UpdateDownloadProgress>`
（字节数、整包字节、速率）。

## 3. 资讯源契约（后台按这个发）

> **官方实现已经有了**：[velashell-feeds](https://github.com/VelaShellLabs/velashell-feeds)
> 部署在 <https://feeds.easilynet.top/feed.json>，聚合 CISA KEV + NVD 的漏洞情报，
> 并带一个投放公告与广告的管理台（复用插件市场的统一认证，白名单管理员）。
> 自行部署的资讯源仍然可以——本节的格式就是它们之间唯一的约定。

地址在「设置 → 常规 → 消息中心 → 资讯源」，必须是 **https**。
**出厂即指向官方资讯源**（`NotificationOptions.OfficialFeedUrl`）：安全资讯的价值在于
「用户没去找的时候它自己到」，而默认关闭的资讯源几乎没人会去打开 —— CISA KEV 那几条
「现在就有人在打这个洞」，就等于谁也收不到。

这个默认值的代价必须说清楚，不能藏：**定期外呼从此是默认发生的**，因此它被写进了客户端
`PRIVACY.md` 的「网络连接」清单。**把地址清空，一个网络请求都不会发出** —— 一个终端客户端
默默定期外呼，在企业环境里是要被问责的事，那个退出口必须一直留着；换成自行部署的资讯源同样支持。

出站走进程级 `HttpClient.DefaultProxy`（由 `VelaWebProxy` 接管），因此自动遵守
「设置 → 网络代理」，与更新检查、Gist 同步同一条链路。

```json
{
  "schema": 1,
  "items": [
    {
      "id":          "2026-08-30-release-1.4",
      "kind":        "news",
      "severity":    "info",
      "title":       "VelaShell 1.4 已发布",
      "body":        "隧道流量统计、断线自动恢复、端口冲突预检。",
      "publishedAt": "2026-08-30T02:00:00Z",
      "expiresAt":   "2026-10-01T00:00:00Z",
      "linkLabel":   "查看详情",
      "url":         "https://velashell.dev/releases/1.4",
      "commandId":   "app.settings.about",
      "locales":     ["zh-Hans", "zh-Hant"],
      "platforms":   ["win-x64", "osx-arm64"],
      "minVersion":  "1.2.0",
      "maxVersion":  "1.3.9"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✅ | 稳定标识。**去重与已读状态的键** —— 同 id 重复投递会被跳过且保住已读状态 |
| `title` | ✅ | 标题，超过 200 字符截断 |
| `publishedAt` | ✅ | ISO 8601（UTC）。列表按它倒序，不是按收到的时间 |
| `kind` | | `news`（默认） / `update` / `security` / `promotion` |
| `severity` | | `info`（默认） / `warning` / `critical`；后两者用警示色徽标 |
| `body` | | 正文，超过 1000 字符截断，列表里最多显示两行 |
| `expiresAt` | | 到点后不再展示，也会在下次载入时被清掉 |
| `linkLabel` | | 动作文案；不给则按去处兜底为「查看」/「阅读全文」 |
| `url` | | **仅 https**，其它协议一律丢弃（条目本身保留，只是没了去处） |
| `commandId` | | 站内命令 id，优先于 `url` |
| `locales` | | 定向：界面语言。缺省或空数组 = 不限 |
| `platforms` | | 定向：RID（`win-x64` / `osx-arm64` / `linux-x64` …） |
| `minVersion` / `maxVersion` | | 定向：版本区间（**含端点**），预发布后缀不参与比较 |

### 客户端的硬约束（后台要照顾到）

- **单次最多接受 100 条**，超出截断。
- **响应体上限 512 KB**，超出直接放弃这次拉取。
- **只走 https**：明文取回的公告可被中间人替换，而公告里带的是用户会去点的链接。
- **一条坏数据不会让整个源哑掉**：缺 `id`/`title`/`publishedAt` 的条目被单独跳过，
  同一批里的好条目照常展示。
- **本机版本号读不出来时不做版本定向过滤** —— 宁可多看一条，也好过因为版本号异常
  就把「你这个版本有问题，快升级」这种正是冲着你来的消息漏掉。
- 源不可达、返回垃圾、字段缺失，一律当作「这次没有新消息」，绝不给用户看错误。

上述规则逐条有测试钉住，见 `tests/VelaShell.Core.Tests/Notifications/AnnouncementFeedDocumentTests.cs`
—— 那份用例同时也是这份契约的可执行说明。

## 4. 本地内容源：可用更新

不依赖资讯源。启动时按「设置 → 常规 → 启动时检查更新」查一次，发现新版本就投一条，
点击落到「关于」页。

- id 形如 `update:1.4.0`，带版本号：同一版本每次启动都会重投，靠 id 去重并保住已读状态；
  真出了新版本则是新 id，重新亮起未读。
- **商店版（MSIX）直接跳过**：安装目录只读、更新由 Microsoft Store 接管，
  推一条「去关于页更新」只会把用户送到一个什么也做不了的页面。

> 顺带修好了一处：`General.CheckUpdatesOnStartup` 此前全仓没有任何消费者
> （设置审计 R-01 判为「更新服务尚未接入」而隐藏），现在它真正决定启动时查不查，
> 因而在常规页恢复展示。更新频道 / 自动下载仍未接线，继续隐藏。

## 5. 存储与上限

- 落点：SonnetDB 文档集合 `notifications`，单份文档 `inbox`（经 `IAppDataStore`）
- **跨重启留存**：一条公告关掉应用第二天再看仍然成立；这与文件传输面板相反 ——
  一次传输的进度隔天已经没有意义
- 保留 **200 条**上限，超出按发布时间丢最旧的；过期条目在投递与载入时各清一次
- 存储损坏或落盘失败都不影响本次运行：读不出来当作没有历史消息，写不进去下次变更再试

## 6. 设置项

「设置 → 常规」下新增「消息中心」分节（`AppSettings.Notifications`）：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 提醒可用更新 | 开 | 把「有可用更新」投进消息中心 |
| 资讯源 | **官方源** `https://feeds.easilynet.top/feed.json` | https 地址；可换自行部署的源，**清空即不订阅、不联网** |
| 拉取间隔（小时） | 6 | 下限 1；启动时另外拉一次 |
| 接收运营消息 | 开 | 关闭后丢弃 `kind = promotion` 的条目，公告与安全资讯照常接收 |

计时器按固定的半小时跳，真正拉不拉由拉取间隔决定 —— 用户改完间隔，下一跳就生效，
不用重启也不用重设计时器。

## 7. 尚未做的

- **插件发通知**：SDK 的 `IUiApi` 目前只有 `ShowPanelAsync`，没有通知能力。
  宿主侧的接口形状已按这个用途定好（`commandId` 跳转对插件注册的命令同样有效），
  但真要开放给插件，需要改 velashell-plugin-sdk 仓库 + 扩展隔离进程的 IPC 协议 + 走 SDK 发版流程，
  是独立的一批。
- **系统级通知**（Windows 通知中心 / macOS 通知）：目前只在应用内呈现。
- **消息分组与搜索**：条数上限 200，暂时用「只看未读」筛选就够。
