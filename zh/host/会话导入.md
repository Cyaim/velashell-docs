# 会话导入

> 更新于 2026-10-09。三个迁移来源:**Xshell**、**WinSCP**、**OpenSSH `~/.ssh/config`**;
> 外加 VelaShell 自己的连接文件(**JSON / CSV** 导入导出,第七节,joesdu/VelaShell#571)。
> English: [`../../en/host/session-import.md`](../../en/host/session-import.md)

从别的工具搬过来这件事,只有第一次做,而且做的时候用户对 VelaShell 还一无所知。
所以这扇对话框的默认路径是**打开、看一眼、点一下**,不是"先告诉我你从哪个工具来"。

## 一、对话框的行为

`SessionImportView` + `SessionImportViewModel`(`Presentation/ViewModels/`):

- **打开即扫描全部来源**,并行呈现为若干张来源卡片。用户不必先回答"从哪导入"——
  那个问题机器自己能查。
- **默认全自动**:受支持、不重复的会话全部预勾选,主按钮上写着数量
  (「导入 12 个会话」),点一下就完事。需要逐条挑时切「自定义选择」展开。
- **跨来源去重**:按 `主机|端口|用户` 归并,同一台机器在 Xshell 和 WinSCP 里各存了一份时
  只保留先扫到的那条;与 VelaShell 中**已存在**的会话撞上的也标成重复,默认不勾
  (「跳过已存在」开关可关)。
- **一个来源一个分组**:导入后新建分组承载,会话打上来源标签,不与用户既有分组混在一起。
- **结果统计**:导入数 / 密码还原数 / 跳过数。

来源探测不到时,那张卡片会给出「手动指定」入口 —— 便携版、非默认安装位置、
以及放在别处的配置文件都从这里进来。

## 二、三个来源

| 来源 | 默认位置 | 手动指定 | 密码 |
| --- | --- | --- | --- |
| **Xshell** | 注册表 `HKCU\Software\NetSarang\Common\<版本>\UserData` 指向的 `Xshell\Sessions`;读不到时回退到「文档\NetSarang Computer\{8,7,6,5}\Xshell\Sessions」 | 选文件夹 | RC4 + 当前 Windows 用户身份(用户名 / SID,兼容 5/6/7/8 两套密钥方案)还原;**启用主密码时一律不解**,会话仍以「不含密码」导入 |
| **WinSCP** | 注册表优先,其次默认 `WinSCP.ini` | 选文件 | 0xA3 编码 + 用户名/主机名前缀校验还原;主密码同上 |
| **OpenSSH config** | `~/.ssh/config` | 选文件 | **没有密码可还原** —— OpenSSH 的配置文件从不存密码 |

前两个来源有一半的代码在解密码;第三个来源一行都没有,它的难点全在解析规则上。

## 三、`~/.ssh/config` 的解析规则

`ssh_config` **不是 INI**:它没有「节内取值」这回事,同一个关键字可以出现在多个块里,
谁生效由**块的顺序**决定。照 INI 的思路写,在简单配置上全对,在任何一份带兜底块的
真实配置上全错 —— 而且错得不响:导进来的会话看着都对,只是全都连错了账号。

### 3.1 先出现者胜

OpenSSH 的规则是**首次取得的值获胜**(`ssh_config(5)`:"the first obtained value for each
parameter is used"),所以约定俗成的写法是具名块在前、`Host *` 兜底在后,兜底块只补
前面没写过的键:

```sshconfig
Host prod
    HostName 10.0.0.5
    User deploy        # 先出现,胜出

Host staging
    HostName 10.0.0.6  # 没写 User

Host *
    User fallback      # 只有 staging 吃到
    Port 2200          # 两条都吃到
```

解析用的是 SSH 库的 `SshConfigFile`(宿主不另写一份):它保留**完整的块结构**(模式列表 + 有序选项),
`Resolve` 按块序遍历所有匹配该别名的块,每个关键字只取最先出现的那个值。只挑关键字而丢掉块归属,这条规则就做反了。

### 3.2 `Include` 就地展开

`Include` 在文件里的**位置决定优先级**:写在开头的 include 里的 `User` 胜过主文件后面的
兜底块,挪到末尾则相反。所以展开发生在解析的那一刻,而不是"先收集所有文件再拼"。

- 相对路径以 **`~/.ssh` 为基准**(OpenSSH 用户配置的规则),不是配置文件自身所在目录 ——
  用户手动指定别处的配置文件时,里面的 `Include conf.d/*` 仍该指向 `~/.ssh/conf.d`
- 互相 include 由「已访问文件集合 + 深度上限 16」兜住(库的 `SshConfigFile.MaxIncludeDepth`)
- 末段通配展开后**排序**,否则同一份配置在不同文件系统上导出的顺序不一样

### 3.3 哪些别名算「一台机器」

只导入**字面量别名**。`Host *`、`Host *.internal !secret.internal` 这类块是给别人兜底用的
模板,本身不是可连的机器;它们的选项会通过取值规则渗到具名别名上,这正是 OpenSSH 的语义,
不需要也不应该单独产出一条会话。取反(`!`)一票否决,被排除的别名不吃这个块。

**`Match` 块按库的规则判定,判不了就不生效**:`all`、`host`、`originalhost` 照常判;
`user`、`localuser` 要知道「以谁的身份、从哪台机器连」,`exec` 要执行命令,`canonical` / `final` 我们不做 ——
静态导入时这些都判不了,那一块的选项不会渗到会话上(取反也一样:`!exec` 判不了仍是判不了)。
不能当成 `Host *` —— 那会把只在特定条件下才生效的选项无条件套到每一条会话上,
一个 `Match exec "on-vpn"` 里的内网跳板会就这么长到所有会话头上。`Match` 块本身不产出会话。
(2026-09-25 之前宿主用自己的解析器,`Match` 块一律整块跳过,`Match all` / `Match host` 也不生效。)

不写 `HostName` 时,**别名本身就是主机名**(`Host build01` 不写 HostName 时 ssh 直接连
build01)。不做这条,一份「全靠别名 + 全局 User」的配置会一条都导不出来。

### 3.4 字段映射

| ssh_config | VelaShell | 说明 |
| --- | --- | --- |
| `Host <别名>` | 会话名称 | 只取字面量别名 |
| `HostName` | 主机 | 缺省即别名;`%h` 展开为原始别名 |
| `Port` | 端口 | 缺省 22;越界值忽略 |
| `User` | 用户名 | 缺省空(连接时再问) |
| `IdentityFile` | 私钥路径 + `AuthMethod.PrivateKey` | `~` 与 `%d` `%u` `%h` `%r` `%%` 由 SSH 库展开(`SshHostConfig.ExpandIdentityFiles`,与连接时读私钥同一套;〔历史〕曾经宿主自己展开,只认 `~` / `%d`,`%h` 原样留在路径里),相对路径按 `~/.ssh` 求绝对;**不校验文件是否存在** —— 密钥可能还没从另一台机器拷过来,把路径带进配置比悄悄丢掉有用;`none` 视为未配 |
| `ProxyJump` | 跳板引用(`JumpHostProfileId`) | 见下 |

**其余关键字一律忽略**:`LocalForward` / `RemoteForward`(端口转发不随会话导入)、
`ServerAliveInterval`、`ForwardAgent` 等等。它们要么在 VelaShell 里是另一处的设置,
要么宿主还不支持 —— 静默丢掉是有意的,导一半配置比不导更容易让人误判。

### 3.5 `ProxyJump` 的三处判断

- **取最后一跳**。`ProxyJump a,b` 的语义是「经 a 到 b、再由 b 抵达目标」,离目标最近的是 **b**;
  VelaShell 的跳板是逐条链式引用(每条配置各指自己的上一跳),取第一跳会把链接反。
  更前面的跳板由 a、b 各自的配置继续串。
- **只在本批次内按别名解析**。拿 config 里的局部别名去撞用户既有会话的名字,会把毫不相干的
  两台机器串成一条跳板链。跳板没被勾选、或压根不在这份 config 里时留**直连** ——
  会话照常导入,用户在连接对话框里补一下即可。
- **成环即断**。config 自己写出 `a→b→a` 时断掉后建立的那一条:留着只会让连接工作流的
  环检测报错,直连是这两条会话里唯一还能用的形态。

解析支持 `user@host:port` 与带方括号的 IPv6,别名匹配只认 host 段。

## 四、预览行的凭据状态

自定义选择模式下,每条会话右侧给出一个凭据状态(四态,五份 resx 齐):

| 状态 | 含义 |
| --- | --- |
| 已还原 | 密码解出来了,导入后勾选「记住密码」并 AES 重新加密落盘 |
| 需手动填写密码 | 来源里有密码但解不出(主密码、换过 Windows 账户等),会话仍导入 |
| **使用密钥文件** | 该会话走私钥认证(来自 `IdentityFile`) |
| 无密码 | 来源里就没存 |

第三态是随 SSH config 一起加的:对一条配了 `IdentityFile` 的会话说「无密码」是**误导** ——
它不是缺凭据,它的凭据是另一种。

来源启用了主密码时,对话框顶部给出整体告警:**主密码库的密码不可恢复,只导会话**。
不支持的协议(WebDAV 等)禁用勾选并标出原协议名。

## 五、新增一个来源要做什么

1. 实现 `ISessionImportService`(`Core/Import/`):`SourceKey`、`BrowseKind`、
   `DetectDefaultSource`、`ScanAsync`、`ImportAsync`
2. 写入复用 `SessionImportWriter`(`Infrastructure/Import/`)—— 建分组、去重、密码重加密、
   `IdentityFile` → 私钥认证、`ProxyJump` → 跳板引用,都在那里
3. 在 `InfrastructureServiceCollectionExtensions` 里**追加一行** DI 注册

对话框那边零改动:它遍历的是 `IEnumerable<ISessionImportService>`。

## 六、隐私与安全

- 三个来源**只读不写**,不改动任何一个外部工具的配置文件
- `~/.ssh/config` **仅在用户执行会话导入时**读取(平时读的是 `~/.ssh` 下的密钥与
  `known_hosts`,见 [`PRIVACY.md`](https://github.com/joesdu/VelaShell/blob/main/PRIVACY.md))
- 还原出的密码由仓储 **AES 重新加密**落盘;**只有成功还原时**才置「记住密码」,
  解不出来的不会留一个空密码假装记住了
- 启用主密码的来源一律不尝试解密,而不是拿错密钥去猜
- 连接文件(第七节)默认不含任何密码;要带就必须设导出口令整段加密,**没有明文导出密码这一选项**;CSV 永远不带

## 七、连接文件:VelaShell JSON 与 CSV(2026-10-09,joesdu/VelaShell#571)

上面三个来源是「从别的工具搬过来」;这一节是 VelaShell 自己的连接文件 —— 备份、换电脑、发给同事,
以及用 Excel 一次填好两百台设备再导进来。

入口都在资源管理器:「更多」菜单的「导入连接文件… / 导出全部连接… / 保存 CSV 导入模板…」,
分组右键的「导出此分组… / 导入到此分组…」,多选右键的「导出所选…」
(界面见 [交互与界面规格.md](交互与界面规格.md) §3 与 §12)。

### 7.1 两种格式

| | VelaShell JSON | CSV |
| --- | --- | --- |
| 用途 | 备份、迁移到另一台电脑、发给同事 | 用 Excel 批量编辑、从零做一张设备清单 |
| 内容 | 连接的全部配置(直接序列化 `SessionProfile`)+ 所在分组 + 被引用的共享凭据 + 端口转发隧道 | 常用字段:Id、名称、分组、协议、主机、端口、用户名、认证、密码、私钥、证书、共享凭据、跳板主机、标签、备注 |
| 敏感信息 | 默认不导;勾上必须设导出口令,整段加密(7.3) | 导出永不包含;导入时可以有 `password` 列 |
| 编码 | UTF-8,无 BOM | 导出为带 BOM 的 UTF-8(没有 BOM,Excel 按本地代码页打开,中文全成乱码);导入见 7.4 |

导出范围是用户选的连接**加上它们的跳板主机**(逐级往上)。只导出经堡垒机连的那批机器、不带堡垒机本身,
到另一台电脑上就全是直连 —— 而直连恰恰是连不上的那种。导出对话框的概要里单独一行说明自动带上了几台。

### 7.2 JSON 的结构

```json
{
  "format": "velashell-sessions",
  "version": 1,
  "exportedAtUtc": "2026-10-09T08:00:00Z",
  "application": "VelaShell 0.9.0",
  "groups": [ { "id": "…", "name": "生产环境", "sortOrder": 0 } ],
  "sessions": [
    { "id": "…", "connectionType": "ssh", "name": "web-01", "host": "10.0.0.11", "port": 22,
      "username": "deploy", "authMethod": "privateKey", "privateKeyPath": "~/.ssh/id_ed25519",
      "groupId": "…", "jumpHostProfileId": "…" }
  ],
  "sharedCredentials": [ … ],
  "tunnels": { "<连接 id>": [ … ] },
  "secrets": { "algorithm": "pbkdf2-sha256-200000+aes-256-gcm", "data": "…" }
}
```

- 枚举写名字(`"privateKey"`),读的时候数字也认;中文原样写、不转成 `\u` 转义 —— 这份文件是给人看、给人改的
- 连接直接序列化 `SessionProfile`,不另抄一份 DTO:另抄一份就多一处「加字段要记得同步」,漏了的表现是
  「导出再导入之后某个设置没了」。代价是新字段会自动进文件,所以 `SessionArchiveFieldTests` 用反射逐个属性检查归类
  (普通配置 / 机密 / 本机状态),新加一个没归类的属性直接红 —— 防的是一个新的机密字段被悄悄明文导出
- 不写进明文部分的:密码、私钥口令、插件机密(要导就进 `secrets`),上次连接时间(本机状态)
- 手写的文件可以省掉 `format` 与 `id`:有 `sessions` 数组就收;没写 `id` 的一律当新连接。允许注释与尾逗号
- `version` 比本程序新的整份拒收,不猜着读;单条连接坏了只坏那一条(预览里标红),不整份作废

### 7.3 敏感信息

- 导出对话框里「包含密码等敏感信息」默认不勾;勾上必须设**至少 8 个字符**、两次一致的导出口令。
  **没有「明文导出密码」这个选项**,是有意的:导出的文件常被随手发出去、丢进网盘,明文密码一旦写进去就收不回来。
  这批连接里一个保存的密码都没有时这一项是灰的。CSV 永远不带敏感信息
- 加密与云同步的端到端口令同一套:PBKDF2-SHA256(20 万次迭代)派生 AES-256-GCM 密钥,
  密文 Base64(salt16 | nonce12 | tag16 | cipher)。只有 `secrets` 这一段是密文,其余照常明文
- 导入时文件带着 `secrets` 就出现口令框;**不解锁也能导,只是不带密码**。口令错与数据损坏不区分,都提示「口令不正确,或者文件已损坏」。
  `secrets.algorithm` 不认识的(将来换了算法)当作解不开,整份文件提示一句,连接照样能导
- 解出来的密码由目标机器的仓储用**它自己的**机器密钥重新加密落盘

### 7.4 CSV 的列与读法

导出的 CSV 就是模板,表头固定为:

`id,name,group,protocol,host,port,username,auth,password,private_key,certificate,credential,jump_host,tags,notes`

| 列 | 写法 | 空着时 |
| --- | --- | --- |
| `id` | 连接 Id(导出时填好,导回时据此精确对上原来那条) | 当新连接 |
| `name` | 显示名称 | 用主机 |
| `group` | 分组名 | 未分组 |
| `protocol` | `ssh` / `sftp` / `ftp`(自动)/ `ftp-plain` / `ftps`(显式)/ `ftps-implicit` / `plugin:<协议 id>`(带点的 id 可省掉 `plugin:`) | `ssh` |
| `host` | 主机名或 IP,**唯一必填**。也可写成 `user@host:port`、`[v6]:port`,对应那一栏空着时才拆;裸 IPv6 不拆,不带端口的 `[v6]` 只去掉方括号(配置里存裸地址)。拆出来的用户名 / 端口在覆盖已有连接时同样生效(哪怕表里没有那两列) | 该行报错 |
| `port` | 1–65535 | SSH / SFTP 22,FTP 21(隐式 FTPS 990);插件协议必填 |
| `username` | 用户名 | 连接时再问 |
| `auth` | `password` / `key` / `certificate` / `agent` / `tailscale` | 有证书是证书,有私钥是私钥,否则密码。导出时总是写出(引用共享凭据的也写),凭据万一对不上,导回去仍是原来的认证方式 |
| `password` | 密码,不修剪首尾空白(导出时恒为空) | 不存 |
| `private_key` / `certificate` | 文件路径,不校验存在 | — |
| `credential` | 共享凭据的名称或 Id;填了就引用它,`auth` 等认证列不作数，**但 `auth=tailscale` 优先且忽略该引用**。本机重名时,若与这一行重复的那条本机连接正引用其中一条就认它,否则不接 | 单独认证 |
| `jump_host` | 跳板主机:另一条连接的名称或 Id。先在文件里找,再在本机找;本机重名时,若与这一行重复的那条本机连接正经其中一台跳就认它,否则不接(宁可直连也不接错) | 直连 |
| `tags` | 分号分隔(`,` `\|` 也认) | — |
| `notes` | 备注,可以多行(整格用双引号括起来) | — |

FTP 与插件协议配了私钥 / 证书 / Agent / Tailscale SSH 的行报错(它们只认密码)。Tailscale 连接清掉旧密码、私钥、口令、证书、共享引用与记住密码；JSON 写出 `"authMethod":"tailscale"` 并接受数字 `4`，加密导出也不携带旧 SSH 秘密。覆盖旧连接时合并完再清理、在解析共享引用之前跳过它，跳板与其它设置保持。读的时候尽量宽容:

- 分隔符按表头那一行自动认逗号 / 分号 / 制表符(德语区的 Excel 默认存分号,从表格里复制出来的是制表符)
- 表头不区分大小写、不管空格与 `_ - .`,也认常见别名与中日韩写法(主机、端口、用户名、分组…,
  表在 `SessionCsvHeaderAliases`);列的顺序随意,不认识的列忽略并在顶部提示。没有 `host` 列的文件整份拒收
- 编码依次试 BOM(UTF-8 / UTF-16)→ 严格 UTF-8 → 本地 ANSI 代码页。最后一步是给中文 Windows 上 Excel 默认的
  「CSV(逗号分隔)」用的,它存的是 GBK;区域格式不是中日韩、界面语言是的时候用界面语言的代码页
- CSV 注入防护:导出时以 `= + - @` 等开头的单元格前面补一个单引号,Excel 就把它当文本而不是公式;
  导入时去掉这个单引号,往返不丢字(连接名、备注可能来自别人给的文件)
- 单行的问题(主机为空或带空格、端口越界、协议不认识)在预览里标出行号,不影响其余行;Excel 末尾的空行跳过

模板带两行示例,地址用文档专用的 192.0.2.x(RFC 5737)、名字以 `example-` 开头 —— 忘了删,预览里一眼看得出来。

### 7.5 重复与写入规则

- **重复的判据**:先看 Id(同一条连接:本机导出的备份、改过再导回来的 CSV),再看「协议 + 主机(不区分大小写)+ 端口 + 用户名」;
  后者撞上多条时优先挑同名的那条。文件内部的重复不管 —— 那是用户自己写进去的
- **重复时**三选一,默认「跳过」:
  - **跳过**:本机那条不动。文件里谁拿它当跳板,改指本机那一条 —— 导出会自动带上跳板,
    到了另一台电脑上那台跳板多半已经在了,这正是最常见的情形
  - **覆盖**:Id 不变。JSON 整条替换,但文件没带机密(没勾或没解锁)时**保留本机的密码与口令**,上次连接时间也留着;
    CSV **只改文件里有的列**,`password` 列空着表示不改(导出时它恒为空),终端设置、插件设置这些 CSV 表达不了的原样保留 ——
    「导出 CSV → Excel 里改用户名 → 导回去」靠的就是这一条。同一条本机连接只被覆盖一次,文件里第二条撞上它的另存;
    同 Id 的那一行优先 —— 它才是那条连接本身,按主机撞上的别的行哪怕排在前面也抢不走它。
    覆盖会改掉主机、而本机这条存着密码 / 口令时,预览里那一行会提示「本机保存的密码将用于新主机」:
    服务器换了 IP 时这正是想要的,但一份被人改过的文件也能借此把密码引到别处去
  - **两条都留**:文件里的另存一条新连接(新 Id),文件内部指向它的跳板引用一起改过去
- 预览里跳过模式下的重复行勾不上(勾了也不会写,看起来能勾只会让人误会);有错误的行任何模式都勾不上
- **Id 尽量沿用文件里的**:不与本机冲突就用,这样在两台开着云同步的电脑之间导来导去,同步看到的仍是同一条连接,而不是一份副本
- **分组**:默认按文件里的分组放 —— JSON 先按 Id、再按名称(不区分大小写)对上本机分组,CSV 按名称;
  都没有就新建,接在已有分组之后、彼此按文件里的先后排,新建的沿用文件里的分组 Id。也可以在「放到」里选一个本机分组或「未分组」,
  全部放进去;从分组右键「导入到此分组…」进来时预选那一组。预览行右侧标出会落到哪个分组,会新建的注明「新建」
- **共享凭据**(JSON):同 Id 或同名的沿用本机那条,**不覆盖**;都没有才新建(解锁过就带上密码)。
  沿用的那条本机缺密码 / 口令(云同步没设端到端口令时拉下来的凭据就是这样)而文件解锁后有的,补上缺的那几项,已有的不动。
  CSV 只引用本机已有的
- **跳板**:找不到(不在文件里,本机也没有)就改为直连并提示;首尾成环的断开一环
- 落盘顺序:共享凭据 → 分组 → 连接 → 隧道。连接引用前两者,反过来的话中途失败会留下一批指向不存在分组的连接,资源管理器里它们会凭空消失
- 写入时做出的妥协(跳板改直连、凭据找不到…)在导入完成后弹框逐条列出(最多 15 条);没有妥协只弹一条浮层提示
- 写库途中对话框关不掉(Esc、取消、标题栏的 × 都不响应),写完自己关。中途失败时对话框留着显示原因;
  这时库里可能已经有了一部分,所以无论之后是重试还是取消,关掉后资源管理器都会重读一遍(批量修改对话框同理)
- 文件大小上限 16 MB(两百台设备的 CSV 也就几十 KB,超过多半是选错了文件)

### 7.6 代码在哪

规则都是纯函数,在 `Core/Import/`:`SessionArchiveBuilder`(导出范围与内容)、`SessionArchiveJson`(JSON 读写与机密加解密)、
`SessionCsv`(CSV 读写,表头别名在 `SessionCsvHeaderAliases`)、`SessionFileText`(编码)、`SessionImportPlanner`(比对与写入集)。
`Infrastructure/Import/SessionArchiveService`(`ISessionArchiveService`)只负责从仓储取数据、把算好的结果写回去;
三个对话框的视图模型在宿主的 `ViewModels/`(`SessionExportViewModel` / `SessionFileImportViewModel` / `SessionBatchEditViewModel`)。
