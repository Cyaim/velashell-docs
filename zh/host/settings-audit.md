# VelaShell 设置界面功能审计与重组清单

> 审计范围:设置模型、设置页面、持久化服务及主要运行时消费者  
> 审计目标:识别功能重复、语义不清、运行时冲突、无效设置、缺失设置,并给出可执行的分组方案  
> 状态说明:本文是整改台账。2026-07-11 完成第一批整改(阶段一~三及条件展示),各表"状态"列已同步;文中源码行号为审计时快照,整改后可能偏移。

## 1. 执行摘要

当前设置中心包含 9 个一级入口,约 80 个可见设置或管理功能。主要问题不是设置数量本身,而是:

1. `BellMode` 与 `VisualBell` 同时控制终端响铃,存在真实运行时冲突。(已修复)
2. 自动重连次数、默认值和"显示隐藏文件"等设置存在多个状态来源。(已修复)
3. 导出、语言切换和关闭确认等功能的界面描述与实际行为不完全一致。(除本地化外已修复)
4. 12 个以上尚未实现的设置以禁用控件形式长期占据界面。(已全部隐藏或删除)
5. "常规"页承担启动、连接、通知、安全、日志、更新等多个领域,已经成为杂项集合。(部分缓解:更新组隐藏、重连设置归组;整体 IA 重组待做)
6. 密钥管理和代码片段属于功能管理工具,不属于应用偏好设置。(待做)
7. 终端颜色位于"外观",终端字体、编码、光标等位于"终端",用户需要跨页寻找同一对象的设置。(待做)

### 1.1 优先级定义

| 优先级 | 含义 | 处理要求 |
|---|---|---|
| P0 | 已确认的安全风险或运行时冲突 | 应优先处理,避免继续产生错误配置 |
| P1 | 明显误导、状态不一致或关键体验缺陷 | 建议进入最近一个整改版本 |
| P2 | 信息架构、可发现性和高级体验问题 | 可在设置界面重组时统一处理 |
| P3 | 可选增强 | 纳入产品规划评估 |

### 2026-09-20 第四批(#474:启动时折叠分组 + rm -rf 删除远端目录)

两项新设置,都是用户需求 #474 的一部分(宿主侧见 `plan.md` §82)。

- **`General.CollapseGroupsByDefault`(常规,默认关)**:开启后资源管理器的分组以折叠态载入。
  它只决定**本次运行首次见到**某个分组时的初始状态 —— 手动展开/折叠的选择由会话树在进程内记着,
  新建 / 编辑 / 删除连接、云同步回写等触发的整树重建不会把它折回去。记忆不落盘,重启后回到设置说的状态。
  ⚠️ 单独开这一项的价值有限:它要与「置顶连接」配套才完整(常用连接被提到整棵树最前,折叠了照样看得见),
  见 [交互与界面规格.md](交互与界面规格.md) §4。
- **`Transfer.UseRecursiveDeleteCommand`(文件传输 > 传输行为,默认开)**:删除远端目录时先试一条
  `rm -rf`,而不是用 SFTP 逐条递归删。
  - **为什么默认开**:SFTP 那条路要先把整棵树列一遍算总数(为了进度条),再对每个条目发一次
    `SSH_FXP_REMOVE`/`RMDIR`,往返次数与文件数成正比;`rm -rf` 是一次往返。删除结果完全一致。
  - **适用范围**:只对**有 exec 通道的 SSH 会话**成立。独立 SFTP 配置、FTP、S3 等插件协议没有命令通道,
    一律照旧走 SFTP 递归。另有三道闸:只对真目录(符号链接仍按叶子删,语义不变)、路径必须是绝对路径、
    且不能是根目录。
  - **失败即回退**:命令不存在、被策略禁掉、或只删了一半就退非零码时,自动回退到 SFTP 递归 ——
    回退路径会把真正的失败原因带出来,而不是一句没有上下文的 `rm: exit 1`。
  - **已知代价(设置项说明里写明了)**:这条路上没有逐条进度(进度条转不确定态),取消只能关闭通道、
    远端的 `rm` 可能已经删完。**删除前的二次确认不受影响,照旧。**

### 2026-09-20 第五批(#476:指纹变更改为弹窗裁决)

`Security.BlockOnFingerprintChange` 的**默认值由开改为关**(宿主侧见 `plan.md` §83)。

- **为什么改**:「换了台服务器,IP 没变」是运维里最常见的正当指纹变更。旧默认(阻断)把它报成
  一条连接错误 —— 而且是 Tmds.Ssh 那句英文的 `UntrustedPeer`,既看不出是主机密钥变了,也不提
  下一步该做什么;用户唯一的出路是去 `.velashell` 里手动删掉记录。其它 SSH 客户端在这里弹的是
  一个「接受并覆盖 / 拒绝」的框,VelaShell 本来也有这个框(三选项弹窗),只是被默认值挡住了。
- **改成什么**:指纹变更走与首次确认同一个三选项弹窗(永久信任 = 覆盖 known_hosts / 仅本次信任 /
  取消)。弹窗多两样东西:**known_hosts 里的旧指纹**(与本次指纹并排,用户要两把对照才判断得了
  这是自己重装的那台还是一次劫持),以及一段说明这两种可能的提示文案。
- **一次性迁移**:存量配置里那个 `true` 分不清是用户选的还是旧默认值带的,因此与录制、代理默认值
  同一套路 —— 统一关一次并打上 `Security.FingerprintChangeDefaultMigrated`,之后完全听用户的。
  要严格 fail-closed 的,把「指纹变更时阻断并告警」打开即可,行为与旧默认一致。
- **被拒时说人话**:无论是策略阻断还是用户自己点的取消,错误信息都换成本地化文案,点名是哪台、
  两把指纹分别是什么,以及去 设置 → 安全与审计 → 已信任主机 删记录这条出路。
- **跳板链同策略**:此前跳板那一跳是另写的一段校验,未知 / 变更一律静默返回 false —— 于是
  「只当跳板、从没单独连过的机器」第一次用就连不上。现在与终点走同一条 `AddHostAuthentication`。
- **弹窗期间的连接超时**:Tmds.Ssh 0.24 的 `ConnectTimeout` 覆盖整个握手,**包括** HostAuthentication
  回调,弹窗摆着的时间照样在计时。用户多想十几秒,裁决刚点完连接已经被判超时。裁决此时已经生效,
  因此包装器在这一种失败上**原地补连一次**(只补一次)。

| 限制经 SSH 转发来的程序 | 关 | 开 / 关(`XServer.RestrictForwardedClients`) | 只对内置引擎生效,也只在选了内置引擎时出现(「键盘」一节的键盘布局下面)。映射到库的 `RestrictForwardedClients`:经 SSH 转发来的程序看不到 XTEST、收不到原始按键事件、不能改动输入设备 |

- **为什么「选中即复制」改成默认关**:开着时本机复制的内容(包括密码)在任何 X 程序里点一下鼠标中键就能粘出来,在 X 程序里选中文字也随手改写系统剪贴板。
  **只改出厂默认,不迁移存量配置**:已经落盘的「开」分不清是用户选的还是旧默认值带的,照旧生效,要关就手动关。
- **剪贴板跟着键盘焦点所在的会话走,不是设置项**:内置引擎上一直生效(库的 `ClipboardFollowsFocus` 默认开,宿主不改它)——
  本机复制的内容只有焦点所在的那个会话读得到,也只有那个会话里的复制写进系统剪贴板;同一个 SSH 会话里的 `xclip` / `xsel` 算同一个会话。
  各会话的选区(PRIMARY / SECONDARY / CLIPBOARD)彼此隔离,跨会话的复制粘贴经本机剪贴板中转。「启用剪贴板」的说明文字写明了这一点。
- **说明文字写明风险**(五种语言):「选中即复制」补一句「默认关闭:打开后,本机复制的内容在 X 程序里点一下鼠标中键就能粘出来」;
  「限制经 SSH 转发来的程序」写明三样限制与代价 —— 连接不完全信任的服务器时建议打开,打开后那些服务器上的 `xdotool` 之类会失效。
- **为什么「限制」默认关、只对内置引擎**:远端的 `xdotool` 之类靠 XTEST 工作,默认值维持现状(产品决策);按连接区分「经 SSH 转发来的」
  只有内置引擎做得到(连接是宿主经 `ServeAuthenticatedAsync` 交进去的),VcXsrv 分不出来。连接级的信任档与「每个会话一个显示」是后续的新功能。
- **「X11 转发时自动启动」的「不插手」条件收窄**:Windows 上 `localhost:0` 后面的监听者要是当前用户会话里的进程才算「本机已经有 X 显示在用」——
  终端服务器上那可能是别的用户开着的 VcXsrv(常带 `-ac`),原先远端程序的窗口、键盘与剪贴板就落到了别人的桌面上;不是自己的就照常自动启动内置引擎
  (`:0` 被占,挑下一个空闲的显示号)。配置里写死了显示地址、或关掉了自动启动时照旧按 `DISPLAY` / `localhost:0` 走。
- **显示编号「自动」**:探测说空着的号在开起来那一刻被占了(探测与绑定之间被抢先,或者锁文件、抽象名这些探测看不出的占用)时,
  换下一个空闲的号再试,至多 4 次,期间状态一直是「启动中」;手动指定的号照旧直接报错。
- **连接里的「受信任(`-Y`)」**(不是 X Server 页的设置,一并记在这里):提示改写为说明所有转发的会话共用一个显示 —— 能看到彼此的窗口、
  读剪贴板、注入输入;内置 X Server 与 Windows 上的多数 X 服务器只支持受信任,非受信要支持 SECURITY 扩展的外部 X 服务器、本机装 `xauth`。
  显示取自内置 X Server 而连接选了非受信时不开转发,终端顶部一行黄字说明原因与两条出路(勾上受信任、改用外部 X 服务器)。
  2026-10-10 起内置 X Server 两种都支持(非受信的通道以非受信客户端接入),那条黄字随之取消;提示再改写为说明两档各意味着什么,
  外部 X 服务器的非受信模式仍要 SECURITY 扩展与本机的 `xauth`,少数老程序在非受信下工作不正常。

### 2026-10-10 第十二批(X Server:草案第十二节的新功能)

随内置 X 服务端的新功能一起加(`xs_plan` F1–F30)。库的行为见 [X Server 架构](../xserver/design/architecture.md) §7(「信任级别」「每个 SSH 会话一个显示」
「单窗口模式」「2026-10-10 补的功能」)与 §10,交互见[交互与界面规格.md](交互与界面规格.md) 的 X Server 一节,现象与处理见 [X Server 排障](../xserver/troubleshooting.md)。
全部只对内置引擎生效(「窗口模式」除外,两种引擎共用),改了在下次启动 X Server 时生效(「标出 X 窗口的来源」除外,立即生效)。
设置页里的位置:透明与来源两项在「显示」一节(窗口模式下面),输入法在「键盘」一节,「限制经 SSH 转发来的程序」、每个会话一个显示、
TCP 端口在新的「安全」一节(原先都排在「键盘」下面)。

| 设置 | 默认 | 取值 | 备注 |
| --- | --- | --- | --- |
| 窗口模式 | 多窗口 | 原有五档(`XServer.WindowMode`) | 原先只对 VcXsrv 起作用;现在两种引擎共用:内置引擎选单个大窗口 / 无标题栏 / 全屏时以单窗口模式起(整个 X 桌面在一个窗口里,远端的窗口管理器接手),多窗口与无根窗口都是每个程序一个窗口 |
| 每个 SSH 会话一个显示 | 关 | 开 / 关(`XServer.DisplayPerSession`) | 不同 SSH 会话的 X 程序各用各的显示,彼此看不见窗口、读不到键盘与剪贴板、不能注入输入;本机的 X 程序照旧用共用的显示;每个会话多占一点内存与一条线程。单窗口模式下关掉某个会话的「X 桌面」窗口只收掉这个会话的显示 |
| X 窗口里用本机输入法 | **开** | 开 / 关(`XServer.UseHostInputMethod`) | 本机输入法组好的字直接输入给 X 程序(远端不用装 fcitx / ibus);关掉后按键原样交给远端,远端自己的输入法照常用。这部分推翻了原先「XIM 不做」的结论:内置 X Server 同时当 XIM 输入法服务端(`@im=velashell`),经 XIM 连上的程序整段收到上屏的字、候选框跟着它的插入点、on-the-spot 的程序自己画预编辑;连接后的 shell 里静默设上 `XMODIFIERS=@im=velashell`(已经设了的不动)。开关只在内置引擎下有效,改了重启 X Server 生效 |
| 标出 X 窗口的来源 | **开** | 开 / 关(`XServer.ShowWindowSource`) | 经 SSH 转发来的窗口标题(也是任务栏上的文字)与托盘图标的提示写成「user@host:22 — 标题」,标在前面:远端把标题设成什么都盖不住来源;本机直接连的程序不标。**立即生效**:开着的窗口当场改标题(原先说明写「对之后打开的窗口生效」,实际要重启 X Server)。自己画标题栏的窗口只在任务栏上看得到来源 |
| X 窗口透明与圆角 | 关 | 开 / 关(`XServer.CompositingManager`) | 服务端当合成管理器,GTK 的圆角与阴影、Electron 的透明窗口才拿得到 alpha。默认关:带 alpha 的窗口要系统多合成一层,开销还没在真机上量过;关着时带 alpha 的窗口按不透明显示。单窗口模式下不起作用 |
| 也开 TCP 端口 | 关 | 开 / 关(`XServer.ListenTcpOnUnix`) | 只在 Linux / macOS 上出现:默认只开 Unix 套接字;打开后端口只听 127.0.0.1,给经 TCP 连本机环回地址的程序(用主机网络的容器);桥接网络里的容器连不到,Linux 上把 `/tmp/.X11-unix` 挂进去用 `DISPLAY=:N`。Windows 上一直开(WSL、Cygwin 的程序只会走 TCP),设置页不显示 |

- **默认值的取舍**:输入法与来源标识默认开 —— 前者不开中日韩用户在远端程序里打不了字,后者是防冒充的;合成管理器默认关(开销未量);
  TCP 端口在 Linux / macOS 上默认关是行为变化:原先一律开环回 TCP,这个端口在那两个平台上只是多一个本机别的进程、别的用户够得着的入口。
  维护者 2026-10-10 确认这些默认值保持,每个 SSH 会话一个显示默认关。
- **说明文字按平台写**:选内置引擎时的说明与显示号一行的说明,Windows 上写 `DISPLAY=localhost:N`(TCP),Linux / macOS 上写 `DISPLAY=:N`
  (Unix 套接字,TCP 默认不开)—— 原先一律写 `localhost:N`,照着做的 Linux 用户连不上。启动提示、按钮悬停里的显示地址同样按实际开着的监听给。

### 2026-10-10 第十三批(启动画面)

冷启动时主窗口要七八秒才出来,中间屏幕上什么都没有,用户以为程序打不开。启动画面在进程一起来就显示(Windows,`Program.Main` 里的原生窗口),
主窗口画完第一帧时淡出。交互见[交互与界面规格.md](交互与界面规格.md) §14.5。

| 设置 | 默认 | 取值 | 备注 |
| --- | --- | --- | --- |
| 启动画面 | 经典 | 经典 / 终端开机 / 船帆座 / 提示符 / 看板娘 / 不显示(`Appearance.SplashStyle`:`classic` / `terminal` / `constellation` / `prompt` / `mascot` / `none`) | 在「外观 → 窗口」里,下拉下方是按设置页里正在编辑的主题与强调色实时播放的预览;**下次启动生效**。只在 Windows 上出现:macOS 的 Dock 弹跳与 Linux 桌面的启动通知已经给了「正在打开」的反馈。认不出的值(手改的、更新版本写的)回到经典 |

- **数据库打开之前就要用**:启动画面比 SonnetDB 早好几秒,读不到设置。保存设置时把主题、强调色、界面语言与这一项镜像进
  `~/.velashell/startup.appearance`(几行 `key=value`),每次启动读到设置后也按它对齐一次(内容没变不写盘)—— 与 `render.mode` 同理。
  这一项参与云同步:它是偏好,不是机器相关的状态。
- `VELASHELL_NO_SPLASH=1` 关掉启动画面(自动化测试、录屏、排障用),优先于设置。

### 2026-10-19 第十四批(录制与会话日志的输出遮盖)

会话日志与会话录制存的是终端原始输出:`cat .env`、`kubectl get secret -o yaml`、`env | grep TOKEN` 的口令与令牌原样落盘。
在两者共用的挂钩点(`SshTerminalBridge.DataReceived`)与记录之间加一道遮盖(`SessionOutputMasker`),屏幕显示不经过它。

| 设置 | 默认 | 取值 | 备注 |
| --- | --- | --- | --- |
| 录制与会话日志中遮盖口令和令牌 | 开 | 开 / 关(`Security.MaskSecretsInCaptures`) | 在「安全审计 → 会话录制」里,自动录制下面;**对之后开始的录制与会话日志生效**。会话日志的开关在「常规」,遮盖两边一起管 |

- **遮什么**(大小写不敏感,宁可多遮):名字里带 password / passwd / passphrase / secret / token / api key / access key / private key / credential 的 `名字=值`、`名字: 值`(含 JSON、YAML 写法;名字与分隔符之间的 `grep --color` 颜色序列不碍事)只换值;`Bearer` / `Basic` 后面的凭据;PEM 私钥块正文(BEGIN / END 两行留着);自带前缀的令牌(AWS `AKIA…` / `ASIA…`、GitHub `ghp_…` 一类、Slack `xox?-…`、`sk-…`)。都换成 `***`。`PWD=` 这类当前目录不算。
- **按字节、按行**:每个字节按 Latin-1 映射再匹配,规则与替换都是 ASCII,UTF-8、GBK 原样往返;整行才匹配,最后不完整的一行只在正写到一个值的中间(或在私钥块里)时扣下等后半段(上限 4 KB),等输入的 `Password: ` 提示与全屏程序不换行的输出当场放出。停止记录时扣着的部分遮完放出。
- 不做的:按用户规则自定义(与「终端输出的自定义高亮规则」共用规则表,见 `feature-plan.md`);不在名字里、也没有前缀的裸值(比如单独一行的 base64)认不出来。
