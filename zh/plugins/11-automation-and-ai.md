# 11 · 自动化与 AI

两者都是"插件系统之上的应用层",共享同一原则:**宿主提供骨架与安全
边界,插件提供血肉**。

## 1. 自动化(S5/S6)

### 1.1 模型:规则 = 触发器 + 条件 + 动作

```text
触发器(Trigger)   会话连接成功 / 传输完成 / 定时(cron)/ 手动命令 / 插件自定义触发器
条件(Condition)   when 表达式(复用 03 §6 文法):主机匹配、时间窗、上次结果…
动作(Action)      内置动作(执行远程命令、上传/下载、发通知、写终端…)/ 插件自定义动作
```

规则本体由**宿主**持有(存储、调度、执行编排、日志),插件的参与方式
有两种,刻意分开:

1. **插件消费宿主事件自己干活**(07 §8 的 vela.events + 各能力):
   适合复杂逻辑,一切行为计入该插件的权限与审计。
2. **插件向规则引擎贡献触发器/动作**(manifest `contributes.automation`):
   用户在宿主的"自动化"页面里可视化编排,把插件能力当积木用。执行时
   宿主回调插件(`automation/evaluateTrigger`、`automation/runAction`),
   动作运行仍受该插件自身权限约束——规则引擎不放大权限。

### 1.2 安全边界

- 规则创建/修改只能由**用户在宿主 UI** 完成;插件只能"建议"规则
  (`SuggestRuleAsync` 弹确认卡片),不能静默创建——自动化 + 
  `remote.exec` 的组合杀伤力大,必须人在环。
- 每条规则显示将动用的权限汇总;含高敏动作(remote.exec/terminal.write)
  的规则首次运行前逐条确认,可勾选"此规则以后自动运行"。
- 规则运行历史(时间、触发原因、动作输出摘要、成败)持久化,失败可
  一键重跑;连续失败 N 次自动挂起规则并通知。
- cron 触发的插件唤醒走 `onSchedule` 激活事件,受"错峰 + 最小间隔
  1min"约束,防插件把宿主变成刷子。

### 1.3 内置动作(宿主自带,无需插件)

执行远程命令(exec 通道)、上传/下载文件、发通知、打开会话、写终端
(高敏)、运行本地程序(高敏,显式路径)。这让轻量自动化零插件可用,
插件负责长尾。

### 1.4 AI 插件的托管执行与恢复（SDK 2.1.0）

本节记录 AI 插件当前新增源码，与上方规则引擎、下方宿主 AI 网关的远期设计分开；不是把网关/通用权限系统宣告为已实现。

**托管命令**仅在应用运行期间保存，不做断线/重启恢复：

| 工具 | 参数与行为 |
| --- | --- |
| `run_command` | `timeoutSeconds=0` 默认无执行死线（显式值上限 86400）；`waitSeconds=2`、最大 10，仅短等窗口，到期返回 running/taskId，不杀命令；`monitoring=false`；`elevated=false` |
| `run_on_sessions` | 最多 16 个目标排入共享 4 流槽位，未开流项取消后不再启动，不直接撞宿主并发上限 |
| `task_status` | `taskId`、`cursor=0`，返回状态及增量输出 |
| `task_wait` | `taskId`、`waitSeconds=2`、最大 30、`cursor=0`；等完不代表执行死线，也不取消命令 |
| `task_cancel` | 请求取消本轮任务；清理不会因读取 scope 已撤销而被阻挡 |

状态为 Starting / AwaitingUser / Running / Succeeded / Failed / Cancelled / TimedOut / Unknown。普通结果保留 stdout、stderr、退出码、超时/截断信息；sudo 是 `combined`，保留原始换行/CR 分片而不伪造 stderr。运行后取消无法确认远端停止时为 Unknown，`cancellationRequested=true`、`remoteStopConfirmed=false`；两种例外记为 Cancelled（同样 `remoteStopConfirmed=false`，但不暂停本轮）：提权命令还停在审批/认证阶段、用户命令尚未报告启动时被取消，以及显式监控任务被 `task_cancel` 点名取消（这是结束它的正常方式；随整轮 Stop 连带取消仍为 Unknown）。未开流取消为 Cancelled 且已确认未启动。SSH 断线、sudo Exited 缺退出码等为 Unknown；已启动 TimedOut 且无停止确认也阻断本 run 后续自动工具副作用，绝不由框架重跑。认证取消/失败/不支持明确表示用户命令未启动，不自动降级普通执行。

每 run 同时保留最多 128 个任务；满额时回收已收尾且终态已交付的任务，Unknown 与未确认停止的 TimedOut 不回收（它们是本轮的停止边界）。输出是线程安全有界队列（32K 字符、256 条、每条最多 4096 字符；超长的一段按序拆成多条，不截断），用 `NextCursor` / `EarliestCursor` / `OutputTruncated` 标出超限被挤出的早期输出。taskId 只在创建它的 run scope 可读，绑定入口/对话/固定 sessionId，不跨聊天或 MCP 客户端。启动、查询、完成重验会话 scope；当前缓存与撤权边界见 [安全 §1.1](12-security-threat-model.md#11-此次-sudo-与-ai-托管执行的实际边界sdk-210)。

命令必须以前台进程留在托管通道。不会解析/改写任意 shell 的 `&`、nohup、daemonize，自行脱离的进程不受监控，父进程退出不能证明它完成。显式 `monitoring=true` 的无限日志流仅本地等退出或 Stop，不自动唤醒/轮询模型。

**提权是两层明确意图。** `elevated=true` 传不含 sudo 包装的实际命令，整条 root 范围包含管道和重定向；插件 Ask/ReadOnlyAuto 独立审批、不记首词批准，Bypass 只跳插件卡片，不能跳过宿主逐次可信确认（NOPASSWD 同样确认）。MCP 无 Handler 时 Ask/ReadOnlyAuto 拒绝，Bypass 可请求桌面确认。密码不经过插件或模型；不是用户终端自动填充。详见 [能力 API §3](07-capability-apis.md#3-velaremoteexec--远程执行s5s6)。

**拒绝是运行级停止边界。** 插件审批返回 false/缺少 Handler，或宿主返回 AuthenticationCancelled（含拒绝 root 确认/取消密码），都会标记当前 run 已拒绝；模型请求前、工具调用前及后台终态续接检查后以 `ExecutionDenied` 强制暂停，桌面/Bridge 显示本地化暂停原因，不依赖模型遵守“不要重试”字符串。桌面/Bridge 新用户轮次会创建新 run，不能在已拒绝的原 run 内继续副作用。对外 MCP 是例外：每客户端 McpToolHost 仍只有一个固定 scope（后台任务才查得到），但拒绝只是那一次调用的结果，不封住这条连接；后续工具照常可用（例如只读放行挡下一条写命令后仍能 `list_sessions`），停不停由 MCP 客户端决定。

**审批挡位**（2026-10-25 起收紧）：「只读自动」只放行形状确定、不改东西的 `run_command` —— `sudo …` 一律照问，`env` 不在名单里（`printenv` 在），切词认空格与制表符；
`curl` 只认把显式 `http://` / `https://` 地址 GET / HEAD 到标准输出的那几个选项，写文件、上传、发数据、换方法、自定义请求头、读配置文件、非 http(s) 协议都问；
`wget` 默认落盘，只认 `-O -` / `-qO-` 与 `--spider`；名单里另有十几个带参数就改状态的命令按参数判（`ip` 只认 show / list / get，`route add`、`ifconfig eth0 down`、`mount -a`、
`hostname x`、`date -s`、`dmesg -c`、`journalctl --vacuum*`、`ss -K`、`rg --pre`、`bat --pager`、`less +!cmd` 等都问），这些命令的参数里出现引号、反斜杠、`$`、通配或花括号就不再猜 shell 会展开成什么、照问。
外部 MCP 服务器的工具一律走审批（`readOnlyHint` 只影响重试），审批的回调与挡位**每轮一份**（`McpApproval` 由调用方每轮传入）：IM 里几个聊天并发时各问各的，不串到别的聊天，
也不因为另一个聊天是「全部自动」就不问。插件自己的对外 MCP 服务在「对话」挡位**一个工具都不给**（`tools/list` 为空，initialize 说明提示切到计划或 Agent）。

**恢复的是模型步骤，不是整轮副作用。** 桌面聊天/Bridge 每会话串行推进，共享协调器；工具账本按 runId + CallId 复用同 id 同参的在途/完成结果，同 id 异参暂停，不把不同 id 的相同命令一概去重。工具帧只在完整 ToolCalls 步骤、参数完整验证后释放；未完成调用/推理不重放。每完成模型步骤与工具结果配对保留 checkpoint，部分正文以明确本地化续接边界保留，不承诺无法证明的无缝去重；断线前只收到空白时原样重发，不送只含空白的 assistant 消息，也不留续接边界。参数绑定错误（缺必填参数、JSON 值转不成参数类型，工具体尚未运行、没有副作用）作为工具错误交还模型改正后重调，单次不暂停，改两次参数再调对不受影响；但连着三步调了工具却一个都没真跑（参数绑定失败，或同 CallId 只交回账本里的旧结果）就以 `NoProgress` 暂停。其它工具失败仍暂停且不自动重试副作用。

正常结束却只有 role/usage/空白的模型步骤也进入恢复；正文、标准/原始思考及完整工具调用不算空。有可见正文（且这一步没有工具调用）的输出上限 / 内容过滤 / 拒绝收尾**照常完成**（2026-10-25 起）：桌面面板挂一张警示色提示卡、Bridge 在回复后附一句，不报错、不换站、不切回原站，记作健康成功；一字未吐的照旧报错、不重试、不换站；错误内容不按空回复重试；Responses 的 `response.failed`（适配器给的是一帧空更新）按服务端原话失败 —— 此前先吐了半截正文的被记成成功、解冻冷却，一字未吐的被当成空回复重试、原话丢失。工具调用之后的最终一步空答补一句「请继续」（只进那次请求、不进历史）重试**一次**，仍空则照常收尾、附说明，不记失败、不冷却，空步骤不进历史。空步骤与瞬时网络/429/适当 5xx 共用每步骤最多 2 次恢复预算（默认 400/800ms，尊重可取得的 Retry-After；超过 120 秒以专属原因暂停，不提前重试，也不先提示「正在重试」或「达到执行预算」；暂停仍带着原始 429 / 503，桌面面板首步照常据此换 Key 或故障转移），每次真实请求经 Steering 复验账号/凭据，取消/拒绝/确定性错误不重试。UI 25 步、Bridge 20 步仅是显式批次边界，沿用同一工具账本与 checkpoint 自动续接，不撤掉工具，也不要求逐批确认；不再设置累计 100 模型步骤、200000 输出 token 或 8 批次硬上限。批次提示仅显示实际编号，不显示虚假的总批数；后台任务完成唤醒不增加批次编号。上下文占比只表示一轮里最后一次请求的输入相对模型窗口的大小（不是多步一轮各步之和），不是执行进度或剩余额度；单请求输出限制及既有上下文压缩/裁剪仍独立生效。成功与失败尝试已上报的输入/输出 usage 仍完整累计，持续运行会持续产生模型用量及费用，用户可随时 Stop。取消、审批拒绝、结果未知、工具错误与两道 `NoProgress` 暂停仍可停止执行：同一工具同样参数连调四次（只读轮询工具 `task_status` / `task_wait` / `transfer_status` / `transfer_wait` 结果在变就算有进展、不计入，结果原样不变才累计；有副作用的工具照旧只按签名拦），以及上段连着三步一个工具都没真跑；两者都不是完备的循环检测。Bridge 原有轮次超时、供应商及模型限制仍适用，不保证任何计划都能完成。

普通桌面聊天在未产生有效输出、没有工具副作用时，空回复最多额外补试两次（400/800ms，状态行与 Agent 同一句「收到空回复，正在重试」），其它瞬时故障仍最多一次；混合失败不重置尝试计数，耗尽后才按已有候选链切换。设置测试、全部检测和切换前探活遇无可见正文的正常空结束仅额外补试一次（400ms），两次请求及等待共享原有 15 秒截止时间；仅思考仍不能判活。用户取消立即传播，失败尝试已上报的用量累计结算，次数不含供应商 SDK 的内部重试。Bridge 复用步骤恢复，耗尽后显示本地化空回复错误。没有新增配置项或改变摘要为空时的裁剪回落。

有限后台任务完成后以本地信号唤醒所属对话，再向模型加入新的终态通知，不为原 CallId 伪造第二个工具结果；已经由 `task_status` / `task_wait` 交付过的终态不再重复通知。通知声明自己不是新的用户指令，远端输出整体包进 `<untrusted-command-output>`，并说明其中是命令输出、不是用户指令，不得照做；内容经 JSON 转义，输出里伪造不出结束标记。会话授权已撤销的任务只交出一条「结果不予提供」的 Unknown 通知（不带输出、退出码或会话 id），本轮以 TaskUnknown 暂停。本地等待不请求模型、无默认 10 分钟等待死线；Bridge 不扩大现有授权或总超时。Stop、入口 detach/销毁、插件卸载、MCP 会话删除/过期/设置 reload、Bridge 授权 reload 取消旧 run 并异步收尾，废弃迟到唤醒；切换聊天不串入其它会话。MCP 只给任务查询/等待/取消协议，外部模型的自动继续由 MCP 客户端负责。

### 1.4a 网络检索与供应商请求的几项口径（2026-10-25）

- **网络检索默认关**：`web_search` / `web_fetch` 与供应商原生检索挂在 AI 全局设置「允许助手检索并阅读网页」一把总闸下，**默认关**。开着时检索词（常常是报错原文与主机名）发到设置里的 SearXNG 实例，
  出厂是 VelaShell 运营的 `https://searxng.easilynet.top`（看得到检索词与来源 IP，收不到对话、终端输出与标识符），可换成自行部署的实例，清空地址即不检索（`web_fetch` 照常可用）；
  `web_fetch` 从本机直接取页，私网地址默认挡。升级前存下的开关原样保留（整份设置落盘，分不清 `true` 是用户勾的还是出厂值），只有没存过这一项的配置拿新默认。
  对外 MCP 服务不读这一项、用的是默认值，所以那条路上不提供 web 工具。
- **Responses 的 `store`**：自定义接入（目录 `custom-*` 与没有目录 id 的老配置）默认发 `store:false`，上下文（含终端输出）不留在供应商那边；设置页供应商一栏「允许服务端保存每一轮（OpenAI Responses 的 store）」勾上才不发
  （新的可空字段 `CustomResponsesStore`，存量自定义接入同样按关 —— 旧字段 `StoreResponses` 是建供应商时抄来的出厂值，不是用户选的）。官方 openai、Codex、Azure 等具名目录项照旧以目录为准。
- **Anthropic 的模型清单请求**与聊天请求对齐：同发 `anthropic-version: 2026-10-21`（此前清单请求停在 2023-06-01），Key 走 `x-api-key`、令牌走 Bearer。
- **root 确认框**：宿主的提权确认框弹出后「批准」先灰约 0.6 秒（从窗口打开起算），取消随时可点，回车与初始焦点仍在取消上。

### 1.5 AI 插件设置页的模型列表

设置页左栏的供应商模型列表默认折叠，与模型数量无关；供应商行仍显示模型个数。打开设置时，若当前活跃模型所属供应商处于折叠状态，则选中供应商行，不自动展开；若已保存为展开状态，则仍选中活跃模型。聊天使用的模型不变。点击供应商行或按 → 展开、← 折叠，手动选择会保存；显式新增或导航到模型时仍显示该模型供编辑。

### 1.6 AI 文件上传与进度（SDK 2.1.1）

本节专指 `upload_local_file`：把用户**本机**文件经 SFTP 上传到已授权的 SSH 会话。它不是把任意大文件塞进模型上下文，也不改变聊天附件或 IM `send_file` 的平台上限；下载双入口的大小限制移除另见 §1.7。上传不设 AI 固定文件大小上限，仍受本地/远端空间、权限、协议及连接状态约束。

| 工具 | 行为 |
| --- | --- |
| `upload_local_file` | 本地绝对路径、远端绝对文件路径、可选会话；`overwrite=false` 默认不替换已有文件，显式覆盖也需审批。返回结构化任务快照，不让一次调用等待整份大文件 |
| `transfer_status` | 按本轮 `transferId` 查询状态、64 位已传/总字节、速率、ETA、执行代次与能否安全恢复 |
| `transfer_wait` | 短等，默认 2 秒、最大 30 秒；等待到期不取消上传 |
| `transfer_cancel` | 指定任务及预期执行代次，请求取消；“已请求”不代表远端已停止 |
| `transfer_resume` | 仅当宿主明确返回 `CanResume` 时，重新审批并验证当前目标连接后恢复，不自动从头上传 |

快照中的 `transfer_id` 关联后台任务，`generation` 区分恢复后的执行代次，`sequence` 用于忽略迟到进度。`stillRunning` 与明确状态共同判断是否还在执行；字节到齐仍可能等待验证/提交，不得把百分比满格当成成功。唯一成功终态是 `Succeeded`。失败、取消及 `Unknown` 不自动重传；提交回执丢失时必须先消歧，不能以另一个任务 id 再次覆盖目标。取消、到期、断线或插件停用之后，宿主最多再等 30 秒让后端真正停下（SFTP 取消要先排空已发出的写入、再等 `CLOSE` 应答）：停下了才算确认停写、清掉远端临时文件，没停下记 `Unknown`。SSH 断线的终态是 `Failed` / `session-disconnected` 而不是 `Cancelled`（`Cancelled` 表示有人不要这次传输了，调用方不该再发）：只有确认停写、目标确认没写入（`destinationCommitConfirmedAbsent`）才落到这一档，模型在重连之后重新发起是安全的；提交已经发出、没等到应答时的断线仍是 `Unknown` / `commit-unknown`。

宿主持有已批准上传，调用方请求和模型等待与传输寿命分离。查询/短等待不需要保持模型生成连接，更不靠不断请求模型刷新进度。AI 按所属 owner/run 隔离任务，查询及完成通知复核会话授权；撤权后的路径和结果不再提供。工具启动回执与最终完成通知分开，不能为同一 CallId 发送第二次工具结果。外部 MCP Agent 通过状态/等待工具主动获取进度，服务端不主动唤醒外部模型。

上传按流处理，不把整个文件装入内存。父目录别名解析后，按**文件身份**核验打开的源句柄（Windows 卷序列号 + 文件 id，Linux / macOS dev + inode），核验那一端不经任何链接走到；映射盘、subst 盘、硬链接名、大小写或 Unicode 规范化不同的写法都按同一个文件放行（2026-10-25 起；此前逐字比句柄的最终路径，这几种写法都被误拒）。审批显示解析后的路径；文件本身的符号链接不支持。Windows 持有拒绝写入/删除共享的源句柄；Unix 不把 FileShare 当成禁止其它写入者的保证，Linux / macOS 在传之前给源文件做一份宿主私有的快照，并与源句柄逐字节核对摘要。快照放在**源文件所在的卷**上（2026-10-25 起；此前一律拷进系统临时目录，/tmp 是 tmpfs 时几个 G 的快照直接吃内存）：源目录里的隐藏文件 `.vela-snapshot-<48 位十六进制>`，建好即删掉名字，靠打开着的描述符存活，宿主中途崩溃也不留明文副本。卷支持写时复制（Btrfs / XFS / bcachefs 的 reflink、macOS APFS 的 clonefile）时快照是瞬间完成、不占空间的克隆；否则需要约一个源文件大小的空间，宿主先查剩余空间，不够「文件大小 + 64 MiB」就在传之前以 `insufficient-space` 失败（说明需要多少、还剩多少；没传任何字节、目标确认没写入）。源目录不可写时退到系统临时目录，同样先查空间。建快照前清扫同目录崩溃遗留的快照（口径同下载临时文件）。准备阶段不会冒充已上传字节。传输完成后优先使用服务端 SHA-256，纯 SFTP 账号不支持服务端摘要时按流回读校验，可能增加约一个文件大小的下载流量；校验/提交期间仍是运行中，速率和 ETA 未知时不显示为零秒完成。当前宿主不能可靠核验重连身份与命名空间，因此明确 `CanResume=false`、恢复报不支持；没有断点自动重试或跨应用重启恢复。

桌面工具卡显示进度条、已传/总量、百分比、速率、ETA 和阶段，未知总量/准备/校验阶段使用不确定进度；失败、取消和未知不显示为绿色成功。切换聊天不改变所属任务卡；模型 Stop 只结束模型等待，原卡仍可显式取消。关闭/销毁面板、插件停用、MCP 会话删除/设置重载或 Bridge 授权重载走显式清理，不保证远端停止确认。严格 run 隔离保持不变，新的模型轮次不能查询旧轮次任务，旧卡持原 scope 管理已批准上传。

Bridge 只在没有其它命令/监控任务的独立上传本地等待期间暂停剩余轮次预算，返回模型请求时恢复原剩余预算；这段等待同时让出桥接的总并发名额（同一聊天的串行闸照旧握着），下一次调模型之前排队取回同一把闸、取回之后才恢复预算 —— 宿主确认没有时限、大文件能传几个钟头，占着名额会把别的聊天堵在闸前；纯命令/监控仍遵守原超时，人工 Stop/生命周期取消始终有效。模型 Stop 后上传继续时，Bridge 保留本地观察并发送带任务标识的最终状态，不自动重启模型。外部 MCP 活跃传输不因无工具请求被两小时空闲回收，已完成且不再活动的任务不会无限阻止回收。

AI 审批与宿主上传确认是独立两层：宿主在读取文件内容与上传前，逐任务确认来源插件、真实目标会话、本地源、**文件大小**、远端路径和覆盖策略；只允许当前任务，不继承终端/开会话授权，不提供“始终允许”。AI `Bypass` 不能跳过宿主确认；无授权闸、提示器或可用桌面窗口时拒绝。任务等待确认时仍走独立生命周期，不占用长 RPC。插件管理页撤销会取消该插件待批准及活动上传的租约，提交前再次检查；撤销后不再提供新的路径与结果，但不抹除此前已知输入或历史，也不保证已提交文件被回滚。宿主明确拒绝当前上传时，桌面/Bridge 的当前 run 强制 `ExecutionDenied` 暂停，不继续请求模型寻找替代路径；外部 MCP 仅该次调用失败，不封住整个客户端固定 run。停止（面板「停止」、换会话、关面板，IM 的 `/stop` 与轮次超时）或本轮任何一次拒绝（插件审批卡、宿主确认框、root 认证）之后，本轮还在 `Approval` 阶段的上传 / 下载（含模型发起的下载）一并撤掉：排在确认闸后的随取消撤下，已弹出的确认框随之关掉，以 `Cancelled` 收尾、什么都没写；停止之后才到的启动回执一到就撤（2026-10-25 起）。已批准的照常传完，正常答完不撤，对外 MCP 连接里的单次拒绝也不撤。宿主撤销后无法读取结果时按 withheld/`Unknown` 安全暂停，不当作暂时网络错误反复读取。这是新上传 API 的专用强制点，不代表其它文件能力或通用 `remote.files`/本地文件 Broker 已实现。底层协议和状态定义见 [SDK §3.3b](../sdk/sdk-reference.md#33b-独立上传任务sdk-211) 与 [IPC §7.2](05-ipc-protocol.md#72-独立上传任务sdk-211)。

### 1.7 AI 双入口后台下载（SDK 2.1.2）

**下载契约已随 SDK 2.1.2 正式发布到 NuGet.org。** 宿主 src / tests 中央包、AI 显式包依赖与 `minSdkVersion` 均已升到 2.1.2（`apiLevel: 2`），不使用本地包或临时包源。下载在 Windows 与 Linux / macOS（x64、arm64）宿主上可用：Windows 与 Linux 的提交用例实际跑过（Linux 在 WSL Debian 的 ext4 与 tmpfs 上），macOS 只经 CI；仍未宣称真实 SSH / GUI 整链验证通过。

- **模型入口** `download_remote_file` 移除原 32 MiB 固定判断，改为 `StartDownloadAsync` 后台启动；`overwrite=false` 默认不覆盖，同名失败，明确覆盖仍须审批。给出的 `local_path` 与上传同一把尺：必须是完整绝对路径（Windows 上 `C:foo`、`\tmp\x` 这类会按进程当前目录补全的一律拒绝），审批之前规范化，审批卡与宿主确认框写的就是实际落点。返回结构化任务回执，含方向 Download、状态/阶段、64 位字节数、速率、ETA、代次与停止确认，不等待整文件完成。
- **远端链接入口**移除原 64 MiB 固定判断。选择保存路径后，创建绑定点击时原对话/会话的独立 scope 和普通进度卡；不是模型工具调用，不伪造模型回执或完成通知。选择器不提前截断最终目标，也不能代替逐任务宿主审批；选到已有文件时由系统保存框先确认替换，确认后按 `overwrite=true` 请求宿主确认（确认框照实写明替换）。切换聊天不串进度，关闭面板纳入 `CloseTransfersAsync`，迟到启动也清理。
- 两入口共用宿主任务、限速和资源预算，并非无限资源：上传下载合计每插件 4 实际传输、32 活动/排队、1024 生命周期回执；回执额度用尽或操作身份冲突是交给宿主之前的拒绝，工具回「启动前被拒」，不算结果未知，也不把整轮停成 TaskUnknown。会话授权、模型上下文/小文件读取、聊天附件及 IM 平台文件上限继续保留。

`transfer_status` / `transfer_wait` / `transfer_cancel` 同时适用于上传和下载。短等待默认 2 秒、最多 30 秒，到期或取消请求仅结束本次等待；下载本身默认无执行死线。显式取消针对预期代次；下载 `CanResume=false`，Unknown 不自动重下。用户工具卡按方向显示上传/下载、Approval/Transfer/Verification/Commit、字节、百分比、速率、ETA与取消；未知总量不编造百分比，满字节或校验/提交中不显示成功；工具没拿到快照（被拒、启动前挡下、回执丢失）时卡片标警示，不打「完成」的勾。`Succeeded` 要求最终提交确认；Unknown/TimedOut 且未确认停止不等于副作用结束，不合作后端实际退出前仍占槽并持有句柄。停止宽限期同上传，30 秒。

模型进度由本地观察刷新，不为每一帧请求模型或追加上下文；观察连续失败三次只把这一项报为「进度不可确认」（算结果未知），之后按 1 秒起翻倍、封顶 30 秒退避继续盯到宿主终态、撤权或插件停用，拿回新鲜快照即撤下这份不确定。协调器每任务终态仅通知一次；status/wait 已消费终态就不重复通知，`transfer_resume` 只查看原任务、不算消费，续不上时那份终态照常由完成通知交给模型；不为原 CallId 伪造第二次工具结果，路径/错误仍按不可信数据处理。严格 owner/run 隔离保留。Stop 只停止模型等待，任务/本地观察仍可继续，原卡可显式取消；关闭/销毁面板、插件停用、MCP 会话删除/设置重载和 Bridge 授权重载显式清理。Bridge沿用纯传输等待暂停剩余预算、让出总并发名额（见 §1.6）与Stop后本地观察/最终状态行为，不自动重启模型；命令/监控预算不扩大。外部 MCP 必须主动 status/wait 查询，服务端不承诺唤醒外部模型，活跃传输仍防空闲回收。

下载宿主许可独立于上传/终端/开会话，逐任务显示插件、真实会话、远端源、最终本地目标及覆盖策略；AI Bypass不能绕过，无提示器/窗口则拒绝。撤权取消待批准/活动租约，提交前重验，后续元数据脱敏，清理取消仍可进行；不回滚已提交文件。`send_file` 不读取已登记但尚未成功提交的下载目标（也不借同名旧文件外发），审批前后各核一次，审批期间文件大小或修改时间变了也不发；既有目录限制、外发审批及IM平台上限不变。

**安全提交支持 Windows 固定本地 NTFS 与 Linux / macOS（x64、arm64）的本地文件系统**：审批之前钉住目标目录链（Windows 逐段持有不共享删除的祖先目录句柄，Linux / macOS 从 `/` 起逐级不跟随链接地 `openat`、只留父目录 fd），独占随机临时文件，并相对钉住的父目录原子提交，祖先事后被改名也落不到别处；默认无替换，明确覆盖不先删目标，时间戳写任务持有的临时句柄。UNC、9p / SMB / FUSE / NFS 等其它文件系统在审批前明确拒绝，不支持的后端同样明确拒绝，都不回退直接写最终路径。按实际本地写入计数，校验长度、前后元数据与可用摘要，纯 SFTP 不强求 exec/默认二次整文件下载；这些检查不是远端原子快照保证。详见 [SDK §3.3c](../sdk/sdk-reference.md#33c-独立下载任务sdk-212)、[能力 API §2.2](07-capability-apis.md#22-独立下载任务sdk-212) 与 [安全 §1.2](12-security-threat-model.md#12-后台下载的实际安全边界sdk-212)。

### 1.8 AI 插件的供应商凭据与故障转移（2026-10-25）

1. **凭据不跟着换地址**。供应商的 Base URL 换到另一个 origin（协议、主机或有效端口不同；只改路径、大小写或写出默认端口不算）时，保存前弹独立的确认框（不再是同一个按钮点两下；
   盖在插件视图里的遮罩 + 卡片，默认焦点在「取消」，Esc 取消，Tab 只在框内循环，点遮罩不算任何选择）：
   - 填 Key 的供应商：清掉主槽、补充槽与没填覆盖地址、自带 Key 的模型的 Key（框里点名这些模型），补充槽与当前槽复位；同一次保存里新填的 Key 落进主槽。按钮「清除并保存」；
     取消时状态行写「已取消，什么都没改」，草稿留着。
   - 订阅登录的供应商（自定义 OAuth、Azure 等）：退出登录（删令牌、推进登录代次），同样清掉跟着旧地址走的模型自带 Key；框里说明正在用这家的对话与 IM 机器人会中断。
     按钮「退出登录并保存」；保存后到「管理登录」为新地址重新登录。在途的请求复验时拒绝发出，已经在路上的那一条照旧打旧地址、带旧地址的令牌（不泄露，只是这一轮作废）。
   - 确认之后要清的有了变动（别处又存了一把、同一个槽换了值、换过一次登录），提交时再拒、换一句话再问，不会把框里没列的一起清掉。
   - 地址改了还没保存时，「测试」不带已存的 Key 或登录：填 Key 的只带表单里新填的那把；订阅登录还登着就请用户先保存、在新地址登录后再测。
   - 目录页给配齐了的订阅行不摆地址框，换地址只在设置页。
2. **模型覆盖地址跨源必须自带 Key**：覆盖基地址与供应商不同源的模型，供应商的 Key（主槽、补充槽）一把都不跟去；要 Key 就勾「此模型使用独立的 API Key」。
   此前跨源时借第 1 把 Key —— 供应商换源之后为新地址填的主 Key 会被发往旧覆盖地址。设置页供应商页点名这类模型，模型页说明请求不带 Key，
   并提供「沿用供应商的第 1 把 Key」（勾上自带 Key、把主槽此刻的 Key 填进表单，点保存才生效）。订阅登录的供应商不在这条口径里（令牌的适用范围由签发方定）。
   供应商自己的地址解析不出 origin（空着或写错）时照旧只用主槽。模型这一层把覆盖地址改到别的源时，模型自带的 Key 照旧跟去（留待定）。
3. **Anthropic 环境变量只给官方主机**：Anthropic 协议没填 Key（供应商没有 Key、模型勾了自带 Key 却没填、换源清了 Key 还没填新的）时，只有基地址是 `https://api.anthropic.com`（默认端口；
   大小写、尾斜杠、`/v1` 都归一）才使用本机的 `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN`（只配环境变量直连官方仍可用；两个都设时 SDK 只认前者）；
   别的地址两者一起显式置空、都不带（明文 http、别的端口、带官方名字的别家主机都不算官方）。
4. **故障转移的候选**：链为空（或全是已删模型）时自动发现同目录、同型号的接入，但**默认只在同一个供应商实例、同一份凭据下换**（换了协议或地址的同一型号）；
   要换到同目录的其它账号（另一个实例或模型自带的 Key，比如公司与个人的 Copilot），在全局设置「故障转移」一节勾选「链为空时，也自动换到同目录的其它账号」
   （`AiSettings.AutoFailoverAcrossAccounts`，默认关；整段对话会发给那个账号、记在它的账上）。显式排进链的条目不受这个开关影响。存量配置升级后为关。
5. **冷却**：一把 Key 回 401（Key 本身被拒）冷却整把 60 秒，换哪个模型都绕开；回 403 / 429 只冷却「这把 Key 用在这个模型上」，同一把 Key 下的兄弟模型故障转移时照常探活。
   这把 Key 在任何模型上成功都解开整把的冷却；只对某个模型的冷却要在那个模型上成功才解。设置页 Key 行的「冷却中」只反映整把。
6. **空主槽**：移除第 1 把 Key（只清主槽的机密）而补充槽还在时，列表照样显示空着的「第 1 把 Key」（「空着，点铅笔填回」），不能显示、移除或检测，点铅笔填好、保存即落回主槽；
   「检测全部」只测有 Key 的行。

新增的全局设置只有 `AutoFailoverAcrossAccounts`（全局设置 → 故障转移，默认关，随「保存」生效）。

### 1.9 桌面对话作图、改图与剪贴板图片（2026-10-27）

- 全局新增 `AiSettings.ImageModelId`（默认 null 关闭）绑定已有图片模型。默认模型被删除或不再是图片模型时显示失效并拒绝调用，不自动回落其它服务。聊天顶栏模型不切换，支持工具调用的聊天模型按上下文整理独立提示词，使用 `generate_image` / `edit_image`；工具没有 URL、Key 或任意路径参数。普通聊天只提供图片工具、不开远程操作工具；计划模式不提供图片工具，Agent 模式可用。自定义提示词保留，但会补充已配置图片能力及会话图片 ID。
- `OpenAiImages` 复用现有 OpenAI SDK、凭据来源、origin/OAuth 守卫、附加头，文生图走 `/images/generations`，编辑走 `/images/edits` multipart（最多 3 张 PNG/JPEG/WebP，每张 20 MiB 内）。聊天模型只发整理后的提示词和选定参考图给图片服务，不把整个上下文直接传入图片接口；这些内容另经图片供应商处理和计费。Ask / ReadOnlyAuto 显示实际模型、地址、参考图数量与提示词审批，Bypass 跳插件审批。取消/拒绝后停止；图片 SDK 不重试，工具错误暂停本轮，已完成工具身份由原工具账本复用。每轮最多 4 次图片调用。旧的直接选择图片模型文生图入口兼容保留，已知名称自动路由和不收费探活边界不变。
- `ConversationImages` 用会话私有 ID 表管理用户附件与生成图，模型不可凭文件路径读取本机图片，也不能引用另一段对话图片。输入与生成图存 `DataDirectory/generated-images`，`ChatTurnMeta.Images` 只记录随机文件名/媒体类型；历史恢复同时恢复引用与显示，缺文件不使整段历史失败，旧历史兼容。生成工具结果只能解析本轮可信回执，不能把任意工具返回的路径当图打开。图片仍按签名、路径及 20 MiB 上限校验；删除历史不立即删文件。IM 桥接暂不注册图片工具，直接图片模型仍提示改用文本模型。
- Paste 优先把剪贴板位图编码为 PNG 附件，直到用户发送才外发；每条消息 4 件/每件 5 MiB、位图 2500 万像素上限不变，无位图回落编辑器原粘贴。可存档输入图获得图片 ID，后续编辑或历史恢复可引用；视觉聊天仍依赖模型能力。只接受接口直接返回的 base64 图片，不跟随供应商 URL；预览与保存按钮沿用原能力。
- 图片操作采用同格 Grid 叠放：右下角常驻两个独立34px圆形图标浮钮（Lucide `image-down` 保存 / `fullscreen` 大图），无文字或共用底板；仅圆形表面半透明、图标不降低不透明度，悬停表面加深、键盘焦点有独立圆环。按钮具备工具提示与辅助名称、跟随动态主题；保存保持原选择器与原始字节。大图按原始PixelSize/当前屏幕缩放计算100%（物理像素1:1），初始窗口按图片+标题/工具条/阴影余量计算并受当前屏幕工作区限制，超大图等比缩小完整显示、不放大小图。`ImagePreviewView`显示实际百分比，支持＋/−、100%、适应窗口、Ctrl滚轮与双击切换；适应模式随可用视口重算，手动放大后双向滚动。Esc/关闭退出；面板 Detach 或离开视觉树统一关窗并释放 Bitmap，打开失败与文件丢失不使对话崩溃。
- 输入语法分离：`@` 只选工具（`@imagegen` / `@imageedit`，本地筛选、无需 SSH），`#` 选远端文件（支持 `#"带空格路径"`、补全/芯片/整块删除/发送展开），`/` 只在输入开头列本地命令。文件不再接受旧 `@/路径`，不改写已有历史文字。工具提及在发送时展开为固定工具意图而非文件读取，默认图片模型/模式门禁与自然对话调用一致，输入菜单不请求供应商或产生计费。支持 `/clear` 新建但保留已存历史、`/resume` 历史选择、`/resume <ID>` 精确恢复或按标题筛选、`/help`；未知命令本地报错，忙态不切换对话，命令不作为模型请求。仅基础命名/语义对齐，不宣称完整 CLI 兼容。
- 本地 SDK generation/edit 报文、会话隔离、headless 当前聊天模型不变/图片显示/历史续图/计划隔离/失败不重发与设置 ID 回归可复现；不代表真实付费供应商、系统剪贴板或跨平台 GUI 验收。此实现只借鉴能力分层，未复制 cc-haha 源码或提示词。

## 2. AI 网关(S3,远期主线)

### 2.1 为什么是"网关"而不是"每个插件自带 SDK 调模型"

- **密钥归宿主**:用户在宿主设置一次模型提供方(Anthropic/OpenAI/
  本地 Ollama…)与 API key,密钥存 OS 凭据库,插件永远拿不到。
- **额度与审计**:按插件统计 token 消耗、限额、审计"哪个插件把什么
  内容发给了模型"——这对运维工具至关重要(终端内容可能含机密)。
- **一次接入,处处可用**:模型供应商演进由宿主消化,插件面对稳定的
  抽象接口。

### 2.2 接口形态(vela.ai,权限 `ai.invoke`)

```csharp
public interface IAi
{
    Task<AiModelInfo[]> ListModelsAsync(CancellationToken ct);       // 用户配置的可用档位(如 fast/balanced/powerful,不暴露密钥)
    IAsyncEnumerable<AiDelta> ChatStreamAsync(AiRequest req, CancellationToken ct);
        // AiRequest: 档位、messages、可选 tools(插件提供的工具回调经 RPC 回插件执行)
    Task<float[][]> EmbedAsync(string model, string[] inputs, CancellationToken ct);
}
```

- 工具调用(function calling)回路:模型请求工具 → 宿主经 RPC 调插件
  的工具实现 → 结果回模型。插件工具的执行仍受其权限约束(AI 不是
  权限旁路)。
- **数据出境提示**:插件首次把 `terminal.read` 获得的内容送入
  ChatStream 时,授权提示明确"终端内容将发送给 <模型提供方>";
  设置里提供"禁止任何插件向 AI 发送终端内容"总开关。
- 宿主侧实现建议直接采用官方 SDK против各供应商;本地模型经 OpenAI
  兼容端点接入,统一在网关内路由。

### 2.3 与自动化的合流

AI 动作("总结这次部署输出并通知我")= 规则引擎的动作调 ai.invoke;
AI 触发器(异常日志语义检测)= 插件订阅终端流 + 网关判定 + 触发规则。
两套骨架拼起来即"智能运维"场景,无需新机制。
