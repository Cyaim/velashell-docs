# 协作接入:IM 桥接与对外 MCP 服务端

> 归属:AI 助手插件(`plugins/VelaShell.Plugin.Ai`,id `velashell.ai`,随主程序发布)。
> 入口:命令面板 → **`AI: 协作接入`**。

这一页讲的是**让 VelaShell 的 agent 与人和其它 agent 一起干活**的两条路。它们方向相反,
但共用同一套安全观念(白名单、挡位、审批),所以配在同一页里:

| 方向 | 谁在用 | 形态 |
| --- | --- | --- |
| **往外** | 团队里的人 | 在飞书 / 钉钉 / Telegram / 企微里 @ 机器人,agent 在你已连上的 SSH 会话上干活,结果回帖到群里 |
| **往内** | 别的 agent | Claude Code / Codex 这类外部 agent 把 VelaShell 当 MCP 服务端调,用的是 AI 插件那套工具 |

**先明确边界**:桥接跑在**你这台机器上的 VelaShell 进程里**。VelaShell 关掉,机器人就下线
(可在 设置 → 常规 里开「关闭时最小化到托盘」让它留驻)。这不是一个部署在服务器上的服务。

---

## 一、IM 桥接

### 1.1 四个渠道,四种入站传输

| 渠道 | 入站方式 | 需要公网地址 | 能改已发出的消息 |
| --- | --- | --- | --- |
| 飞书 / Lark | 官方长连接(WebSocket) | 否 | 能(流式改同一条) |
| 钉钉 | Stream 模式(WebSocket) | 否 | 不能 |
| Telegram | Bot API 长轮询 | 否 | 能 |
| 企业微信 | 公网回调(本机 HTTP 监听) | **是** | 不能 |

前三家都是**从你的机器主动连出去**,躲在 NAT 后面也能用,不需要任何公网配置。
企业微信只有"平台把消息 POST 到你配的地址"一条路,所以它是唯一需要额外铺路的一家。

> **飞书的连接数限制**:一个应用最多 50 条长连接,而且同一个应用起多个客户端时平台按
> **集群**投递(随机挑一个),不是广播。**同一套应用凭证不要在两台机器上同时跑** ——
> 消息会随机落到另一台上,表现为"有时候不回"。

### 1.2 配置步骤

**① 拿凭证**(各家都要去自己的开发者后台建一个应用):

| 渠道 | 要填的 | 从哪拿 |
| --- | --- | --- |
| 飞书 / Lark | App ID、App Secret | 开放平台 → 凭证与基础信息 |
| 钉钉 | Client ID(AppKey)、Client Secret | 开发者后台 → 应用凭证 |
| Telegram | Bot Token | BotFather |
| 企业微信 | CorpID、AgentID、Secret、回调 Token、EncodingAESKey | 企业微信管理后台 → 自建应用 |

飞书还要在开放平台上做两件事,否则**凭证完全正确也一条消息都收不到**:
把「事件订阅」的方式改成**长连接**,并订阅 `im.message.receive_v1`;改完之后
**发布一个新版本**。这两条是接飞书最常见的翻车点。

**② 填进设置页并点 [测试]**。这一步是只读的(换一次令牌、查一次自身信息、
问一次长连接接入点),不发消息、不改任何配置。它会分别告诉你是凭证不对、
还是凭证对了但接入点被拒(那基本就是上面那两条没做)。

**③ 把机器人加进群**:

- **飞书**:客户端里 群设置 → 群机器人 → 添加机器人,搜应用名。
  (飞书**没有**"扫码把机器人加进群"的链接 —— `applink` 的 `client/app/open` 是打开小程序页面用的,
  纯机器人应用扫出来是"此页面无效"。)
- **Telegram**:测试通过后设置页会给一张二维码,手机扫一下直接进"加进哪个群"的选择界面。
- **钉钉 / 企微**:按各自后台的说明把应用可见范围放到目标群/部门。

**④ 授权这个聊天**。白名单为空时机器人**谁都不理** —— 这是安全默认,一个能在生产机上
敲命令的机器人不该因为被拉进某个群就开始听话。两条路,都不用手抄群 id:

- **配对码**:设置页点「生成」拿一个六位码,在要授权的聊天里发 `/pair 428913`。
  一次性、十分钟过期、猜错五次作废。
- **一键放行**:敲过门的聊天会出现在设置页的「敲过门的聊天」里,一行一个「允许」按钮。

> 配对码**只能把聊天加进白名单**,动不了挡位与审批 —— 它决定的是"这个聊天能不能跟机器人说话",
> 不是"能不能动服务器"。

> **你自己跟机器人的单聊也要授权。**机器人分不出私聊它的这个人是不是你 ——
> 同一个租户里任何人都能私聊它。单聊默认放行的话,等于全公司都能指使你的生产机。
>
> 另外,页首那个「启用 IM 接入」是**总开关**而不是"授权别人用":不勾就一条连接都不建,
> 飞书那边没有客户端在监听,你在单聊里发什么都收不到。一个人自用同样要勾。

**⑤ 绑一台服务器**:在聊天里发 `/sessions` 看有哪些连着的,再 `/use user@host:port`。
绑定存的是 `user@host:port` 而不是会话 id,所以断线重连、隔天重开 VelaShell 之后仍然有效。

### 1.3 在聊天里能做什么

群里 **@机器人** 再说话即可(单聊直接说)。斜杠命令:

| 命令 | 作用 |
| --- | --- |
| `/help` | 列出这些命令 |
| `/sessions` | 列出当前连上的服务器 |
| `/use <user@host:port>` | 把本聊天绑到某一台 |
| `/mode chat\|plan\|agent` | 换挡位(默认只能往低了调,见下) |
| `/new` | 丢掉上下文,开一段新对话 |
| `/stop` | 中止正在跑的那一轮 |
| `/status` | 看本聊天的当前设定 |
| `/pair <码>` | 授权本聊天(未授权时可用) |

### 1.4 安全模型

这几条是**刻意设成这样**的,不是默认值凑巧:

- **白名单为空 = 谁都不理**。第一次被 @ 时机器人回一句(且只回一句)带聊天 id 的提示 ——
  沉默更"安全",但会把用户卡在第一步:群 id 在飞书/钉钉的界面上根本看不到。
- **默认挡位是「计划」(只读)**,比聊天面板保守一档。面板前面坐着人,点一下就能拦住;
  IM 那头的发起人可能在地铁上。
- **`/mode` 默认只能往低了调**。否则白名单里任何人一句话就能把只读桥接变成能敲命令的,
  设置页那个"只读"就形同虚设。要放开,去设置页勾「允许在聊天里用 /mode 提高挡位」。
- **审批走文本回复**(`y` 放行 / `n` 拒绝 / `a` 本次对话内总是放行),超时按**拒绝**处理。
  没用交互卡片是因为四家的卡片回传各有各的坑(飞书的 `card.action.trigger` 在长连接上
  并不总能收到),文本是唯一四家都稳的通道。
- **审批人可以与"能说话的人"分开配**:值班的谁都能问,重启服务得管事的点头。

### 1.5 企业微信:为什么它要多一步

企微只能往一个**公网可达的回调地址**推消息,而本实现**只绑 `127.0.0.1`**,
不提供绑 `0.0.0.0` 的选项 —— 把一个能在生产机上敲命令的回调口直接开到公网,
不该是一个勾选框能决定的事。

让它够得着的做法:在一台有公网的机器上用 nginx 之类把 HTTPS 落到某个端口,
再用**反向隧道**把那个端口转发到你本机的监听口。VelaShell 自己就有远程端口转发
(会话 → 隧道 → 远程转发),转发目标填 `127.0.0.1:<设置页里的回调端口>` 即可。

## 二、对外 MCP 服务端

让 Claude Code / Codex / Cursor 这类外部 agent 反过来调用 VelaShell 的工具:
枚举会话、读终端、跑一次性命令、读写远端文件。工具就是 AI 插件 agent 模式那一套,
外加一个 `use_session` 让外部 agent 挑机器(先 `list_sessions` 看有哪些)。

### 2.1 接进去

设置页勾上开关,把「接入方式」那一栏整段复制走。Claude Code:

```bash
claude mcp add --transport http velashell http://127.0.0.1:8391/mcp \
  --header "Authorization: Bearer <令牌>"
```

其它客户端用通用的 `mcp.json` 片段(设置页里第二段):

```json
{"mcpServers":{"velashell":{"type":"http","url":"http://127.0.0.1:8391/mcp",
 "headers":{"Authorization":"Bearer <令牌>"}}}}
```

### 2.2 为什么是 HTTP 而不是 stdio

stdio 的前提是"客户端能把服务端拉起来",而 VelaShell 是一个**已经开着的桌面程序** ——
外部 agent 拉不起它,也不该为此再拉起第二个。HTTP 只需要在自己的 agent 配置里填一行地址。

### 2.3 安全

- **只绑 `127.0.0.1`**,不提供绑其它地址的选项;
- **每个请求必须带令牌**,令牌随机生成、不可关闭。本机监听不等于安全 ——
  同一台机器上任何进程(包括浏览器里的网页)都能往本地端口发请求,令牌是唯一的门。
  设置页可以随时「重新生成」(生成后记得同步改 agent 那边的配置);
- **默认挡位是只读**。开箱可用不等于开箱可写;
- **审批在这条路上没有界面** —— 外部 agent 跑在别的进程里,弹不出 VelaShell 的审批卡。
  所以「每次询问」在这里等于**一律拒绝写操作**。要让它能改东西,得显式选「只读放行」
  或「绕过审批」,这是一个明摆着的选择,而不是一个悄悄的默认;
- 可以用「允许操作的服务器」把外部 agent 限制在指定的几台上。

这一条**默认开**:只绑回环 + 强制令牌 + 默认只读,三条叠起来风险足够低,
而"默认关"带来的"装完还得先翻一页设置"是没必要的门槛。

## 三、已知限制

- **只能操作用户已经连上的机器**。`ISessionsApi` 目前只有 `ListAsync` / `GetAsync`,
  插件开不了新会话 —— 值班的人昨晚关了那个标签页,机器人就只能回一句"你先去连一台"。
  SDK 侧的契约(`ListSavedAsync` / `OpenAsync` / `CloseAsync`)已在路上,见
  [SDK 参考](../sdk/sdk-reference.md)的版本历史。
- **企业微信需要公网入口**(见 1.5)。
- **飞书的卡片按钮**未接:审批走文本回复。
- 桥接只处理**文本消息**;图片、文件、富文本暂不解析。

## 四、排障

| 现象 | 多半是 |
| --- | --- |
| [测试] 说"凭证 OK,但接入点被拒" | 飞书:事件订阅没改成长连接,或改完没发布版本 |
| 群里 @ 了没反应 | 这个聊天不在白名单(先看机器人有没有回那句带 id 的提示);或者机器人没被加进群 |
| 回一句 401,前缀是`<供应商> / <模型>` | 是**模型服务商**拒的,不是 IM 平台 —— 去 AI 设置里查那个接入的密钥/登录状态 |
| 回一句以 `Feishu … failed` 开头 | 才是飞书那边的问题 |
| 有时回有时不回 | 同一套飞书应用凭证在两台机器上同时跑了(平台按集群随机投递) |

模型换了、订阅重新登录了,**不必重启桥接** —— AI 设置每轮现读,下一句就跟上。
渠道凭证与白名单改了才需要在设置页点保存(那会按新配置重起渠道)。
